# tray-tools

画面の一部を付箋のように最前面へ貼り付けておけるキャプチャ機能と、音声出力先の切替を統合した、
Windows用のシステムトレイ常駐アプリです。
1プロセス・1つの `QApplication` で、通知領域に2つのアイコン（音声用／画面用）を表示します。

> **本家「Rapture」との関係について**
>
> 画面の一部を付箋化するという着想は、KENY 氏が公開している Windows 用フリーソフト
> **Rapture**（<https://www.knystudio.net/rapture.html>）から得ています。

> 本家のソースコードや配布物は一切使用しておらず、**本家およびその作者とは何の関係もありません。**
> 本家そのものをお探しの方は上記の公式サイトからどうぞ。
>
> 本リポジトリ内で「Rapture」と書いている箇所は、この付箋キャプチャ機能を指す通称です。

## セットアップ

初めてのPCでは `python setup.py` を実行してください（下の「他のPCで使う」を参照）。セットアップ済みなら、起動は次のとおりです。

```
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe main.py
```

**仮想環境（venv）はこのフォルダの中ではなく `%USERPROFILE%\.venvs\tray-tools` にあります。**
PySide6 だけで5000ファイル以上・約680MBあり、これは `requirements.txt` からいつでも作り直せる
自動生成物です。プロジェクトの中に置くと、クラウド同期の対象フォルダに置いたときに丸ごと同期されて
しまう（同期の詰まりや競合の原因になる）ため、意図的に外へ出しています。リポジトリにも含めません。

グローバルの `python` ではなく必ず上記 venv の `python.exe` を使ってください。

venv を作り直す場合:

```
python -m venv %USERPROFILE%\.venvs\tray-tools
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe -m pip install -r requirements.txt
```

初回起動時、`settings.json` が無ければ既定値で自動生成されます。壊れている場合も既定値にフォールバックして起動します。
既定値の `audio.devices` は空です（デバイスIDはPC固有のため、コードに既定値を持てません）。設定するまで音声アイコンのメニューには「音声デバイスが未設定です」と表示されます。

## 他のPCで使う

別のPC（仕事用PCなど）へ展開する手順です。**管理者権限は不要です。**

```
git clone <リポジトリのURL> tray-tools
cd tray-tools
python setup.py
```

`setup.py` が行うこと（何度実行しても壊れません）:

1. Python 3.10 以上かを確認
2. `%USERPROFILE%\.venvs\tray-tools` に venv を作成（既にあればそのまま使う）
3. `pip install -r requirements.txt`（失敗した場合はプロキシ指定の方法を案内します）
4. 音声出力デバイスを検出して `settings.json` を用意（下記）
5. `TrayTools.lnk` を作成
6. サインイン時の自動起動を登録するかを `y/n` で確認（既定は「しない」。`--startup` / `--no-startup` で確認を省略可）

#### `settings.json` が既にある場合（手順4）

**既存の値は書き換えません。** そのうえで次の2つを行います。

- **不足している設定項目を足す** … 版が上がって増えた項目（`launcher` / `snippets` など）を書き込みます。動作自体は既定値へのフォールバックで問題ありませんが、それだと設定ファイルを開いても「今どんな項目があるのか」が分かりません。実体を書いて見えるようにします。足した項目は画面に一覧表示されます
- **音声デバイスの構成が変わっていたら確認する** … 今の登録と検出結果を並べて表示し、入れ替えるかを `y/n` で聞きます（既定は「しない」。使う機器だけ絞って登録している場合に、検出した全部で上書きされると設定し直しになるため）。`--redetect-audio` / `--keep-audio` で確認を省略できます

書き換える前に `settings.json.bak_YYYYMMDD_HHMMSS` へ控えを取ります。変更が無いときはファイルを書きません。

セットアップ後、アプリ本体は `setup.py` からは起動しません。`TrayTools.lnk` から起動してください。

セットアップ用スクリプトを PowerShell (`.ps1`) ではなく Python で書いてあるのは意図的です。企業のPCでは実行ポリシーがGPOで固定されていて `.ps1` の実行自体が禁止されていることがあり、`-ExecutionPolicy Bypass` でも上書きできない場合があるためです。ショートカット作成にだけ `powershell -Command` のインライン実行を使っています（実行ポリシーが規制するのはスクリプト「ファイル」の実行なので、この経路なら通る可能性が高い）。

### PCごとに持つもの・共有するもの

| もの | 扱い |
|---|---|
| `settings.json` | **PCごとのローカルファイル。リポジトリには含まれません**（`.gitignore` 済み）。デバイスIDや保存先パスがPC固有のため |
| `*.lnk` | 絶対パスを埋め込むためコミットしません。`setup.py` が各PCで作り直します |
| venv | `%USERPROFILE%\.venvs\tray-tools`。各PCで作り直します |

### 音声デバイスIDについて

`audio.devices[].id` は `{0.0.0.00000000}.{GUID}` 形式のPC固有の値で、**別のPCでは必ず異なります**。`setup.py` が自動検出して書き込みます。

デバイスを買い替えるなどして構成が変わったときは、`python setup.py --redetect-audio` を実行すれば検出結果で入れ替えられます（ラベル・アイコン・色も自動で振り直します）。使う機器だけ手で選びたい場合は、次で一覧を確認して `settings.json` を書き換えてください。

```
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe list_devices.py
```

IDが1つも実在しない状態でもアプリは正常に起動します（トレイアイコンは出ます）。その場合はメニューに「音声デバイスが未設定です」と表示され、切り替えを試みると通知で設定を促します。**クラッシュはしません。**

### デバイスIDの自動追従（`match_name`）

**同じ機器でもエンドポイントIDは振り直されることがあります。** USBドングルを挿すポートが変わった、ドライバが更新された、といった日常的なきっかけで起こります（Bluetoothの再ペアリングでも同様）。機器は繋がっていて音も出るのに、`settings.json` のIDだけが実在しなくなり、切り替えが効かなくなります。そのたびに手でIDを直さなくて済むよう、アプリが名前を手がかりに追従します。

- **記録**：IDで解決できている間、そのデバイスの現在の FriendlyName（Windowsが報告する名前）を `audio.devices[].match_name` に自動で保存します。使えているうちに控えておかないと、IDが変わってから名前を調べる術がないためです
- **追従**：設定のIDが実在しないとき、`match_name` と**名前が完全一致する有効（Active）なデバイスがちょうど1台だけ**見つかれば、そのIDを採用して `settings.json` に書き戻し、`〇〇 のIDが変わっていたため追従しました` と通知します
- **追従しない条件**：`match_name` が未記録のとき／一致が**0台**のとき／一致が**2台以上**のとき。部分一致・前方一致は使わず、無効（Active でない）なデバイスも対象外です

一致が複数あるときにあえて何もしないのは安全のためです。`Digital Output` や `3 - EX-LDGCQ321HD` のように**同名のデバイスが複数存在する**のは珍しくなく、曖昧なまま推測すると意図しない出力先に切り替わり、「音が別のスピーカーから出る」という原因の分かりにくい事故になります。この場合は `list_devices.py` でIDを確認して手で直してください。

`match_name` は `label` とは別物です。`label` はメニュー表示用にユーザーが自由に付ける名前で（例：`ヘッドホン (Loop120)`）、Windowsが報告する名前（例：`ヘッドホン (Loop120 by Shokz)`）とは一致しないため、照合には使いません。

なお、IDでの解決に成功している通常時は全デバイスの列挙を行いません（メニューを開くたびのコストを増やさないため）。名前での探索は、IDが実在しなかったときだけ走ります。

### 会社のPCで使う場合の注意（ホットキーとEDR）

**このアプリは `keyboard` ライブラリでグローバルキーフックを使っています。** OS全体のキー入力を監視する仕組みのため、企業のエンドポイント保護（EDR/アンチウイルス）にキーロガーとして検知・ブロックされる可能性があります。これは事実として認識したうえで導入を判断してください。組織のポリシーによっては、導入前に情報システム部門へ確認するのが安全です。

ホットキーが不要なら、`settings.json` の `hotkeys` の各値を**空文字 `""` にすればキーフックの登録自体を行いません**。トレイアイコンのクリックとメニューだけで全機能を使えます。

```json
"hotkeys": {
  "audio_toggle": "",
  "capture_now": "",
  "capture_sequence": "",
  "mic_mute": "",
  "color_picker": "",
  "always_on_top": "",
  "snippet_picker": "",
  "launcher": ""
}
```

### 更新の反映

```
git pull
```

これだけで反映されます（`settings.json` はリポジトリに含まれないので、`git pull` で自分の設定が上書きされることはありません）。`requirements.txt` に依存が増えたときだけ、次を実行してください。

```
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe -m pip install -r requirements.txt
```

### 起動用ショートカット

- `TrayTools.lnk` … コンソールを出さずに起動する（`pythonw.exe` 経由）。`setup.py` でスタートアップ登録を選んだ場合は、同じものが Windows のスタートアップフォルダにも置かれ、サインイン時に自動起動します
- `TrayTools-debug.bat` … コンソール付きで起動する。うまく起動しないときに、エラー内容を確認するために使う

自動起動をやめたい場合は、スタートアップフォルダ（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`）の `TrayTools.lnk` を削除してください。

## トレイアイコンの操作

通知領域に2つのアイコンが表示されます。

**アイコンを増やさないのは意図的な設計です。** 「状態を持つ機能だけがアイコンの見た目を占有してよい。単発の動作はメニュー項目で足りる」という方針で、機能を増やしてもアイコンは2つに保っています。

### 音声アイコン

見た目が示す状態：**現在の出力先**（図柄と色）＋**マイクがミュート中かどうか**（赤い斜線）。

- **左クリック**：次の出力デバイスへトグル切替
- **右クリック**：現在のデバイス表示／切り替え／各デバイスへ直接切替／マイクをミュート／設定／終了

| 機能 | ホットキー（既定） |
|---|---|
| 出力デバイスの切替 | `Ctrl+Alt+H` |
| マイクのミュート切替 | `Ctrl+Alt+M` |

出力デバイスもマイクのミュートも他アプリ（Teams等）から変更されうるため、メニューを開くたびに実際の状態を読み直します。

### 画面アイコン（`icons/rapture.png`）

見た目が示す状態：**スリープ抑止が有効かどうか**（有効中はアイコン全周にオレンジのリング）。

- **中クリック**：即キャプチャ（範囲選択オーバーレイが出ます）
- **右クリック**：下記メニュー

| メニュー項目 | 内容 | ホットキー（既定） |
|---|---|---|
| 📷 キャプチャ（今すぐ）/ ⏱ 5秒後 / ⏱ 10秒後 | **画面を凍結して**、その静止画の上で範囲を選び付箋化する。遅延ありの場合は**待ってから凍結する** | `Ctrl+Alt+R`（今すぐ） |
| （メニューなし・ホットキーのみ） | **連番キャプチャ**：いま出ている付箋（最後に作ったもの）を1枚撮り足す。**付箋がアクティブでなくても効く**（後述） | `Ctrl+Alt+S` |
| 💧 カラーピッカー | 画面の色を吸って `#RRGGBB` をクリップボードへ。ルーペで拡大しながら選べる | `Ctrl+Alt+C` |
| 📏 画面定規 | ドラッグした範囲の幅・高さ・始点・終点・対角線を測ってコピー | — |
| 📋 定型文 | `snippets` フォルダのテンプレートを選んでクリップボードへ。プレビューと変数の展開あり | `Ctrl+Alt+V` |
| 📂 定型文フォルダを開く | `snippets` フォルダをエクスプローラで開く | — |
| 📁 フォルダブックマーク | 登録したフォルダを選んでそこへ移動する。**前面がエクスプローラならその窓を、でなければあふｗを**移動させる（`launcher.target` で固定も可能） | `Ctrl+Alt+B` |
| 📽 発表者ツール | 同梱の `presenter.html` を既定のブラウザで開く。資料は開いた先へドラッグ＆ドロップ。詳細は[発表者ツール](#発表者ツールpresenterhtml) | — |
| 🌐 サイトを取り込んで開く | **任意のウェブサイト**を取り込んで、上の発表者ツールの資料として開く。詳細は[任意のサイトを取り込んで開く](#任意のサイトを取り込んで開くweb_presenterpy) | — |
| 🔦 プレゼン支援（画面に重ねる）▸ | レーザーポインタ／スポットライト／黒画面／白画面。詳細は[プレゼン支援](#プレゼン支援presenter_overlaypy) | `Ctrl+Alt+L` ほか |
| 🖥 画面ミラー（別モニタへ）▸ | **手元の画面の一部を、別のモニタへ全画面で映す**。範囲を選んだあともその中は普通に操作できる。**開始と範囲の選び直し**が `Ctrl+Alt+P`、**静止**が `Ctrl+Alt+F`、**終了**が `Ctrl+Alt+Q`。詳細は[画面ミラー](#画面ミラーscreen_mirrorpy) | `Ctrl+Alt+P` ほか |
| 📌 このウィンドウを最前面に固定 | いま手前にあるウィンドウの最前面固定をトグルする | `Ctrl+Alt+T` |
| ☕ スリープ抑止 ▸ | 30分／2時間／無期限／解除。時限指定なら自動で解除される | — |
| 🖱 マウスジグラー ▸ | 30分／2時間／無期限／解除。**無操作のときだけ**カーソルを 1px 動かして戻し、リモートデスクトップのアイドル切断を防ぐ。詳細は[マウスジグラー](#マウスジグラーmouse_jigglerpy) | — |
| 🖥 タスクバーウィジェット | **セカンダリのタスクバーに置く「トレイの代わり」**の表示/非表示（既定は無効）。詳細は[セカンダリのタスクバーウィジェット](#セカンダリのタスクバーウィジェットtaskbar_widgetpy) | — |
| 🎨 背景色を取り直す | 上のウィジェットの背景色を、いま画面にある色で測り直す（表示中のみ選べる） | — |

**メニュー項目の先頭には絵文字を1つ置いています。** 通知領域のメニューは項目が縦に並ぶだけで手掛かりが少なく、目的の行を探すのに毎回文字を読むことになるためです（画面アイコン側だけの扱いで、音声アイコン側のメニューには付けていません）。

範囲選択オーバーレイはドラッグで範囲を指定し、離すと付箋ウインドウが開きます。`Esc` でキャンセルできます。
付箋ウインドウは同時に何枚でも開けます。

**キャプチャを始めた時点で画面は凍結します。** オーバーレイが出ている間に見えているのは、全モニタを1枚に撮った静止画です。範囲を離した瞬間に撮り直すのではなく、その静止画から切り出すので、**選択中に見えていた絵と保存される絵は必ず一致します**（動画やアニメーションが動いていてもズレません）。凍結するのは「今すぐ」でも同じです。

**ドラッグを始める前でも、カーソル位置の座標が常に表示されます**（キャプチャ・画面定規のどちらでも）。始点を決める前に「今どこを指しているか」が分かります。表示される座標は全モニタを合算した仮想デスクトップ基準の**実際の画面座標**です。

**「5秒後 / 10秒後にキャプチャ」は、まずカウントダウンだけが出ます。** カウントダウン中は画面がふだんどおり動くので、その間に撮りたいメニューやツールチップを開いておいてください。時間が来ると画面が凍結し、止まった絵を見ながらゆっくり範囲を選べます。**範囲選択の操作でメニューが閉じてしまっても、凍結済みなので撮れます。** カウントダウン表示自体は凍結画像に写り込みません（撮る直前に閉じ、OSの再描画を待ってから撮ります）。

**通知はWindowsのトーストではなく自前で描いています。** Windows 11 のトースト通知は通知システムを経由するため数秒遅れて出ることがあり、操作し終わった後になって鳴るだけで邪魔になるためです。カーソルのある画面の右下に即座に小さなパネルが出て、約1.6秒でフェードアウトして消えます。クリックは透過し、フォーカスも奪わないので操作の邪魔になりません（連続して出しても積み上がらず、常に最新の1枚だけが残ります）。

**マイクのミュート切替とデバイス切替では、成功時に通知を出しません。** 状態はトレイアイコン（ミュート中は赤い斜線、出力先は図柄と色）が即座に反映するので、そちらが合図として十分で、いちいち通知が出る方が冗長なためです。

**スリープ抑止は時限指定を既定の導線にしています。** 抑止したまま忘れて何日もスリープしなくなるのが一番ありがちな失敗のためです。アプリ終了時には抑止も最前面固定も自動で解除されます。

**画面定規は、ドラッグ中に小さなパネルで「幅 x 高さ／始点／終点／対角線」を表示します。**
離すと、そのままノートや報告に貼れるラベル付きの複数行テキストをクリップボードへコピーします。

```
幅 x 高さ: 1920 x 1080
始点: (100, 200)
終点: (2020, 1280)
対角線: 2202.9 px
```

始点・終点は**実際にドラッグを開始した点と離した点**で、矩形の左上・右下ではありません（右から左へ引けば始点が右になります）。座標は全モニタを合算した仮想デスクトップ基準のグローバル座標のため、プライマリの左にモニタがある構成では負の値になります。通知には `1920 x 1080 / 対角線 2202.9 px をコピーしました` と要約のみ出ます。

**カラーピッカーは、オーバーレイを開いた瞬間の画面を静止画として扱います**（カーソル追従のルーペを出すため、開いた時点で1回だけ画面全体を取得しているため）。動画など変化し続けるものの色を拾いたい場合は、拾いたい瞬間に開いてください。

**アプリ全体の終了は、どちらかのトレイアイコンの右クリックメニュー「終了」から行います。** 付箋ウインドウを全部閉じてもアプリは常駐し続けます。**逆に、アプリを終了・再起動しても開いている付箋は閉じません**（付箋は別プロセスで動いています。後述の「付箋は本体とは別のプロセス」を参照）。

**多重起動はしません。** すでに常駐している状態でショートカットを起動しても、2つ目のプロセスは静かに終了し、常駐中の側が「すでに起動しています」と通知します（スタートアップからの自動起動と手動起動が重なっても、トレイアイコンが2組並んだりホットキーが二重登録されたりしません）。

## マウスジグラー（`mouse_jiggler.py`）

### なぜスリープ抑止とは別に必要なのか

**スリープ抑止（☕）ではリモートデスクトップの切断を防げません。** あちらは `SetThreadExecutionState` で OS に「スリープするな・画面を消すな」と申告するだけの機能で、電源まわりにしか効きません。

一方、**リモートデスクトップのアイドル切断やロック画面は「入力があったかどうか」を見ています。** 電源の状態とは無関係なので、スリープ抑止をいくら効かせていても、キーもマウスも触らないまま放っておけば時間が来て切れます（会社の環境ではポリシーで 10〜15 分に設定されていることが多く、こちらは設定で伸ばせません）。

そこで、**入力そのものを起こす**のがこの機能です。カーソルを相対で **+1px 動かし、すぐ -1px 戻す**入力を 1 組送ります。差し引きゼロなのでカーソルは実質その場に留まりますが、OS から見れば確かに入力があったことになり、アイドルのカウントが 0 に戻ります。

### 無操作のときだけ動きます

**あなたが操作している最中は何もしません。** `GetLastInputInfo` で最後の入力からの経過を測り、**30秒以上**（`screen.jiggler_idle_seconds`）無操作のときだけ入力を送ります。操作中に割り込んでカーソルが跳ねると、ドラッグ中や細かい位置合わせ中に邪魔になるだけだからです。

送る間隔は **60秒**（`screen.jiggler_interval_seconds`）です。アイドルタイムアウトが通常 10〜15 分であることに対して十分な余裕があり、かつ普段の操作をまったく妨げない頻度として選んでいます。

### 使い方

画面アイコンの右クリックメニュー **「🖱 マウスジグラー」** から、`30分` / `2時間` / `無期限` / `解除` を選びます。**スリープ抑止とまったく同じ操作感で、すぐ下に並べてあります**（狙いが近いので、探すときに同じ場所を見れば済むようにしています）。

- 時限を選ぶと、**時間が来たときに自動で解除されます**（つけっぱなしを防ぐため、時限指定を既定の導線にしているのもスリープ抑止と同じです）
- 有効中はサブメニューの見出しが `🖱 マウスジグラー（残り25分）` のように**残り時間**を表示します
- アプリを終了すると自動的に止まります

**トレイアイコンの見た目は変わりません。** アイコン全周のリングはスリープ抑止が使っており、実質16px相当のアイコンに2つ目の目印を入れても潰れて読めないためです。動作中かどうかは**アイコンのツールチップ**（`Rapture（マウスジグラー動作中）`）とメニューの見出しで確認してください。

### 送れなかった場合

入力の送信（`SendInput`）は、**管理者権限で動いているウィンドウが前面にある間は Windows に弾かれます**（UIPI）。この場合はそのまま回しても毎回失敗するだけなので、**自動的に停止して 1 度だけ通知します**（`入力を送れないため停止しました`）。前面のウィンドウを切り替えてから、もう一度メニューで有効にしてください。

なお、座標を直接書き換える `SetCursorPos` は「入力」として記録されない場合があり、目的を達しません。旧 API の `mouse_event` も非推奨のため、`SendInput` を使っています。

## セカンダリのタスクバーウィジェット（`taskbar_widget.py`）

**Windows は通知領域（トレイ）をプライマリのタスクバーにしか出しません。** ノートPCの画面をプライマリ、正面の拡張ディスプレイをセカンダリにしている構成（拡張側をプライマリにすると別の不都合がある、という事情はよくあります）では、tray-tools を使うたびに視線と手が「正面ではない方の画面」へ行くことになります。セカンダリのタスクバーには `TrayNotifyWnd`（通知領域）そのものが存在しないため、設定で移せるものでもありません。

そこで、**セカンダリのタスクバーにトレイの代わりを自分で置く**のがこの機能です。

**普段はセカンダリの時計に重なって、時計のふりをしています。** マウスを乗せている間だけ、時計が消えて **Rapture と音声の2つのアイコンに入れ替わります**（隣に生えるのではありません）。タスクバーの上に自前のものが常時2つ増えて見えるのが邪魔なためで、狙いはあくまで「トレイの代わりを正面の画面に置くこと」です。

**既定では無効です。** セカンダリのタスクバーが無いPCで勝手に出さないためで、画面アイコンの右クリックメニュー「🖥 タスクバーウィジェット」で表示/非表示を切り替えます（切り替えると `settings.json` にも保存され、次回起動時もその状態で立ち上がります）。

### 操作

| 場所 | 操作 | 動作 |
|---|---|---|
| 左半分（Rapture アイコン） | 中クリック | 即キャプチャ（通知領域の画面アイコンと同じ） |
| 左半分（Rapture アイコン） | 右クリック | 画面アイコンのメニューをその場に出す |
| 右半分（音声アイコン） | 左クリック | 出力デバイスを切り替え |
| 右半分（音声アイコン） | 右クリック | 音声アイコンのメニューをその場に出す |
| 時計部分（アイコン非表示時） | 右クリック | 画面アイコンのメニュー |
| 全体 | **Ctrl+左ドラッグ** | 位置を微調整する（離した時点で `settings.json` に保存） |

**当たり判定は左右half分けです。** 59x31 の中に20px級の絵が2つ並ぶだけなので、絵の矩形そのものを判定にすると周りが死に領域になり「押したのに何も起きない」が頻発するためです。

**メニューは通知領域と同じものをそのまま出しています**（別に組み立てていません）。別々に作ると、項目やホットキー表記が片方だけ古くなるためです。

**移動が Ctrl+左ドラッグなのは、素の左ドラッグを音声の切替（クリック）判定に使っているからです**（付箋のペンが Ctrl+左ドラッグなのと同じ理由）。

### どこに出るか

**ディスプレイ1枚につき1つ出します。** 数えるのは「タスクバーの数」ではなく**画面の数**です。Windows の「タスクバーをすべてのディスプレイに表示する」がオフの環境ではセカンダリに `Shell_SecondaryTrayWnd` が存在せず、タスクバーを数えると2番目以降が1つも出ないためです（実際にそう報告されました）。

`all_displays` を `false` にするとプライマリの画面だけ外します（そちらには本物の通知領域があるため）。

### 位置とサイズ

**位置はディスプレイごとに独立して持ちます。** `settings.json` の `taskbar_widget.positions` が「画面のキー → `{"right": …, "top": …}`」の辞書です。値は絶対座標ではなく、**その画面のタスクバーの右端・上端からの距離**です（解像度や拡大率が変わっても右下との位置関係が保たれるため）。

**画面のキーはモニタ自身が持つ情報（EDID）から作ります。** `QScreen.name()` は Windows ではモニタの型番を返すので、これにシリアルを繋げて `EX-LDGCQ321HD#951` のようにします。接続順で決まる名前を使わないのは、モニタを繋ぎ替えても切替器で他のPCへ渡して戻しても**同じ名札が付く**ようにするためです。同じ型番でシリアルも読めない2台が並んだときだけ、画面の左上座標を混ぜて分けます（常に座標を混ぜると、モニタを並べ替えるたびに位置を忘れてしまうため）。

**設定にその画面のキーが無ければ、既定の余白（右端から 19px・上端から 10px）で自動配置します。** この値は、画面のピクセルから Windows 11 の時計の描画範囲を割り出したうえで、実機2枚で目視調整した結果に寄せたものです（濃淡から測る方法は、文字のアンチエイリアスの分だけ内側に見積もります）。**別のPCへ `settings.json` を持って行っても壊れません**（知らないモニタは既定位置に落ちるだけです）。

**Ctrl+左ドラッグで動くのは、動かしたウィジェット1つだけです。** 保存されるのもその画面の分だけで、他の画面のウィジェットは1pxも動きません。以前は余白1組を全画面で共有していたため、1つ動かすと全部そろって動き、さらにドラッグ中に別の画面のタスクバーへ入った瞬間に基準が乗り換わって**別の画面へワープ**していました。**基準にする矩形は、そのウィジェットが生成されたときのもので固定です**（途中で乗り換えません）。

**置ける場所に制限はありません。** タスクバーの外でも画面の中央でも、置いたまま保存されます。作業領域（`availableGeometry`）へクランプしないのは、この窓の居場所であるタスクバーの上がそもそも作業領域から除外されているためで、クランプすると必ずタスクバーの外へ弾き出されてしまいます。タスクバーの中へ引き戻す補正も入れていません（入れると「ある高さより下には置けない」ことになります。実際そうなっていました）。

唯一の歯止めは、**保存済みの位置が仮想デスクトップとまったく重ならなくなったとき**（モニタを外した等）だけで、そのときは既定位置に出し直します。二度と掴めない場所に出ると `settings.json` を手で直すしかなくなるためで、**1pxでも重なっていれば手を出しません**。

**タスクバーが見つからない画面では、その画面の下端に「タスクバーがあるとすればここ」という帯を仮定し、そこを基準にします。** 縦位置の基準になるものが他に無く、かつタスクバーは必ず画面の下端に接しているので、下端から逆算すれば既定の余白（上端から 6px 下）がそのまま通用します。帯の高さは**実在するタスクバー（たいていはプライマリ）のものを借ります**（Windows は全ディスプレイで同じ高さのタスクバーを出すため）。1つも見つからないときだけ、Windows 11 の既定値である 48px を使います。

### 背景色

**タスクバーの背景色は決め打ちにできません。** 透明効果が有効だと壁紙が透けるため、環境と壁紙で色が変わるからです（実測環境では `#DDF2B9` という緑がかった色でした）。そのため、**表示する直前に自分が乗る位置の画面を撮り、いちばん多い色（最頻色）で塗ります**。平均ではなく最頻色にしているのは、時計の文字が混ざった平均だと地の色からずれるためです。

文字色は背景の明るさ（BT.601 の輝度）から自動で決めます。上の実測値のような明るい背景では黒、暗い背景では白になります。

**壁紙を変えたら、メニューの「🎨 背景色を取り直す」で測り直してください**（ウィジェットが表示されているときだけ選べます）。測るときは自分をいったん隠し、OSが下を描き直すのを待ってから撮ります（隠した直後に撮ると自分の色をもう一度測ってしまうためです）。

**測り直した色は `settings.json` に書き戻しません。** `background_color` を `null` のままにしておけば起動のたびに実測されるので、壁紙を変えても放っておけば次回から合います。書き込んでしまうと以後その色に固定され、壁紙を変えるたびに手で取り直す羽目になるためです。

色を固定したい場合は `settings.json` の `background_color` / `text_color` に `#rrggbb` を書いてください。書いてあれば自動判定より優先されます。

### 最前面の維持

**タスクバーは常に最前面なので、その上に居続けるには押し上げ続けるしかありません。** 500ms ごとに `SetWindowPos(HWND_TOPMOST, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)` を呼んでいます。

**`SWP_NOACTIVATE` は必須です。** 付け忘れると 0.5 秒ごとにフォーカスを奪い、入力中の文字が飛びます。ウィンドウ自体にも `Qt.WindowDoesNotAcceptFocus` を付けてあるので、クリックしても作業中のウィンドウからフォーカスは移りません。

**非表示のときはタイマーを止めます**（時計の更新も、最前面への押し上げも）。他のウィンドウのZオーダーを触る操作を、見えていない間まで続ける理由が無いためです。

**全画面のアプリが前面に来たら、Zオーダーの後ろへ回ります**（`HWND_BOTTOM`。`hide()` はしません — 隠すと `hideEvent` でこのタイマーごと止まり、全画面が終わったことに気づけなくなります）。判定は `GetForegroundWindow` の矩形が自分の画面を丸ごと覆っているか。**自分の画面だけを見ます**（2枚目で動画を全画面にしているときに、1枚目のウィジェットまで引っ込む必要はありません）。

**[画面ミラー](#画面ミラーscreen_mirrorpy)のミラー窓だけは、この判定では捕まえられません。** あれは発表の邪魔をしないよう `WS_EX_NOACTIVATE`（`Qt.WindowDoesNotAcceptFocus`）＋ `WA_ShowWithoutActivating` で作ってあり、**決して前面にならない**窓だからです。前面のままなのは発表者が操作している手元のアプリで、その矩形はミラー先のモニタを覆いません。そのためウィジェットは 500ms ごとに押し上げ続け、同じく 500ms ごとに最前面を主張するミラー窓と**奪い合って、共有側のモニタでチカチカしていました**。今はミラー側から「この画面を覆っている」と名指しで教えてもらい（`MirrorController.attach_screen_cover` → `TaskbarWidget.set_app_covered`）、**ミラー先の1枚だけ**が引っ込みます。ミラーを終えれば元に戻ります。

### 時計の表示

Windows 11 のタスクバー時計に合わせて2行（上に時刻、下に日付）です。書式は `settings.json` の `clock_format_top` / `clock_format_bottom` で変えられます（`strftime` の書式）。

**先頭ゼロを落とすのは Windows では `%#H` です**（`%-H` は Linux 系のもので、Windows では例外になります）。書式を書き損じても時計が消えないよう、失敗したら既定の書式に落として標準エラーに1回だけ警告を出します。

`%a`（曜日）などを日本語で出せるよう、初回描画時に `locale.setlocale(locale.LC_TIME, "")` を試みます（失敗しても英語表記になるだけで、表示は続きます）。

**分単位の表示でも毎秒描き直しています。** 秒がずれた時計は見た目ですぐ分かって気持ち悪く、59x31 の再描画1回の負荷は無視できるためです。

### この機能が Feature ではない理由

`taskbar_widget.TaskbarWidget` はトレイアイコンを持たないので Feature ではありません（[機能の追加方法](#機能の追加方法)の方針どおり、アイコンは2つのままです）。生成と参照の保持は `ScreenFeature` が行い、音声側の参照（アイコンの絵・デバイス切替・メニュー）は Feature が全部そろってから `main._wire_taskbar_widget()` が渡します。

音声アイコンの絵は `AudioFeature.current_icon_pixmap()` から受け取り、こちらでは描き直しません。「トレイの代わり」である以上、色も形も本物と食い違ってはいけないためです。デバイスは他アプリ（Teams等）からも変えられるので、**マウスを乗せた瞬間だけ**状態を読み直します（描画のたびに読み直すと COM 越しの問い合わせがホバー中ずっと走ります）。

## 定型文

`snippets` フォルダに置いた `*.txt` / `*.md` を、絞り込んで選んでクリップボードへコピーします。`Ctrl+Alt+V`（既定）またはメニューから開きます。

**専用の編集UIはありません。ファイル名（拡張子を除く）がそのまま表示名です。** テキストエディタで足す・消す・リネームするだけで増減できます（フォルダは初回起動時に自動で作られます）。BOM付きUTF-8でも読めます。読めないファイルがあっても、そのファイルだけを飛ばして残りは表示します（理由は標準エラーに出ます）。

ウインドウの操作は次のとおりです。

| キー | 動作 |
|---|---|
| 文字入力 | **前方一致（大文字小文字を無視）**で絞り込む |
| `↑` `↓` | 選択を動かす |
| `Enter` | 変数を展開してクリップボードへコピー |
| `Ctrl+N` | 新規作成。名前を尋ねて `snippets\<名前>.txt` を**空で作り**、関連付けアプリで開く |
| `Ctrl+E` | 選択中のテンプレートを関連付けアプリで開く |
| `Ctrl+O` | `snippets` フォルダをエクスプローラで開く |
| `Esc` | 閉じる |

**絞り込みは候補そのものを減らします**（見えているものが選べるものと一致していないと、`Enter` の行き先が分からなくなるため）。

**`Ctrl+N` / `Ctrl+E` / `Ctrl+O` はファイルを開いた後、ピッカーを閉じます。** 外部エディタで直した内容を反映するには開き直すしかなく、開いたままにすると古い一覧が画面に残って中身と食い違うためです。`Ctrl+N` で同じ名前がすでにある場合は、**作り直さずにそのファイルを開くだけ**にします（打ち間違いひとつで書き溜めたテンプレートを消さないため）。テンプレートが1件も無いときはピッカー自体が開かないので、その場合はトレイメニューの「📂 定型文フォルダを開く」から辿ってください。

### プレビュー

一覧の下に、**選択中のテンプレートが実際にコピーされる姿**が出ます。`{clipboard}` や `{date}` は**展開した後の値**で表示されるので、「何がコピーされるか」を押す前に確かめられます。

**`{input}` だけは尋ねずに `【ラベル】` の形で表示します。** プレビューは選択が動くたびに作り直されるので、ここで入力ダイアログを出すと一覧を眺めることすらできなくなるためです（`snippets.expand_variables(本文, preview=True)` がこのモードです。実際にコピーするときの挙動は今までどおりで、`{input}` はちゃんと尋ねます）。

ウインドウの下端には変数の早見表とキー操作を小さく常時表示しています。

### 並び順（最近使った順）

**コピーしたテンプレートが次から一覧の先頭に来ます。** 履歴は `settings.json` の `snippets.recent` に表示名のリストとして貯まり（新しいものが先頭・上限20件）、履歴に無いものはファイル名順で後ろに続きます。

保存はメモリ上の設定を丸ごと書き出すのではなく、`settings.json` を読み直して `snippets.recent` だけを差し替えます（丸ごと書くと未設定の既定値まで焼き込まれてファイルの姿が変わるためで、`launcher.bookmarks` の登録と同じ作法です）。

### 変数

本文には次の変数を書けます。

| 記法 | 展開されるもの |
|---|---|
| `{clipboard}` | 現在のクリップボードの文字列 |
| `{date}` | 今日の日付（`2026/08/22`） |
| `{date:書式}` | 書式指定の日付（`{date:%m月%d日(%a)}` → `08月22日(土)`）。`strftime` の書式 |
| `{time}` | 現在時刻（`14:30`） |
| `{datetime}` | 日時（`2026/08/22 14:30`） |
| `{input}` | その場で入力を求める（複数行可） |
| `{input:ラベル}` | ラベル付きで入力を求める。**ラベルはダイアログのタイトルにも出ます**（続けて複数聞かれたときに、いま何を聞かれているのか分かるように） |

**同じ `{input:ラベル}` が複数回出てきても、尋ねるのは1回だけです**（同じ内容を2回打たされないため）。入力をキャンセルすると、そのテンプレートは**コピーせずに**閉じます（中途半端に展開された文字列をクリップボードへ載せないため）。

**上の表に無い `{なにか}` はそのまま残ります。** テンプレートにコード片や JSON が混じっていても壊れません（`str.format()` を使わず、既知の変数名だけを正規表現で拾っているためです）。

## プレゼン支援（`presenter_overlay.py`）

画面の上に重ねて使う道具です。**対象を選びません** — ウェブサイトでも PowerPoint でも PDF でも、何を映していても効きます。

| 機能 | 既定のキー | 動き |
|---|---|---|
| 🔴 レーザーポインタ | `Ctrl+Alt+L` | マウス位置に赤い光点。**下のアプリは普通に操作できます** |
| 💡 スポットライト | `Ctrl+Alt+O` | マウス周辺だけ残して暗くする。半径と暗さは設定で変えられます（[画面ミラー](#画面ミラーscreen_mirrorpy)中なら**ツールバーのホイールで発表中に変えられます**） |
| ⬛ 黒画面 | `Ctrl+Alt+B` | 画面を黒く覆う。話に集中させたいときに（[画面ミラー](#画面ミラーscreen_mirrorpy)中は**ミラー先だけ**を覆います） |
| ⬜ 白画面 | `Ctrl+Alt+W` | 同じく白で |

**レーザーとスポットライトはクリックが素通しします。** `WA_TransparentForMouseEvents` だけでは Qt 内部の配送が止まるだけで下のアプリには届かないので、`WindowTransparentForInput`（`WS_EX_TRANSPARENT`）も付けています。そのぶん自分ではマウス位置を受け取れないため、カーソルは 16ms 間隔のポーリングで追います。

**黒画面と白画面は逆にクリックを受け、押すと解除されます。** 覆ってしまえば下は操作できず、クリックを吸っても失うものがない一方、「透過すると閉じる手段が無くなる」ほうが困るためです。ただしフォーカスは奪わないので、解除後もそのまま矢印キーでスライドを送れます。

出るのは**カーソルのある画面**だけです。マルチディスプレイで全画面を覆うと、手元の資料や発表者ツールまで見えなくなります（`presenter_overlay.target_screen` を `"all"` にすれば全画面も選べます）。

### `presenter.html` との使い分け

| | 対象 | できること |
|---|---|---|
| **presenter.html** | ローカルの HTML 資料 | スライド検出・送り・次スライド・カンペ・タイマー・レーザー |
| **プレゼン支援**（こちら） | **何でも** | レーザー・スポット・黒画面 |
| **画面ミラー** | **何でも** | 手元の一部を別モニタへ全画面で。レーザー・スポット・カーソル・クリック波紋 |

あちらは資料を `about:blank` に書き出して親と同一オリジンにすることで、DOM を直接操作しています。だからスライドを検出できる代わりに、対象がローカルの HTML に限られます。こちらは画面に重ねるだけなので、何に対しても使える代わりに中身は知りません。

## 画面ミラー（`screen_mirror.py`）

**手元の画面の一部を切り取り、別のモニタへ全画面で映します。** 画面共有（Teams 等）に出しているモニタへ向けて使うための道具です。

```
モニタ1（手元）              モニタ2（画面共有に出している）
┌────────────────┐        ┌──────────────┐
│  ┌──────────┐  │        │              │
│  │ 選択範囲   │──┼───────▶│  全画面ミラー  │
│  │(操作できる) │  │        │ ＋カーソル    │
│  └──────────┘  │        │ ＋レーザー等   │
└────────────────┘        └──────────────┘
```

**範囲を選んだあとも、その中は普通に操作できます。** ミラーは見ているだけなので、ブラウザでリンクを辿ろうが PowerPoint を送ろうが、そのまま向こうに映ります。対象がブラウザでも PowerPoint でも PDF でも関係ありません。

トレイメニューの **🖥 画面ミラー（別モニタへ）▸ ▶ 範囲を選んで開始**、または `Ctrl+Alt+P` から。

### 操作の一覧

| したいこと | 方法 |
|---|---|
| **始める** | `Ctrl+Alt+P` ／ トレイメニュー **▶ 範囲を選んで開始** |
| **映す範囲を変える** | `Ctrl+Alt+P`（**映したまま**範囲選択がやり直せます）／ 手元のツールバーの 🔲 ／ トレイメニュー **🔁 範囲を選び直す（映したまま）** |
| **静止させる** | `Ctrl+Alt+F` ／ 手元のツールバーの ⏸ ／ トレイメニュー **⏸ 静止（一時停止）** |
| **終わる** | `Ctrl+Alt+Q` ／ 手元のツールバーの ✕ ／ トレイメニュー **⏹ 終了** |
| **選び直しをやめる**（ミラーは続く） | 範囲選択中に `Esc` |

**`Ctrl+Alt+P` はミラーを止めません。** 以前は押すたびに開始／終了のトグルでしたが、発表の途中で映す場所を変えたくなったときに、いったんミラーを畳むことになっていました。画面共有に出しているモニタが一瞬黒くなるので、見ている側からは事故に見えます。**今は映したまま範囲だけを選び直します。** 終わらせる手段は上のとおり3つ用意してあります。

> 選び直している間、ミラーは**自動で静止します**。範囲選択の減光オーバーレイは全モニタを覆うので、撮り続けたままだと向こうには「減光した自分の画面」が映ってしまうためです。選び終える（または `Esc` でやめる）と元に戻ります。

ランチャ（タスクバーウィジェット）にも `screen_mirror` として登録してあります。ただし**既定の並びには入れていません**（パネルは縦に伸びる一方なので）。使うなら `settings.json` の `launcher_items` に足してください。

### 範囲の選び方

範囲選択はキャプチャと同じオーバーレイです（ドラッグ、`Esc` でキャンセル、クリックでその位置のウィンドウ全体）。違いは**縦横比が固定される**ことと、**プリセットが選べる**ことです。

| キー | 比率 |
|---|---|
| `1` | 自由 |
| `2` | 4:3 |
| `3` | 16:9（既定） |
| `Space` / `Tab` / ホイール | 順送り |

**大きさは自由です。** 固定されるのは比率だけなので、800×450 でも 1600×900 でも 1920×1080 でも選べます。**ドラッグの途中でも比率を切り替えられます**（今引いている枠がその場で合わせ直されます）。

#### プリセット — 決まった矩形を一発で

範囲選択中、画面の左上に**プリセットの一覧**が出ます。**クリック**するか **`Ctrl`+数字**で、その矩形がそのまま確定します（比率には合わせません。大きさまで決めたものなので）。

| 既定のプリセット | 大きさ | 始点 |
|---|---|---|
| **等倍（ミラー先と同じ）** | ミラー先のモニタと同じ解像度 | そのモニタの中央 |
| **上を100空ける** | 1600×900 | (0, 100) |
| **HD** | 1280×720 | 中央 |
| **FHD** | 1920×1080 | 中央 |

**`x` / `y` は「今カーソルがあるモニタの左上」からの相対です。** (0, 100) と書けば、作業しているモニタの上端から 100px 下——タスクバーやブラウザのタブ・アドレスバーを外した位置になります。絶対座標にすると、プライマリでないモニタで作業している人の手元では別のモニタを指してしまうためです。特定のモニタに固定したいときは `screen` に `QScreen.name()` を書いてください。

**中身は `settings.json` の `screen_mirror.presets` で増やせます。**

```json
"screen_mirror": {
  "presets": [
    {"label": "等倍（ミラー先と同じ）", "size": "target"},
    {"label": "上を100空ける", "x": 0, "y": 100, "width": 1600, "height": 900},
    {"label": "左半分", "x": 0, "y": 0, "width": 1280, "height": 1440}
  ]
}
```

| キー | 意味 |
|---|---|
| `label` | 一覧に出す見出し |
| `width` / `height` | 大きさ（論理px） |
| `size: "target"` | 大きさを**ミラー先のモニタと同じ**にする（＝等倍。**滲みません**） |
| `x` / `y` | 始点。省略するとその画面の中央 |
| `screen` | 基準にするモニタ名（`QScreen.name()`）。省略すると今カーソルのあるモニタ |

指定した大きさが画面に収まらないときも**縮めません**（等倍のために指定した大きさを勝手に変えては意味が無いため）。始点だけ画面の中へ寄せます。書き損じた行はその行だけ落ちます。

### 負荷 — 範囲が大きいほど重くなります

映すたびに手元の範囲を撮り直すので、**選ぶ範囲が大きいほど1枚あたりの時間が延びます**。このPCでの実測（既定 30fps・ミラー先 2560×1440）：

| 範囲 | 1枚の取得 | 30fps で回したとき |
|---|---|---|
| 1280×720 | 16.9 ms | **約 30 fps / CPU 60〜75%**（1コア換算） |
| 1920×1080 | 33.5 ms | 約 26〜30 fps / CPU 65〜110%（**コマ落ちします**） |

**1280×720 前後がこのPCの快適な上限です。** それより大きく映したいときは `screen_mirror.fps` を落としてください（1920×1080 なら 20fps で CPU が 5 割ほどに、15fps で 4 割ほどに下がります）。**画面の拡大率を上げている環境（`QT_SCALE_FACTOR=1.5` など）ではさらに重くなります**（撮る実ピクセルも描く実ピクセルも増えるため。1280×720 で 28fps、1920×1080 で 20fps 程度）。

自分で加減できるよう、目安を2か所に出しています。

- **範囲選択中**：その大きさで出せそうな fps（`比率: 16:9　目安 30fps`）
- **ミラー中**：実測 fps（手元の枠に添えた帯。**帯もミラーには映り込みません**）

### ミラー先のモニタ

**モニタが3枚以上ある構成でも、どれに出すかを選べます。** サブメニュー **🖵 ミラー先** から選ぶと `screen_mirror.target_screen_name` に保存され、次回以降もそこに出ます。「自動」に戻すと、**選択範囲が乗っていないモニタ**の先頭を使います。

選んだモニタに全画面で出し、**アスペクト比は保ったまま余白は黒**にします。

**選択範囲がミラー先のモニタに重なっているときは始まりません**（自分を撮ることになり、無限に入れ子になるため）。通知でその旨をお知らせします。モニタが1台しかないPCでも同じ理由で始まりません。

### ミラー先に描かれるもの

| | 動き |
|---|---|
| **カーソル** | 白い矢印を自前で描きます（実カーソルは画面キャプチャに写りません）。**大きさは拡大率によらず一定**なので、どの範囲を選んでも見え方が揃います |
| **レーザーポインタ** | `Ctrl+Alt+L`。ミラー先に赤い光点。**出している間はカーソルを隠します**（同じ位置に2つ重ねない） |
| **スポットライト** | `Ctrl+Alt+O`。ミラー先で周囲を暗くします。**大きさと暗さは発表中にその場で変えられます**（下記） |
| **クリック波紋** | クリックした瞬間、押した位置に輪が広がります。画面共有では「今押した」が伝わりにくいため |
| **黒画面・白画面** | `Ctrl+Alt+B` / `Ctrl+Alt+W`。**ミラー先だけ**を覆います。手元は普通に見えたままです（下記） |

**ミラー中は、4つとも行き先が自動でミラー先へ切り替わります。** ホットキーもメニューも[プレゼン支援](#プレゼン支援presenter_overlaypy)と共通で、キーは増えていません。レーザーとスポットライトを振り替えるのは、手元の画面に重ねるとそれがそのまま撮られて向こうへ二重に映る（スポットライトは減光ごと焼き込まれて戻せない）ためです。ミラーを止めれば、どれも従来どおり手元に重なります。

#### 黒画面・白画面は共有側だけ

**ミラー中の `Ctrl+Alt+B` / `Ctrl+Alt+W` は、ミラー先のモニタだけを覆います。手元はそのまま見えています。** 以前は手元（カーソルのある画面）を覆い、覆われた結果がミラーにも映る作りでしたが、それでは**手元まで真っ黒になって次に何を見せるか準備できません**。覆っている間はキャプチャそのものを止めるので、そのぶんCPUも空きます。

覆っていることは**手元の3か所**に出ます（静止と同じ流儀）。手元が普通に見えている以上、ここに出さなければ気付きようがないためです。

- **枠の色が青（`#00c8ff`）から紫（`#a855f7`）に変わる**
- 枠の帯が `⬛ 共有側だけ黒画面（手元は見えています）` になる
- ツールバーの ⬛ が点灯し、右側に `⬛ 共有側は黒画面` と出る

**ミラーしていないときは従来どおり**、カーソルのある画面を覆います。

#### スポットライトの大きさと暗さをその場で変える

**手元のツールバーの上でホイールを回すと半径、`Shift`（または `Ctrl`）+ホイールで暗さが変わります。** スポットライトのアイコンの上なら消えていても効き、点いている間はツールバーのどこで回しても効きます。変えた値は右側に `スポット 半径 170 / 暗さ 72%` のように出ます。

**変えた値は `presenter_overlay.spotlight_radius` / `spotlight_dim` へ書き戻されるので、次回も同じ設定で始まります。** 書き戻しは最後の操作から少し置いてから1回だけ行います（ホイールは目盛りが連続で飛んでくるため）。半径は 20〜1200、暗さは 0〜95% で止まります（100% にすると周りが完全に潰れ、資料の一部に注目させるという目的から外れるため）。

色や大きさの設定は `presenter_overlay` セクションと共通です（同じ道具の同じ光点を2か所で設定させないため）。

**カーソルが選択範囲の外に出たら、ミラーには何も描きません。** 端に貼り付けて見せることもできますが、実際には指していない場所に光点や矢印が居座るのは見ている側への嘘になります。消えること自体が「発表者はいま範囲の外を触っている」という正しい情報になり、戻ってくれば同じ位置に現れます。

### 手元の枠

いま映している範囲が手元で分かるよう、**範囲のまわりに薄い枠**を出し続けます（`screen_mirror.source_frame` で切れます）。

**枠は範囲の外側にあり、ミラーには映り込みません。** 枠の窓そのものに `setMask` で範囲ぶんの穴を開けているので、撮る範囲にこの窓のピクセルは1枚もありません（毎フレーム隠して出し直すとちらつくうえ、1枚17msの予算に窓の表示切替が乗ります）。穴の部分のクリックもそのまま下へ抜けます。

### 手元のツールバー

**枠の下（範囲の外）に、プレゼン支援の操作をアイコンで並べます**（`screen_mirror.toolbar` で切れます）。トレイメニューまで手を伸ばさずに押せるようにするためのものです。

| アイコン | 機能 |
|---|---|
| 🔴 | レーザーポインタ（`Ctrl+Alt+L` と同じ。ミラー先に描かれます） |
| 💡 | スポットライト（`Ctrl+Alt+O` と同じ） |
| ⬛ | 黒画面（`Ctrl+Alt+B` と同じ。**ミラー先だけ**を覆います） |
| ⬜ | 白画面（`Ctrl+Alt+W` と同じ） |
| ⏸ | **静止**（下記） |
| 🔲 | 範囲を選び直す（映したまま） |
| ✕ | ミラーを終了 |

**点いている機能はアイコンが点灯します**（下地に色が敷かれて縁取られます）。ホットキーやトレイメニューから切り替えても追随します。マウスを乗せると右側に名前が出ます。

**ツールバーも範囲の外にあり、ミラーには映り込みません。** 枠の真下（入らなければ真上）に置き、それでも撮影範囲に掛かってしまう場合は**出しません**（映り込むと、映った自分をまた撮る入れ子になるため）。枠がマウスを透過する窓なので、押せるものは別の窓として出しています。

### ミラー範囲を動かす — ツールバーのタイトルバーをドラッグ

**ツールバー右側（点々の付いた説明欄）がタイトルバーです。そこを掴んでドラッグすると、映す範囲ごと動きます。** 手元の枠とツールバーも一緒に付いてきて、**ドラッグしている間もミラーは動いた先を映し続けます**（範囲を選び直すのと違い、共有が途切れません）。**大きさは変わりません**（移動だけ）。

**アイコンの上のドラッグでは動きません。** 押すつもりで少し滑っただけで範囲ごと動いては困るためです（付箋で「画像部分のドラッグで動く」をやめたのと同じ判断）。

歯止めは2つです。

- **ミラー先のモニタには重ねられません**（自分を撮ると無限に入れ子になるため）。突き当たったら、その向きの成分だけ捨てて残りは動きます（縁に沿って滑らせられます）
- **範囲の中心は画面の中に残ります。** 画面の外へ丸ごと送れてしまうと掴む手段が無くなるうえ、ツールバーの置き場所も「範囲の中心にあるモニタ」を基準に探しているので、中心が画面外だと離した瞬間にツールバーが画面外へ行ってしまいます

離したところで、枠とツールバーを新しい範囲に合わせて作り直します（帯を範囲の上下どちらに置くか、ツールバーが下に収まるかは位置ごとに変わるため）。

### 静止（一時停止）— 手元を見せずに切り替える

`Ctrl+Alt+F` ／ ツールバーの ⏸ ／ トレイメニューの **⏸ 静止（一時停止）** で、**ミラーを静止させられます**。止めている間は撮りに行かないので、向こうには最後の1枚が出たままになります。手元で資料を切り替えたり、見せたくないものを開いたりする間に使ってください。もう一度押すと現在の画面に戻ります。

**静止していることは手元の3か所に出ます。**

- **枠の色が青（`#00c8ff`）から橙（`#ff8c00`）に変わる**
- 枠の帯が `⏸ 静止中（動いていません）` になる
- ツールバーの ⏸ が点灯し、右側に `⏸ 静止中` と出る

気付かずに静止したまま話し続けるのがいちばん困るので、ここは目立たせてあります。**ミラー先には何も出しません**——静止していることを知る必要があるのは発表者だけで、向こうに印を出したら「今は見せていない」と宣言することになります。

静止中は**カーソルもレーザーも波紋も描きません**。絵が止まっているのに指先だけ動くと、指している場所が嘘になるためです。

### 手元のカーソルのちらつき対策

ミラー中に手元のマウスカーソルがちらつく、という報告への対策として2つ手を打っています。**どちらが効いたかは目視でしか確かめられないので、断定はしていません。**

**① 毎フレームの `BitBlt` から `CAPTUREBLT` を外しました。** mss は `SRCCOPY | CAPTUREBLT` で撮ります。`CAPTUREBLT` は「上に重なっているレイヤードウィンドウも結果に含める」フラグで、そのために Windows は撮る直前に**画面からカーソルをいったん取り除きます**。1枚撮るだけなら誰も気付きませんが、**毎秒30回撮り続けると目に見えるちらつきになります**（`gdigrab` などの画面録画でも知られた症状です）。

ミラーはそもそもレイヤードウィンドウを撮りたくない（自前の枠やツールバーが写ると入れ子になる）ので、外して困るものがありません。**このPCで実測しても、可視のレイヤードウィンドウ6枚の矩形を `CAPTUREBLT` あり／なしで撮り比べて1バイトも違いませんでした**（DWM 合成の画面から `BitBlt` する以上、フラグの有無で中身が変わらないため）。付箋（Rapture）側の1枚撮りは従来どおり `CAPTUREBLT` を付けたままです（`grab_region(..., include_layered=False)` を指定したときだけ外れます）。

なお `GetCursorInfo` の `CURSOR_SHOWING` は、`CAPTUREBLT` 付きで撮り続けている間も一度も落ちませんでした（3.3秒・180万サンプル中0件）。**この取り除きはウィンドウごとの表示カウントには表れない**ということなので、この計測は仮説を否定する材料にはなりません。

**② 最前面への押し上げを「実際に覆われているときだけ」にしました。** 以前は枠・ツールバー・ミラー窓の3枚が、500ms ごとに無条件で `raise_()` していました。Zオーダーを触る操作は毎回 Windows に並びを組み替えさせ、**カーソルの下にあるウィンドウへ当たり判定とカーソル形状の問い合わせを出し直させます**。いまは `GetWindow(GW_HWNDPREV)` で自分より手前を遡り、**自分の矩形に重なる可視ウィンドウが1枚も無ければ押し上げません**。

**判断が付かないときは押し上げる側に倒します**（矩形が取れない、遡りが上限に達した等）。ここが誤って「覆われていない」と答えると、ミラー窓が会議アプリの裏へ回って共有先に何も映らなくなり、ちらつきよりはるかに重い事故になるためです。

これに[タスクバーウィジェットの引っ込め](#最前面の維持)を合わせて、ミラー中に 500ms 周期でZオーダーを触る箇所は 4 か所から実質 0 になりました。

### 滲み — 拡大する以上は避けられません

**手元の範囲を引き伸ばして映す以上、補間による滲みは原理的に避けられません。** Qt が持っている拡大方法は2つだけで、その間はありません。

| 方式 | 見え方 |
|---|---|
| `SmoothTransformation`（双線形） | 滑らかだが**滲む**（元に無い中間色が生える） |
| `FastTransformation`（最近傍） | **鮮明**だがブロック状になる |

**本当の解は「等倍で映すこと」です。** 範囲選択の**プリセット「等倍（ミラー先と同じ）」**を選べば、手元の範囲とミラー先の解像度が一致するので**拡大も縮小も起きず、1画素も滲みません**（等倍では上の2方式の出力が完全に一致することを実測で確認しています）。**滲みが気になるときは、まずこれを選んでください。**

等倍にできないときのために `screen_mirror.scaling` を用意しました。`auto`（既定）／`smooth`／`fast`。**`auto` は倍率が整数のときだけ `fast` にします。** 640×360 の文字と細線を実際に拡大して画素を数えた結果：

| 倍率 | 方式 | 元に無い中間色 | 隣接画素の差の平均（輪郭のコントラスト） |
|---|---|---|---|
| 2倍 | Smooth | 16.8% | 9.42 |
| 2倍 | **Fast** | **0%** | **12.15**（約1.3倍鮮明） |

整数倍なら元の1画素がそのまま正方形へ分かれるので、中間色が1つも生えません（2倍では1px幅の線がすべて2pxになることも確認済み）。一方 **1.33倍のような半端な倍率で `fast` にすると、1px幅の線が 1px と 2px に割れて**（実測で 58本と28本）、行によって太さの違う文字になります。だから半端な倍率では `smooth` に落とします。

いま何倍で、どちらの方式で描いているかは、**手元の枠の帯に出ます**（`拡大 2.00倍 鮮明`）。

### なぜ画面をそのまま映すのか

同梱の `presenter.html` は**ローカル HTML 資料専用**で、リンク遷移をすると制御から外れます。WebEngine を内蔵して自前のブラウザにする案もありましたが、それは実質ブラウザを作ることになります。**画面をそのまま映せば、操作の問題が丸ごと消えます。** `presenter.html` はローカル資料用としてそのまま残します（併存）。

## 発表者ツール（`presenter.html`）

HTML のプレゼン資料に、PowerPoint の発表者ツール相当を付ける単一ファイルのビューアを同梱しています。カンペ、次スライドのプレビュー、タイマー、レーザーポインタ、スポットライト、サムネ一覧。

トレイメニューの **📽 発表者ツール**、またはタスクバーウィジェットのランチャから開きます。**サーバー不要**で、既定のブラウザに投げるだけで動きます（`file://` で単独動作するよう作られています）。

資料は**開いた先へドラッグ＆ドロップ**してください。tray-tools から資料を渡す仕組みは持たせていません。`file://` からパス指定で資料を読ませるには、ブラウザのファイルアクセス制限を緩める必要があるためです。

使い方とキー操作は [presenter_README.md](presenter_README.md) を参照してください。

**開くブラウザは Edge です**（`settings.json` の `tools.browser` で `chrome` / `firefox` / 実行ファイルのフルパスに変えられます）。既定のブラウザに任せないのは、**Firefox では真っ白になる**ためです。`presenter.html` は `about:blank` へ `document.write` して親と同一オリジンにする作りで、Firefox の `file://` の扱いと噛み合いません。Chrome と Edge では動きます。

別の場所に置いたものを使いたいときは、`settings.json` の `tools.presenter` にパスを書けば差し替えられます。空なら同梱のものを開きます。

### 任意のサイトを取り込んで開く（`web_presenter.py`）

トレイメニューの **🌐 サイトを取り込んで開く** で URL を尋ねられます。入力すると、そのページを取り込んで**発表者ツールの資料として**既定のブラウザで開きます。ローカルの HTML 資料と同じように、カンペ・次スライド・タイマー・レーザーが使えます。

**なぜ一手間かかるのか。** `presenter.html` は資料を `about:blank` へ `document.write` して親と同一オリジンにすることで DOM を直接操作しています。他所のサイトを `iframe` で直接開くとクロスオリジンで何も触れません。そこで **tray-tools 側がブラウザ（`QtWebEngine`）を持ちます**。こちらでサイトを開いてレンダリング後の DOM を文字列として取り出し、それを資料として渡す——相手のサーバから見れば普通の閲覧なので壁はありません。取り出した後はただの HTML 文字列なので、`presenter.html` はローカル資料と区別せずに扱えます。

流れは次のとおりです。

1. `QInputDialog` で URL を尋ねる（一度取り込んだ URL は履歴として入力欄に並びます）
2. **非表示の** `QWebEngineView` でそのページを開く（窓は出ません）
3. `page().toHtml()` で**レンダリング後の DOM** を取り出す（JS が組み立てた内容も入ります）
4. `<head>` の先頭に `<base href="元のURL">` を挿す。これで画像・CSS・フォントの相対参照が元のサーバから引けます
5. `presenter.html` の中身＋「起動時に `loadHtml()` を呼ぶ `<script>`」を `%TEMP%\traytools-presenter\` に書き出す
6. そのファイルを既定のブラウザで開く

**`presenter.html` は1バイトも変えていません。** 「単一ファイルを `file://` からダブルクリックで動かせる」ことがあのファイルの存在理由なので、こちらの都合を持ち込まない方針です。足すのは末尾の `<script>` だけで、それも `%TEMP%` に書き出すコピーに対してだけ行います。**`QtWebEngine` は PySide6 のフルインストールに最初から入っている**ので追加依存もありません（読み込みが重いので `import` は使うときまで遅らせています。実測 45ms）。

#### 制約

- **認証の要るサイトは取り込めません。** 取り込みに使う `QWebEngine` は窓を出さずに動かしており、**中で対話的にログインする手段がありません**（クッキーも都度空です）。ログイン後のページを資料にしたい場合は、ブラウザで「名前を付けて保存（完全）」してから **📽 発表者ツール** にドラッグ＆ドロップしてください。ログイン用の窓を出す・プロファイルを保存する、という道もありますが、「画面に勝手に窓を出さない」ほうを優先して採っていません。
- **取り込みはスナップショットです。** 取り込んだ後に元のサイトが変わっても追随しません。最新にしたいときは取り込み直してください（履歴から同じ URL を選べます）。
- **SPA や凝った動的サイトは崩れることがあります。** 取り込んだ `<script>` は発表者ツールの `iframe` の中で改めて実行されるため、ルーティングや「元の URL 前提」の処理が暴れることがあります。そういうサイトは `settings.json` の `tools.web_presenter_strip_scripts` を `true` にすると `<script>` を落として静止させられます。
- **JS で後から書き足すページ**は、読み込み完了から `tools.web_presenter_settle_ms`（既定 800ms）だけ待ってから取り出します。骨組みしか取り込めないときはここを伸ばしてください。
- **読み込みが終わらないサイト**があるので、`tools.web_presenter_timeout_seconds`（既定 30 秒）で必ず打ち切ります。失敗しても通知が出るだけで、常駐アプリは落ちません。

#### 設定

| キー | 既定 | 意味 |
|---|---|---|
| `tools.web_presenter_timeout_seconds` | `30` | 読み込みの打ち切り（秒）。`loadFinished` が来ないサイト対策 |
| `tools.web_presenter_settle_ms` | `800` | 読み込み完了から DOM を取り出すまでの追加の待ち（ミリ秒） |
| `tools.web_presenter_strip_scripts` | `false` | `true` で取り込んだ `<script>` を落とす |
| `tools.web_presenter_recent` | `[]` | 入力欄に出す履歴。取り込みに成功したときだけ増える（最大10件） |

ランチャ（タスクバーウィジェット）にも `web_presenter` として登録してあります。ただし**既定の並びには入れていません**（パネルは縦に伸びる一方なので）。使うなら `settings.json` の `launcher_items` に足してください。

```json
"launcher_items": ["capture", "audio", "ruler", "color_picker", "snippets", "bookmarks", "web_presenter"]
```

#### 実装で気を付けた点

- **`toHtml()` も `runJavaScript()` もコールバック方式**です。同期では取れないので、`document.baseURI` → `toHtml()` の順に入れ子で呼んでいます。`<base>` に `view.url()` ではなく `document.baseURI` を使うのは、ページ自身が `<base href>` を持っていた場合にその解決結果を尊重するためです（元からある `<base>` は `<head>` の中からだけ消します。文書順で最初の `<base href>` だけが効くうえ、相手が相対 href だと `%TEMP%` の `file://` を基準に解決されて全部壊れるため）。
- **`QWebEngineView` の参照を握り続けます。** 読み込みは非同期なので、掴んでいないと関数を抜けた瞬間に GC で消えて何も起きません（`web_presenter._ACTIVE`）。
- **取り込んだ HTML を JS に埋めるとき、`<` をすべて Unicode エスケープ（バックスラッシュ + `u003c`）へ逃がします。** `JSON.stringify` 相当だけでは足りません。資料の中に `</script>` が現れると**そこで囲っている `<script>` タグが閉じてしまい**、以降が本文として垂れ流されます（HTML パーサは JS の文字列リテラルの中かどうかを見ません）。生の `<` を残さなければ `</script>` も `<!--` も HTML パーサからは見えなくなります。
- **一時ファイルは溜まるので掃除します。** 取り込むたびに `%TEMP%\traytools-presenter\site_*.html` が1枚増え、ブラウザに投げた後は誰も片付けません。次に取り込むついでに**6時間より古いものを消します**（付箋の受け渡し PNG が5分なのに対して長いのは、こちらはタブが生きている限り再読み込み（F5）の対象で、消すとタブが白くなるためです）。
- **履歴の保存は「指定キーだけを書き戻す」**作法です。メモリ上の設定は既定値をマージ済みなので、丸ごと書き出すと未設定の既定値まで `settings.json` に書かれて姿が変わります（`launcher.save_bookmark` と同じ）。
- **入力に `picker.py` は使いません。** あれは「用意された一覧から1つ選ぶ」窓で自由入力の口がなく、ここで欲しいのは毎回違う文字列だからです。ただし「同じサイトをもう一度」は頻繁に起きるので、履歴があるときは `QInputDialog.getItem(..., editable=True)` の編集可能なコンボボックスにして、選ぶことも打ち直すこともできるようにしています。ダイアログには `Qt.WindowStaysOnTopHint` を足しています（呼び元にタスクバーウィジェットがあり、あれは枠なし・最前面の窓なので、素のダイアログだとその陰に隠れて「押したのに何も起きない」ように見えます）。

## フォルダブックマーク（あふｗ／エクスプローラ）

登録したフォルダを絞り込んで選ぶと、そのフォルダへ移動します。`Ctrl+Alt+B`（既定）またはメニューから開きます。ウインドウの操作は定型文と同じです（同じ選択ウインドウ `picker.py` を使っています）。

移動先は二画面ファイラ **[あふｗ](https://akt.d.dooo.jp/afxw.html)** と、Windows の**エクスプローラ**の2つです。どちらへ送るかは `settings.json` の `launcher.target` で決めます。

| `launcher.target` | 動作 |
|---|---|
| `auto`（既定） | **ブックマークを開いた時点で前面だったウィンドウ**がエクスプローラなら、その窓を移動させる。それ以外（あふｗ・ブラウザ・エディタなど何でも）ならあふｗへ送る |
| `afxw` | 常にあふｗへ送る（この機能を足す前の動作） |
| `explorer` | 常にエクスプローラ。前面がエクスプローラでなければ**新しい窓を開く** |

**判定に使うのは「開いた時点」の前面ウィンドウです。** ピッカーが出た瞬間に前面はピッカー自身へ移るので、`ScreenFeature.start_launcher()` の**いちばん最初**に `GetForegroundWindow()` で掴んでから `launcher.create_picker()` へ渡しています（ホットキー・メニュー・IPC の3経路すべて同じ）。前面が取れない場合は掴まなかったことにして、従来どおりあふｗへ落ちます。

エクスプローラを移動させるときは**新しい窓を開かず、今見ている窓の中身を差し替えます**（あふｗの `-s -p` と同じ考え方）。ピッカーを開いている間にその窓が閉じられていた場合や、移動に失敗した場合は新しい窓を開きます（黙って何も起きないのが一番困るため）。

あふｗへの移動は `AFXW.EXE -s -p"パス"` の形で呼び出します。`-s` は二重起動せず既存のあふｗに渡す指定、**小文字の `-p`** は「そのフォルダの中を表示」です（大文字の `-P` は親フォルダを開いてカーソルを合わせる別の動作なので使いません）。`launcher.afxw_path` の実行ファイルが見つからない場合は、その旨を通知します。

登録は `settings.json` の `launcher.bookmarks` に貯まります。**削除・並べ替え・名前の変更は `settings.json` を直接編集してください**（定型文をフォルダに置くのと同じで、専用の編集UIは持ちません）。

### エクスプローラとのやり取り（`explorer_nav.py`）

エクスプローラが今どこを開いているかは、`Shell.Application` の `ShellWindows`（COM）越しに読みます。`explorer_nav.py` がその窓口で、トレイアイコンは持ちません（`window_tools.py` と同じ立ち位置）。実装で踏んだ点：

- **パスは `LocationURL` から組み立てます。** `w.Document.Folder.Self.Path` で直接取る手もありますが、comtypes の遅延バインディングでは `AttributeError` になって届きません。
- **`file:///C:/Users/...` は URL エンコードされています。** 日本語やスペースを含むパスは `%E3%83%89...` の形で入っているので、`unquote` を通さないと化けたパスができます。
- **`file:` 以外は対象外です。** コントロールパネル・ごみ箱・「PC」などの特殊フォルダ（`::{GUID}` 形式）はパスが無いものとして扱います。
- **`ShellWindows` はエクスプローラと Internet Explorer の両方を列挙します。** `FullName` が `explorer.exe` で終わるものだけを見ます（IE に `Navigate` すると見当違いのページを開かせてしまうため）。
- **`comtypes.COMError` は `OSError` のサブクラスではありません。** 両方を捕まえないと素通りします（`mic_control.py` と同じ罠）。ここの関数は例外を投げず、取れなければ `None`／失敗なら `False` を返します（**PySide6 はスロットから例外が抜けると常駐アプリごと終了する**ため）。
- **COM オブジェクトは呼ぶたびに作り直します。** エクスプローラを再起動すると以前の参照は無効になり、以後ずっと `COMError` を返す抜け殻になります。ブックマークを選んだときにしか呼ばない＝1操作につき1回なので、掴み続ける価値がありません。

対象とみなすのはウィンドウクラスが `CabinetWClass` のフォルダウィンドウだけです（デスクトップや「ファイルを開く」ダイアログは別クラスなので動かしません）。

### 「＋ ここを登録」

一覧の末尾に **「＋ ここを登録   `<いま見ているパス>`」** が並ぶことがあります。選ぶと名前を尋ねられ（既定はフォルダ名）、`launcher.bookmarks` に追記されます。パスの決め方は次の優先順位です。

1. IPC で渡されたパス（あふｗが `$P` で明示してきたカレント）
2. 前面のエクスプローラが開いているパス
3. どちらも無ければ、この項目は出ません

つまり**ホットキーやメニューから開いた場合でも、前面がエクスプローラなら登録できます**（あふｗから呼んだときだけ、という制限は無くなりました）。登録項目を全角の `＋` で始めているのは、英字を打った時点で候補から外れるようにするためです（ブックマークを選ぶつもりで `Enter` を押して誤登録するのを防ぎます）。

### あふｗから呼ぶ（`$P` で今いるフォルダを渡す）

あふｗ側からはコマンド送信用の極小スクリプト `traytools_send.py` を叩きます。`AFXW.key` に次のように書きます（`$P` はあふｗのカレントパス）。

```
K00xx="4074C:\Users\<ユーザー名>\.venvs\tray-tools\Scripts\pythonw.exe R:\claude\tray-tools\traytools_send.py bookmark "$P""
```

`traytools_send.py` は **PySide6 を import しません**。Qt の import だけで1秒近くかかり、キーを押してからウインドウが出るまでの体感がそのぶん遅くなるためです（標準ライブラリだけで書いてあります）。tray-tools が起動していない場合は標準エラーにメッセージを出して終わります（**勝手に常駐アプリを起動したりはしません**）。

### 外部からのコマンド受付（IPC）

多重起動を防ぐための待ち受け（`QLocalServer`／Windows では名前付きパイプ `\\.\pipe\traytools.single-instance`）が、そのまま外部コマンドの入口を兼ねています。接続して**UTF-8 の JSON を1行**書くと、常駐中の本体がその機能を開きます。

```json
{"command": "bookmark", "args": ["C:\\いまのパス"]}
```

| `command` | 動作 |
|---|---|
| `bookmark` | フォルダブックマークを開く。`args[0]` があれば、そのパスで「ここを登録」を添える（無い場合は前面のエクスプローラから読む） |

何も書かずに切れた場合は、従来どおり「すでに起動しています」と通知します（＝ただの二重起動）。知らない `command` は通知で知らせるだけで、常駐は続きます。

## 付箋は本体とは別のプロセス（`capture_process.py`）

**付箋（Rapture のキャプチャウインドウ）は、常駐アプリ本体とは別のプロセスで動きます。** 本体が落ちても、機能を足して**再起動しても、開いている付箋はそのまま残ります**。手順書を作るために連番キャプチャで何枚も並べている最中に本体を再起動すると付箋が全部消える、という道連れを防ぐためです。

- 付箋1枚につき1プロセス（`pythonw.exe capture_process.py ...`）。閉じるとそのプロセスは終わります。
- 画像はプロセス境界を越えられないため、一時フォルダ（`%TEMP%\traytools-rapture\`）へ PNG を書いて渡します。**付箋は読み込んだ時点でその PNG を消します**（起動に失敗して取り残された分は、次に付箋を開くときにまとめて掃除されます）。
- 付箋は起動時に**自分専用の名前付きパイプ** `\\.\pipe\traytools.rapture.<作成時刻ms>.<pid>` を開いて待ち受けます。中身の約束事は本体の IPC と同じ、UTF-8 の JSON 1行です。

| `command` | 動作 |
|---|---|
| `capture_sequence` | 連番キャプチャを1枚進める（右クリックメニューの「キャプチャ＆保存」と同じ） |
| `ping` | 何もしない。生きているかを確かめるためだけのもの |

`Ctrl+Alt+S` を押すと、本体は `\\.\pipe\` の一覧からこの名前を探し、**作成時刻がいちばん新しい付箋**へコマンドを送ります。一覧から毎回引き当てるので、**本体を再起動しても対象を見失いません**。

### 待機プロセス（付箋が出るまでの待ちを消す仕組み）

別プロセスにした当初は、**付箋を1枚出すたびに Python と Qt を読み込む**ため、範囲を選んでから付箋が出るまで 0.4 秒ほどかかっていました（別のPCでは3秒以上という報告もあります）。その7割強は「Qt を読み込んで最初のウインドウを出す」固定費で、コードの書き方では縮みません。

そこで、**その費用を待たされない時間帯へ前払いします。**

1. 本体の起動から3秒後、付箋プロセスを1つ **待機役** として起こしておきます（`capture_process.py --prewarm`）。待機役は Qt を読み込み、付箋ウインドウの実体まで作り、**画面外・不透明度0・タスクバーにも出さない状態で一度だけ描画してから隠れて待ちます**。
2. キャプチャのときは、その待機役へ**画像と表示位置を送るだけ**。受け取った待機役は隠していたウインドウを出して、普通の付箋になります。
3. 本体は続けて**次の待機役を裏で起こします**。

実測（このPC。範囲を選んでから付箋の待ち受けが立つまで、5回の平均）:

| | 実測 |
|---|---|
| 待機役あり（既定） | **9.9 ms** |
| 待機役なし（従来どおり1枚ごとに起動） | 354.9 ms |

**待機役が居ないときは必ず従来どおりの起動に落ちます。** 待機役が死んでいてキャプチャが失敗する、ということはありません（そのぶん 0.4 秒かかりますが、確実に出ます）。落ちた場合も、次の1枚のために待機役の補充を試みます。

代償は**常時1プロセスぶんのメモリ**です。実測で**専有 27MB 前後**（ワーキングセットは 56MB ですが、大半は Qt の DLL で本体と共有しています）。惜しい場合は `settings.json` の `capture.prewarm` を `false` にすると、1枚ごとにプロセスを起こす従来の形へ戻ります。

- 待機役は `\\.\pipe\traytools.rapture-warm.<起きた時刻ms>.<pid>` で待ち受けます。付箋の名前（`traytools.rapture.<...>`）とは**別の名前空間**なので、`Ctrl+Alt+S` が画面に出ていない待機役へ飛ぶことはありません。
- 待機役は**本体を終了すると一緒に終わります**（まだ何も表示していないので残す理由がありません）。本体が落ちて合図を送れなかった場合も、待機役自身が本体の待ち受けを15秒ごとに見ていて、2回続けて見つからなければ自分で終わります。**付箋になったあとはこの見張りを止める**ので、表示中の付箋が本体の終了で消えることはありません。
- 待機役を使うと `Ctrl+Alt+S` の宛先が立つのも速くなるため、「キャプチャ直後に間髪入れず押すと1つ前の付箋が対象になる」問題も起きにくくなります。

### 連番キャプチャ（`Ctrl+Alt+S` / Space）

手順書を作るときのように、**同じ範囲を何度も撮る**使い方のための機能です。

範囲を1回選んで付箋を出したら、あとは「操作する → `Ctrl+Alt+S` → 操作する → `Ctrl+Alt+S`」と繰り返すだけで撮り溜められます。押すと、付箋自身が写り込まないよう一瞬隠れてから**その付箋が今いる位置**を撮り直し、保存して、付箋の表示を新しい画像に差し替えます（描き込んだ内容はクリアされます）。

**`Ctrl+Alt+S` は付箋がアクティブでなくても効きます。** ブラウザやアプリを操作する側にフォーカスを置いたまま撮れる、というのがこの機能の本命の使い方です（付箋は常に最前面で位置を保っているので、フォーカスが無くても狙った範囲がそのまま撮れます）。

**対象は「いま開いている中でいちばん新しい付箋」です。** 付箋は同時に何枚でも開けますが、ホットキーが撮るのはその1枚だけです。その付箋を閉じると、対象は**残っている中で次に新しい付箋**へ移ります。1枚も開いていなければ `Ctrl+Alt+S` は「付箋がありません」と通知します。

> 付箋を別プロセスに出す前は「最後に作った付箋」をオブジェクトとして掴み続けていたため、それを閉じると他の付箋が残っていても対象は無しになっていました。いまは押されるたびに待ち受けの一覧から選び直すので、次に新しいものへ引き継がれます（そのかわり本体を再起動しても対象を見失いません）。

**キャプチャ直後に間髪入れず押すと、1つ前の付箋が対象になることがあります。** その付箋の待ち受けがまだ立っていないためです（付箋が1枚のときは「付箋がありません」と出るだけです）。待機プロセスが使われた場合は待ち受けが 10ms 前後で立つので、まず起きません。従来どおりの起動に落ちたときだけ 0.4 秒ほどの隙があります。

**付箋がアクティブなときは Space も使えます。** 手元で付箋を触っているときの近道で、実行される処理は `Ctrl+Alt+S` とまったく同じものです。Space をグローバルホットキーにすると全アプリの文字入力を奪ってしまうため、非アクティブでも効く方は `Ctrl+Alt+S` に分けています。

**撮っている最中に押しても二重には走りません。** 隠す → 少し待つ → 撮る、という流れなので、待っている間の入力は無視されます（連打しても同じ絵が2枚保存されたりしません）。

**付箋1枚が1つの「セッション」**です。ファイル名のタイムスタンプは付箋を作った時刻で固定され、撮るたびに末尾の連番（3桁ゼロ埋め）だけが増えるので、一連の作業がファイル名でまとまります。

```
rapture_20260823_140919-001.png   ← キャプチャ直後の自動保存
rapture_20260823_140919-002.png   ← Ctrl+Alt+S
rapture_20260823_140919-003.png   ← Ctrl+Alt+S
```

- **直前に保存した画像と変化が無ければ、保存も連番の加算もしません。** 同じ絵が溜まらないようにするためです。見送ったときは「変化がないので保存しませんでした」と通知が出ます（付箋の表示もそのまま＝描き込みは消えません）。
- 付箋の**左上に、そのセッションで何枚目かのバッジ**が出ます。これはウインドウ上に描いているだけなので、**保存される画像やコピーした画像には含まれません**。ズームしても大きさは変わりません。
- 「再キャプ」（右クリックメニュー）は従来どおり、保存せずに撮り直すだけです。連番は進みません。
- Ctrl+S の「保存」は描画内容を焼き込んだ別物の保存なので、連番セッションには入らず `rapture_YYYYMMDD_HHMMSS.png` として保存されます。

| `screen_mirror.toolbar` | 手元の枠の下に操作パネル（レーザー・スポットライト・黒画面・白画面・静止・選び直し・終了）を出すか（既定 `true`）。**これも範囲の外に置くのでミラーには映り込みません**（置ける場所が無いときは出ません）。**右側の説明欄はタイトルバーを兼ねていて、ドラッグすると[ミラー範囲ごと動きます](#ミラー範囲を動かす--ツールバーのタイトルバーをドラッグ)。ホイールで[スポットライトの大きさと暗さ](#スポットライトの大きさと暗さをその場で変える)が変わります** |
| `screen_mirror.scaling` | 拡大方法。`auto`（既定）／`smooth`（滑らか・滲む）／`fast`（鮮明・ブロック状）。`auto` は**倍率が整数のときだけ** `fast`。**滲みを本当に無くしたいならプリセット「等倍（ミラー先と同じ）」で映してください**（拡大が起きないので滲みません）。詳細は[滲み](#滲み--拡大する以上は避けられません) |
| `screen_mirror.presets` | 範囲選択で一発で選べる矩形の配列（クリックか `Ctrl`+数字）。`{"label": 見出し, "width": 幅, "height": 高さ, "x": 始点X, "y": 始点Y}`。`"size": "target"` と書くと**ミラー先と同じ解像度**（＝等倍）。`x`/`y` は**今カーソルのあるモニタの左上からの相対**で、`"screen"` にモニタ名を書けば固定できます。詳細は[プリセット](#プリセット--決まった矩形を一発で) |
| `taskbar_widget.enabled` | タスクバーウィジェットを出すか（既定 `false`）。**メニューの「🖥 タスクバーウィジェット」で切り替えると、この値も自動で書き換わります** |
| `taskbar_widget.all_displays` | 全ディスプレイに出すか（既定 `true`）。`false` にするとプライマリの画面だけ外す（そちらには本物の通知領域があるため） |
| `taskbar_widget.positions` | 表示位置を**ディスプレイごと**に持つ辞書。キーはモニタの型番とシリアル（`EX-LDGCQ321HD#951` 等）、値は `{"right": タスクバー右端からの距離, "top": タスクバー上端からの距離}`。**Ctrl+左ドラッグで動かしたウィジェットの分だけが書き込まれます**（他の画面は動きません）。書かれていない画面は既定の余白（右 19px・上 10px）で自動配置。**知らないモニタは無視されるので、別のPCへこのファイルを持って行っても壊れません** |
| `taskbar_widget.width` / `.height` | 大きさ（既定 `59` x `31`＝Windows 11 の時計の描画範囲の実測値）。下の本物の時計を隠しきれない場合は少し大きくしてください |
| `taskbar_widget.background_color` | 背景色（`#rrggbb`）。`null` なら表示直前にその位置の画面を撮って最頻色を使う（タスクバーの透明効果で壁紙が透けるため、決め打ちでは浮きます） |
| `taskbar_widget.text_color` | 時計の文字色（`#rrggbb`）。`null` なら背景の明るさから自動で黒／白を選ぶ |
| `taskbar_widget.clock_format_top` | 上段（時刻）の `strftime` 書式。既定 `%#H:%M`。**先頭ゼロを落とすのは Windows では `%#H` です**（`%-H` は Linux 系） |
| `taskbar_widget.clock_format_bottom` | 下段（日付）の `strftime` 書式。既定 `%Y/%m/%d` |

**ホットキーは空文字 `""` にすると登録されません**（無効化したい場合や、他アプリと競合する場合に使います）。

デバイスIDが分からなくなった場合は `%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe list_devices.py` で一覧を確認できます。

## 機能の追加方法

`feature_xxx.py` に、次の規約を満たすクラスを1つ書きます（抽象基底クラスは無く、ダックタイピングです）。

- コンストラクタ `__init__(self, app_settings, settings_path)` で `QSystemTrayIcon` を1つ構築し、`self.tray_icon` に保持する
- `hotkeys()` メソッドで `{"設定キー名": 呼び出す関数}` の辞書を返す（不要なら空辞書 `{}` を返す）

書けたら `main.py` の `FEATURE_CLASSES` リストにクラスを追加するだけです。ホットキーの実体（`ctrl+alt+x` のような文字列）は `settings.json` の `hotkeys` セクションに追記してください。

**Feature を増やすのは「アイコンの見た目を占有する状態」を持つ場合だけにしてください。** アイコンを持たない機能は普通のモジュール（`color_picker.py` / `snippets.py` / `launcher.py` / `taskbar_widget.py` など）として書き、既存 Feature のメニュー項目から呼びます。開いたウインドウの参照は呼び出し側（`ScreenFeature`）が保持します（**ローカル変数だけだと GC で即消えます**）。

`taskbar_widget.py` は「画面に出っぱなしになる窓を持つが、Feature ではない」例です。トレイアイコンを持たないので Feature の条件に当てはまらず、生成と参照の保持は `ScreenFeature` が行います。他の Feature の参照が要る場合は、**Feature が全部そろってから** `main.py` 側で渡してください（`_wire_taskbar_widget()` がその例です。コンストラクタは1つずつ呼ばれるので、その中では相手がまだ居ません）。

「一覧から絞り込んで1つ選ぶ」UIが要る場合は `picker.PickerWindow(タイトル, [(表示名, データ), ...], on_accept)` を使ってください。決定すると `on_accept(表示名, データ)` を呼び、その後**必ず**ウインドウを閉じて `closed` を出します（定型文とフォルダブックマークが同じ窓を共有しています）。

`PickerWindow` には任意の引数がいくつかあり、**渡したものだけが姿を現します**（既定では今までどおり「絞り込んで選ぶだけ」の窓です）。定型文には要るがフォルダブックマークには要らない、という差をここで吸収しています。

| 引数 | 渡すと |
|---|---|
| `preview_provider(データ) -> str` | リストの下に読み取り専用のプレビューが出る。選択が動くたびに呼ばれる。窓の横幅も広がる |
| `hint` | ウインドウ下部に小さな説明の行が出る（改行可） |
| `on_new()` / `on_edit(表示名, データ)` / `on_open_folder()` | `Ctrl+N` / `Ctrl+E` / `Ctrl+O` が効くようになる。いずれも**実行後にウインドウを閉じます** |

渡さなかった処理のキーは握り潰さずに素通しします（押しても何も起きないだけです）。プレビューやキー操作の追加分は `_fit_to_items()` で**固定値の高さ**として足しています。`QT_QPA_PLATFORM=offscreen` ではフォントメトリクスが当てにならず、測った値だけを根拠にすると環境によって高さが潰れるためです。

## 既知の制限事項

- **マルチモニタでDPI(拡大率)が異なる場合、1回の選択が2画面をまたぐとズレが残ります。** キャプチャは選択範囲の中心にある画面のdevicePixelRatioを基準に行うため、単一モニタ内の選択であれば各モニタごとの拡大率差には対応していますが、範囲が複数モニタにまたがりそれぞれ拡大率が異なる場合は原理的に補正しきれません。
- 付箋ウインドウのタイトルバーの高さ・見た目はOSのテーマに依存します。
- グローバルホットキーは他アプリと競合すると登録に失敗します。失敗しても他の機能・アプリ全体は動作を続けますが、標準エラー出力にメッセージが出ます（通常運用ではコンソールが無いため気付きにくい点に注意してください）。
- **スリープ抑止が防げるのは「無操作によるスリープ・画面オフ」だけです。** スタートメニューから明示的にスリープした場合、ノートPCの蓋を閉じた場合、組織のポリシーで強制されるロック画面は防げません（**入力の有無で決まるアイドル切断・ロックには「🖱 マウスジグラー」を使ってください**）。
- **マウスジグラーは、管理者権限で動いているウィンドウが前面にある間は入力を送れません**（Windows の UIPI が弾きます）。その場合は自動的に停止して通知します。また、会社によっては入力の自動生成そのものが規程で禁じられていることがあります（EDR が検知する可能性もあります）。使う前に自分の環境の決まりを確認してください。
- 通知領域のアイコンは Windows 11 では既定で「隠れているインジケーター」に入ります。見えない場合はオーバーフローから引っ張り出してください。
- **付箋の待機プロセスが常に1つ動きます（専有 27MB 前後）。** 付箋が出るまでの待ちを消すためのもので、タスクマネージャーには本体とは別の `pythonw.exe` として並びます。ウインドウは持たないのでタスクバーには出ません。要らなければ `settings.json` の `capture.prewarm` を `false` にしてください。
- **セカンダリのタスクバーウィジェットは「重ねて隠している」だけで、本物の時計を消しているわけではありません。** セカンダリの時計は XAML（`Windows.UI.Composition.DesktopWindowContentBridge`）で描かれており、子ウィンドウとして掴めないため、位置も大きさも画面のピクセルから実測して合わせるしかありません。Windows の更新でタスクバーの見た目が変わったら、`width` / `height` と Ctrl+左ドラッグで合わせ直してください。
- **セカンダリのタスクバーが複数ある（モニタが3枚以上ある）場合、どれに出るかは選べません。** 最初に見つかったものを基準に置きます。狙いと違う画面に出たら Ctrl+左ドラッグで動かしてください（位置が保存され、以後はそちらが使われます）。
