# tray-tools

画面の一部を付箋のように最前面へ貼り付けておけるキャプチャ機能と、音声出力先の切替を統合した、
Windows用のシステムトレイ常駐アプリです。
1プロセス・1つの `QApplication` で、通知領域に2つのアイコン（音声用／画面用）を表示します。

> **本家「Rapture」との関係について**
>
> 画面の一部を付箋化するという着想は、KENY 氏が公開している Windows 用フリーソフト
> **Rapture**（<https://www.knystudio.net/rapture.html>）から得ています。

> 本家のソースコードや配布物は一切使用しておらず、**本家およびその作者とは何の関係もありません。**
> 本家そのものをお探しの方は上記の公式サイトからどうぞ。
>
> 本リポジトリ内で「Rapture」と書いている箇所は、この付箋キャプチャ機能を指す通称です。

## セットアップ

初めてのPCでは `python setup.py` を実行してください（下の「他のPCで使う」を参照）。セットアップ済みなら、起動は次のとおりです。

```
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe main.py
```

**仮想環境（venv）はこのフォルダの中ではなく `%USERPROFILE%\.venvs\tray-tools` にあります。**
PySide6 だけで5000ファイル以上・約680MBあり、これは `requirements.txt` からいつでも作り直せる
自動生成物です。プロジェクトの中に置くと、クラウド同期の対象フォルダに置いたときに丸ごと同期されて
しまう（同期の詰まりや競合の原因になる）ため、意図的に外へ出しています。リポジトリにも含めません。

グローバルの `python` ではなく必ず上記 venv の `python.exe` を使ってください。

venv を作り直す場合:

```
python -m venv %USERPROFILE%\.venvs\tray-tools
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe -m pip install -r requirements.txt
```

初回起動時、`settings.json` が無ければ既定値で自動生成されます。壊れている場合も既定値にフォールバックして起動します。
既定値の `audio.devices` は空です（デバイスIDはPC固有のため、コードに既定値を持てません）。設定するまで音声アイコンのメニューには「音声デバイスが未設定です」と表示されます。**音声アイコンのメニューの「デバイスを登録/解除…」から、繋がっている機器を選ぶだけで登録できます**（[音声デバイスの登録](#音声デバイスの登録メニューから)）。

## 他のPCで使う

別のPC（仕事用PCなど）へ展開する手順です。**管理者権限は不要です。**

```
git clone <リポジトリのURL> tray-tools
cd tray-tools
python setup.py
```

`setup.py` が行うこと（何度実行しても壊れません）:

1. Python 3.10 以上かを確認
2. `%USERPROFILE%\.venvs\tray-tools` に venv を作成（既にあればそのまま使う）
3. `pip install -r requirements.txt`（失敗した場合はプロキシ指定の方法を案内します）。続けて、背景透過の任意の依存を入れるか聞きます（AI：rembg / onnxruntime は `--with-ai` / `--no-ai`、ベクタ化：vtracer は `--with-vector` / `--no-vector` で確認を省略可）
4. 音声出力デバイスを検出して `settings.json` を用意（下記）
5. `TrayTools.lnk` を作成
6. サインイン時の自動起動を登録するかを `y/n` で確認（既定は「しない」。`--startup` / `--no-startup` で確認を省略可）

#### `settings.json` が既にある場合（手順4）

**既存の値は書き換えません。** そのうえで次の2つを行います。

- **不足している設定項目を足す** … 版が上がって増えた項目（`launcher` / `snippets` など）を書き込みます。動作自体は既定値へのフォールバックで問題ありませんが、それだと設定ファイルを開いても「今どんな項目があるのか」が分かりません。実体を書いて見えるようにします。足した項目は画面に一覧表示されます
- **音声デバイスの構成が変わっていたら確認する** … 今の登録と検出結果を並べて表示し、入れ替えるかを `y/n` で聞きます（既定は「しない」。使う機器だけ絞って登録している場合に、検出した全部で上書きされると設定し直しになるため）。`--redetect-audio` / `--keep-audio` で確認を省略できます

書き換える前に `settings.json.bak_YYYYMMDD_HHMMSS` へ控えを取ります。変更が無いときはファイルを書きません。

セットアップ後、アプリ本体は `setup.py` からは起動しません。`TrayTools.lnk` から起動してください。

セットアップ用スクリプトを PowerShell (`.ps1`) ではなく Python で書いてあるのは意図的です。企業のPCでは実行ポリシーがGPOで固定されていて `.ps1` の実行自体が禁止されていることがあり、`-ExecutionPolicy Bypass` でも上書きできない場合があるためです。ショートカット作成にだけ `powershell -Command` のインライン実行を使っています（実行ポリシーが規制するのはスクリプト「ファイル」の実行なので、この経路なら通る可能性が高い）。

### PCごとに持つもの・共有するもの

| もの | 扱い |
|---|---|
| `settings.json` | **PCごとのローカルファイル。リポジトリには含まれません**（`.gitignore` 済み）。デバイスIDや保存先パスがPC固有のため |
| `*.lnk` | 絶対パスを埋め込むためコミットしません。`setup.py` が各PCで作り直します |
| venv | `%USERPROFILE%\.venvs\tray-tools`。各PCで作り直します |

### 音声デバイスの登録（メニューから）

**音声アイコンを右クリック →「デバイスを登録/解除…」** で、いま繋がっている出力デバイスの一覧が開きます。選んで `Enter` を押すだけで登録され、**`id` と `match_name` は自動で埋まります**。もう一度選べば登録が外れます。新しいPCを立ち上げたときも、`settings.json` を手で書く必要はありません。

```
ヘッドホン (Loop120 by Shokz)                          ［登録1］
1 - LG HDR WFHD (AMD High Definition Audio Device)     ［未登録］
Speakers (Realtek(R) Audio)                            ［未登録］
2 - EX-LDGCQ321HD (AMD High Definition Audio Device)   ［未登録・使用中］
ヘッドホン (Loop120)                                    ［登録2・未接続］
```

| 表示 | 意味 |
|---|---|
| `［登録N］` | 登録済み。**Nがそのまま切り替えの巡回順**（`Ctrl+Alt+H` はこの番号順に回ります） |
| `［未登録］` | このPCに繋がっているが、まだ登録していない |
| `使用中` | いまの既定の出力先 |
| `未接続` | 登録は残っているが、いまは繋がっていない（電源を切ったヘッドホンなど）。**この行も出るので、外すことができます** |
| `ID:…cc20b103cfcf` | **同名のデバイスが複数あるときだけ**付く、エンドポイントIDの末尾。`Digital Output` や `3 - EX-LDGCQ321HD` のような同名は珍しくないため |

- 上の入力欄で**デバイス名の前方一致で絞り込め**ます。`↑↓` で選択、`Enter` で登録⇔解除、`Esc` で閉じる
- 下のプレビューに**エンドポイントIDの全体**・状態・登録位置・アイコン/色が出ます（同名を最後に見分ける手段）
- 1件ごとに窓は開き直します。続けて何台でも登録/解除できます
- **巡回順を変えたいときは、外してから登録し直してください**（登録した順に後ろへ並びます）。`settings.json` の `audio.devices` の並びを直しても同じです
- **ラベル・アイコン・色を手で直していても壊れません。** 登録/解除は `audio.devices` の配列だけを書き戻し、触っていない項目はそのまま残します

登録時に**アイコンの図柄は自動で決まります**。Windows が各エンドポイントに持たせている `FormFactor` を見て、ヘッドホン/ヘッドセットなら `headphone`、モニタ（HDMI/DisplayPort）なら `monitor`、それ以外は `speaker` になります。取れない機器のときだけ名前から推測します。**色は使っていないものが順に振られます**（通知領域のアイコンは色で出力先を見分けるため、同じ色が並ばないようにしています）。どちらも `settings.json` で好きに直せます。

デバイス一覧の取得（全デバイス列挙）は**この窓を開いた時だけ・1回だけ**走ります。1台ごとに全プロパティを読むので重く（このPCでの実測は、有効な出力デバイスに絞って 78ms、絞らないと 312ms）、メニューを開くたびに走らせるとメニューが引っかかるためです。

### 音声デバイスIDについて

`audio.devices[].id` は `{0.0.0.00000000}.{GUID}` 形式のPC固有の値で、**別のPCでは必ず異なります**。上の「デバイスを登録/解除…」か `setup.py` が自動検出して書き込みます。

`setup.py` からまとめて入れ替えることもできます。`python setup.py --redetect-audio` を実行すると検出結果で入れ替わります（ラベル・アイコン・色も自動で振り直します）。CLIで一覧だけ見たい場合は次のとおりです。

```
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe list_devices.py
```

IDが1つも実在しない状態でもアプリは正常に起動します（トレイアイコンは出ます）。その場合はメニューに「音声デバイスが未設定です」と表示され、切り替えを試みると通知で登録を促します。**クラッシュはしません。**

### デバイスIDの自動追従（`match_name`）

**同じ機器でもエンドポイントIDは振り直されることがあります。** USBドングルを挿すポートが変わった、ドライバが更新された、といった日常的なきっかけで起こります（Bluetoothの再ペアリングでも同様）。機器は繋がっていて音も出るのに、`settings.json` のIDだけが実在しなくなり、切り替えが効かなくなります。そのたびに手でIDを直さなくて済むよう、アプリが名前を手がかりに追従します。

- **記録**：IDで解決できている間、そのデバイスの現在の FriendlyName（Windowsが報告する名前）を `audio.devices[].match_name` に自動で保存します。使えているうちに控えておかないと、IDが変わってから名前を調べる術がないためです
- **追従**：設定のIDが実在しないとき、`match_name` と**名前が完全一致する有効（Active）なデバイスがちょうど1台だけ**見つかれば、そのIDを採用して `settings.json` に書き戻し、`〇〇 のIDが変わっていたため追従しました` と通知します
- **追従しない条件**：`match_name` が未記録のとき／一致が**0台**のとき／一致が**2台以上**のとき。部分一致・前方一致は使わず、無効（Active でない）なデバイスも対象外です

一致が複数あるときにあえて何もしないのは安全のためです。`Digital Output` や `3 - EX-LDGCQ321HD` のように**同名のデバイスが複数存在する**のは珍しくなく、曖昧なまま推測すると意図しない出力先に切り替わり、「音が別のスピーカーから出る」という原因の分かりにくい事故になります。この場合は「デバイスを登録/解除…」から登録し直してください（同名の行にはIDの末尾が付き、プレビューにIDの全体が出るので、どちらを選んでいるか確かめられます）。

`match_name` は `label` とは別物です。`label` はメニュー表示用にユーザーが自由に付ける名前で（例：`ヘッドホン (Loop120)`）、Windowsが報告する名前（例：`ヘッドホン (Loop120 by Shokz)`）とは一致しないため、照合には使いません。

なお、IDでの解決に成功している通常時は全デバイスの列挙を行いません（メニューを開くたびのコストを増やさないため）。名前での探索は、IDが実在しなかったときだけ走ります。登録用の一覧も、「デバイスを登録/解除…」を選んだときにだけ列挙します。

### 会社のPCで使う場合の注意（ホットキーとEDR）

**このアプリは `keyboard` ライブラリでグローバルキーフックを使っています。** OS全体のキー入力を監視する仕組みのため、企業のエンドポイント保護（EDR/アンチウイルス）にキーロガーとして検知・ブロックされる可能性があります。これは事実として認識したうえで導入を判断してください。組織のポリシーによっては、導入前に情報システム部門へ確認するのが安全です。

ホットキーが不要なら、`settings.json` の `hotkeys` の各値を**空文字 `""` にすればキーフックの登録自体を行いません**。トレイアイコンのクリックとメニューだけで全機能を使えます。

```json
"hotkeys": {
  "audio_toggle": "",
  "capture_now": "",
  "capture_sequence": "",
  "mic_mute": "",
  "color_picker": "",
  "always_on_top": "",
  "snippet_picker": "",
  "launcher": ""
}
```

```

```

これだけで反映されます（`settings.json` はリポジトリに含まれないので、`git pull` で自分の設定が上書きされることはありません）。`requirements.txt` に依存が増えたときだけ、次を実行してください。

### 起動用ショートカット

- `TrayTools.lnk` … コンソールを出さずに起動する（`pythonw.exe` 経由）。`setup.py` でスタートアップ登録を選んだ場合は、同じものが Windows のスタートアップフォルダにも置かれ、サインイン時に自動起動します
- `TrayTools-debug.bat` … コンソール付きで起動する。うまく起動しないときに、エラー内容を確認するために使う

自動起動をやめたい場合は、スタートアップフォルダ（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`）の `TrayTools.lnk` を削除してください。

## トレイアイコンの操作

通知領域に2つのアイコンが表示されます。

**アイコンを増やさないのは意図的な設計です。** 「状態を持つ機能だけがアイコンの見た目を占有してよい。単発の動作はメニュー項目で足りる」という方針で、機能を増やしてもアイコンは2つに保っています。

### 音声アイコン

見た目が示す状態：**現在の出力先**（図柄と色）＋**マイクがミュート中かどうか**（赤い斜線）。図柄は `headphone`（ヘッドホン／ヘッドセット）・`speaker`（卓上スピーカー／USB DAC など）・`monitor`（HDMI/DisplayPort でモニタから鳴らすもの）の3種類です。

- **左クリック**：次の出力デバイスへトグル切替
- **右クリック**：現在のデバイス表示／切り替え／各デバイスへ直接切替／マイクをミュート／**デバイスを登録/解除…**／設定／終了

| 機能 | ホットキー（既定） |
|---|---|
| 出力デバイスの切替 | `Ctrl+Alt+H` |
| マイクのミュート切替 | `Ctrl+Alt+M` |

**「デバイスを登録/解除…」から、繋がっている機器を選ぶだけで登録できます**（IDは自動で埋まります）。詳細は[音声デバイスの登録](#音声デバイスの登録メニューから)。

出力デバイスもマイクのミュートも他アプリ（Teams等）から変更されうるため、メニューを開くたびに実際の状態を読み直します。ただし**全デバイスの列挙は行いません**（重いため。登録の窓を開いたときだけ走ります）。

### 画面アイコンのメニュー構成

トップは14項目に畳んであります。**よく使うもの（定型文・背景を透過・あっふ・画面ミラー）はトップに残し**、それ以外は性質ごとにサブメニューへ入れました。全部畳むと頻度の高い操作が一段深くなって遅くなり、全部並べるとトップが20項目を超えて目的の行を探せなくなるためです。ホットキーのある項目は畳んでも実害が小さい（そちらから呼べる）という判断も入っています。

```
📷 キャプチャ ▸        今すぐ / 5秒後 / 10秒後
🔧 画面の道具 ▸        カラーピッカー / 画面定規 / 最前面に固定
──────
📋 定型文
🪄 背景を透過…
（アイコン）あっふ…    ※専用アイコン(本家 AfxW 風のドット明朝)
📽 発表者ツール ▸      ローカルの資料 / サイトを取り込む
🖥 画面ミラー ▸        開始 / 静止 / 終了 / ミラー先
🎙 一人会議を開始…
🤖 Copilot ▸          状態監視バー / エージェントループ
──────
⚡ 電源 ▸             スリープ抑止 / スリープ・休止 / マウスジグラー
──────
⚙ 設定 ▸             ウィジェット / 背景色 / スマホ通知 / 各種ファイル
──────
🩺 診断…
🔄 再起動
✖ 終了
```

**メニュー項目の先頭には絵文字を1つ置いています。** 通知領域のメニューは項目が縦に並ぶだけで手掛かりが少なく、目的の行を探すのに毎回文字を読むことになるためです（画面アイコン側だけの扱いで、音声アイコン側のメニューには付けていません）。

範囲選択オーバーレイはドラッグで範囲を指定し、離すと付箋ウインドウが開きます。`Esc` でキャンセルできます。
付箋ウインドウは同時に何枚でも開けます。

**キャプチャを始めた時点で画面は凍結します。** オーバーレイが出ている間に見えているのは、全モニタを1枚に撮った静止画です。範囲を離した瞬間に撮り直すのではなく、その静止画から切り出すので、**選択中に見えていた絵と保存される絵は必ず一致します**（動画やアニメーションが動いていてもズレません）。凍結するのは「今すぐ」でも同じです。

**ドラッグを始める前でも、カーソル位置の座標が常に表示されます**（キャプチャ・画面定規のどちらでも）。始点を決める前に「今どこを指しているか」が分かります。表示される座標は全モニタを合算した仮想デスクトップ基準の**実際の画面座標**です。

**「5秒後 / 10秒後にキャプチャ」は、まずカウントダウンだけが出ます。** カウントダウン中は画面がふだんどおり動くので、その間に撮りたいメニューやツールチップを開いておいてください。時間が来ると画面が凍結し、止まった絵を見ながらゆっくり範囲を選べます。**範囲選択の操作でメニューが閉じてしまっても、凍結済みなので撮れます。** カウントダウン表示自体は凍結画像に写り込みません（撮る直前に閉じ、OSの再描画を待ってから撮ります）。

**通知はWindowsのトーストではなく自前で描いています。** Windows 11 のトースト通知は通知システムを経由するため数秒遅れて出ることがあり、操作し終わった後になって鳴るだけで邪魔になるためです。カーソルのある画面の右下に即座に小さなパネルが出て、約1.6秒でフェードアウトして消えます。クリックは透過し、フォーカスも奪わないので操作の邪魔になりません（連続して出しても積み上がらず、常に最新の1枚だけが残ります）。

**マイクのミュート切替とデバイス切替では、成功時に通知を出しません。** 状態はトレイアイコン（ミュート中は赤い斜線、出力先は図柄と色）が即座に反映するので、そちらが合図として十分で、いちいち通知が出る方が冗長なためです。

**スリープ抑止は時限指定を既定の導線にしています。** 抑止したまま忘れて何日もスリープしなくなるのが一番ありがちな失敗のためです。アプリ終了時には抑止も最前面固定も自動で解除されます。

**画面定規は、ドラッグ中に小さなパネルで「幅 x 高さ／始点／終点／対角線」を表示します。**
離すと、そのままノートや報告に貼れるラベル付きの複数行テキストをクリップボードへコピーします。

```
幅 x 高さ: 1920 x 1080
始点: (100, 200)
終点: (2020, 1280)
対角線: 2202.9 px
```

始点・終点は**実際にドラッグを開始した点と離した点**で、矩形の左上・右下ではありません（右から左へ引けば始点が右になります）。座標は全モニタを合算した仮想デスクトップ基準のグローバル座標のため、プライマリの左にモニタがある構成では負の値になります。通知には `1920 x 1080 / 対角線 2202.9 px をコピーしました` と要約のみ出ます。

**カラーピッカーは、オーバーレイを開いた瞬間の画面を静止画として扱います**（カーソル追従のルーペを出すため、開いた時点で1回だけ画面全体を取得しているため）。動画など変化し続けるものの色を拾いたい場合は、拾いたい瞬間に開いてください。

**アプリ全体の終了は、どちらかのトレイアイコンの右クリックメニュー「終了」から行います。** 付箋ウインドウを全部閉じてもアプリは常駐し続けます。**逆に、アプリを終了・再起動しても開いている付箋は閉じません**（付箋は別プロセスで動いています。後述の「付箋は本体とは別のプロセス」を参照）。

**多重起動はしません。** すでに常駐している状態でショートカットを起動しても、2つ目のプロセスは静かに終了し、常駐中の側が「すでに起動しています」と通知します（スタートアップからの自動起動と手動起動が重なっても、トレイアイコンが2組並んだりホットキーが二重登録されたりしません）。

## スリープ・休止（`keep_awake.py`）

**☕ スリープ抑止** は席を外しても寝ないようにするもの、**😴 スリープ・休止** はその逆で、指定した時間のあとに寝かせるものです。長い処理を回している間だけ起こしておいて、終わったら寝かせる、という使い方ができます。

| | 電力 | 復帰 | 停電・電池切れ |
|---|---|---|---|
| スリープ (S3) | 消費し続ける | 数秒 | **内容が消える** |
| 休止状態 | **ゼロ** | 数十秒 | 平気 |

**予約の時刻になってもすぐには寝ません。** 20秒の猶予を置いて声を掛けます。予約したことを忘れて作業している最中に落ちると、開いているものが道連れになるためです。その間に「予約を取り消す」を押せば止まります。

**休止状態が無効な環境では、押しても何も起きません。** `SetSuspendState` は無効なまま呼ぶとスリープに落ちるか無反応になり、故障に見えます。そこで実行前に `IsPwrHibernateAllowed` で確かめ、使えない場合は理由を通知して何もしません（`powercfg /hibernate on` で有効化できます）。

### 外から操作する

あふｗ連携と同じ名前付きパイプの口を使います。**長い処理を回すスクリプトや AI から、掛け外しできます。**

```
traytools_send.py keep-awake on          抑止する（無期限）
traytools_send.py keep-awake on 90       90分だけ
traytools_send.py keep-awake off         解除する

traytools_send.py sleep                  猶予のあとスリープ
traytools_send.py sleep 1800             30分後にスリープ
traytools_send.py sleep 1800 hibernate   30分後に休止状態
traytools_send.py sleep cancel           予約を取り消す
```

**Claude Code からは MCP サーバー経由でも呼べます**（下の「Claude Code から道具として呼ぶ」）。

想定外の引数が来ても落ちません。外から叩かれる口なので「何もしない」側に倒してあります。

## Claude Code から道具として呼ぶ（`mcp_server.py`）

常駐している tray-tools を、Claude Code の **MCP サーバー**として差し出します。Claude が「そういう道具がある」と知った状態になり、自分で判断して呼べるようになります。

**できることは増えていません。** 名前付きパイプは今でもこのマシン上の何からでも書けます。MCP 化は**既存の口に説明書を付けるだけ**です。増えるのは次の2つ。

- Claude が道具の存在と使い方を知っている（言われなくても適切な場面で使える）
- **道具ごとに承認の粒度を分けられる**（`status` は読むだけ、`sleep_pc` は要確認）

### 登録

`~/.claude/settings.json` の `mcpServers` に足します。**PySide6 を読まないので、起動は実測 0.085 秒**です（Claude Code の起動ごとにこのサーバーが立つため、ここが重いと毎回の待ちになります）。

### 道具の一覧

| 道具 | 引数 | 印 |
|---|---|---|
| `status` | なし | `readOnlyHint` |
| `read_log` | `lines` | `readOnlyHint` |
| `keep_awake` | `state`（必須）, `minutes` | `idempotentHint` |
| `sleep_pc` | `action`（必須）, `seconds` | **`destructiveHint`** |
| `notify` | `message`（必須） | |
| `beep` | `kind` | |
| `pushover` | `message`（必須）, `title`, `priority`, `sound` | `openWorldHint` |
| `capture` | `screen` | |
| `bookmark` | `path` | |

`annotations` はクライアントが承認の重さを決める材料です。読むだけのものに `readOnlyHint` を付けてあるので、都度確認せずに使う設定にしやすくなっています。逆に `sleep_pc` には `destructiveHint` を付けてあります —— **作業中に寝られるのがいちばん困る**ためです。

### 何を載せて、何を載せないか

`main.py` の `_build_command_handlers` と**同じ線引き**です。載せてよいのは「**常駐しているこのプロセスでなければできないこと**」だけ。ファイル操作もアプリ起動も呼ぶ側が直接できるので載せません。口を通る危険だけが増えます。

`capture` がこの線引きの分かりやすい例です。`mss` のインスタンスを都度作ると COM/GC 衝突で落ちるため（2026-08-28 に8回）、**常駐が抱えているものを通すしか安全な手がありません。**

逆に**画像そのものは返しません。** 撮ったファイルのパスを返せば、読む側は普通にファイルを開けばよく、数MBを base64 で流す必要がないためです。

### 実装上の約束

- **MCP の SDK を使いません。** stdio 上の JSON-RPC は数十行で足りるうえ、venv に依存を増やさずに済みます
- **`stdout` には MCP のメッセージ以外を一切書きません。** 診断は `stderr` へ。メッセージは1行1件で、**中に改行を含めません**（`separators=(",", ":")` で潰しています）
- **常駐が起きていなければ、起こしに行かず「起きていない」と返します。** `traytools_send.send()` は未起動なら本体を起動して6秒待ちますが、それはあふｗから呼ぶときの作法です
- **引数の不正はプロトコルのエラーにせず、`isError` を立てた結果として返します。** そのほうが Claude 側が読んで対処できます（プロトコルのエラーは会話に載りません）

## 画面を撮る（外部コマンド）

```

traytools_send.py capture 2      2番目の画面だけ
```

保存先は Rapture と同じ `capture.save_folder` で、応答の2行目に保存したパスが返ります。

## 疑似エージェントループ（`agent_loop.py` / `copilot_loop.py` / `agent_loop_viewer.py`）

Copilot アプリを相手に「プロンプト送信 → 応答受信 → コード実行 → 結果貼り戻し」を自動で回す仕組み。**Ctrl+V や Enter を送らない**（UIA の `ValuePattern.SetValue` と `InvokePattern.Invoke` だけを使う）ので、フォーカスを奪わず、裏で作業しても事故が起きません。

### 3つのモード

| モード | 送信 | 実行 | いつ使うか |
|---|---|---|---|
| **通常 dry-run** | tray-tools がお題を送信 | 実行しない | 初めての題材で、Copilot がどんなコードを書くか目視 |
| **通常 auto**（`--auto`） | tray-tools がお題を送信 | 実行して結果を貼り戻す | 慣れた題材、Claude Code や PowerShell から起動 |
| **監視モード**（`--watch`） | **人が Copilot に手で投稿** | 実行して結果を貼り戻す | 業務PC など Claude Code の無い環境。トレイメニューから開始できる |

### 使い方（コマンド）

```
traytools_send.py agent-loop start C:\path\to\お題.txt         # 通常 dry-run
traytools_send.py agent-loop start C:\path\to\お題.txt --auto   # 通常 auto
traytools_send.py agent-loop start --watch --auto               # 監視モード
traytools_send.py agent-loop status                             # いま回っているか
traytools_send.py agent-loop cancel                             # 次の周の頭で止まる
```

Claude Code から MCP 経由でも呼べます（ツール名 `agent_loop`、`action=start|status|cancel`、`watch=true` オプション）。

### 使い方（トレイメニュー・業務PC向け）

トレイの **🤖 エージェントループ ▸ 監視モード開始** を押します。ログ窓が開き、その後 Copilot アプリの入力欄に人が手でお題を貼って Enter するだけ。応答が始まると tray-tools が引き取ってループを回します。

**トレイアイコンの色で状態が見えます**（既存の Rapture アイコンにリングを重ねる形。「アイコン2つ固定」の方針を維持）：

| 色 | 状態 |
|---|---|
| なし（通常） | エージェントループ停止中 |
| 🟠 オレンジ | スリープ抑止中 |
| 🟢 緑 | 監視モード待機中（Copilot の応答を待っている） |
| 🔵 青 | 応答受信中・PowerShell 実行中 |
| 🔴 赤 | 危険パターン検出などで停止（要確認） |

### ログ窓（`agent_loop_viewer.py`）

監視モード開始と同時に開く常時表示の窓です。周ごとに次を色分けで流します：

- 送信するプロンプトの先頭（監視モードなら「送信スキップ」と表示）
- 応答受信の経過秒と先頭 800 文字
- 抽出されたコード全文
- 実行結果（exit code、stdout、stderr）
- 停止理由

**PowerShell 窓ではなく tray-tools 自身の窓なので**、監視モード終了で自動的に閉じられ、周が増えても窓は1枚に集約され、スクロールと文字選択もそのまま使えます。トレイの **🤖 ▸ 📜 ログ窓を前面に** で後から呼び戻せます。

**タスクバーのアイコンは 🤖**（tray-tools 本体の Rapture ドット絵とは別）で、この窓が何者か遠目でも分かります。窓上部の **「📌 最前面固定」** チェックで、他アプリの上に貼り付けたまま観察できます（設定は `settings.json` の `agent_loop_viewer.always_on_top` に覚えます）。

### Copilot 入力待ち通知（`copilot_watchdog.py`）

**業務PC 想定の別機能。Pushover を使えない環境で、Copilot に相談した後で返事を返し忘れて放置しているのを、遠目でも気づけるようにするための画面通知です。**

- **有効化**：トレイ **🤖 ▸ 🔔 Copilot 入力待ちを画面通知（30秒〜）** をチェック
- **判定**：Copilot が idle（応答済み・入力欄が空）状態が閾値秒（既定30秒）続いたら1回だけ画面中央に半透明の赤い大きな窓を出す
- **抑止**：agent-loop が動いている間は完全に休む（応答→次周送信の間の idle を拾わない）／人が入力欄に何か書き始めたらリセット／一度通知したら次の busy を経由するまで再通知しない
- **設定**：`settings.json` の `copilot_watchdog.enabled` と `copilot_watchdog.threshold_seconds`

### 安全機構

### 安全機構

- **既定は dry-run**（`--auto` を明示するまで実行しない）。Copilot が返したコードは `copilot_loop.log` に残るので、目視で確かめてから `--auto` を付ける
- **危険パターン検知**（`Remove-Item` / `Stop-Process` / `Invoke-WebRequest` / `git push` / `-Force` など）にヒットしたら実行せず停止。Copilot に理由を返して人の判断を待つ
- **3層のタイムアウト**: PowerShell 1回（既定60秒）／応答待ち（180秒）／ループ全体（30分）
- **キャンセルはファイル方式**（`.copilot_loop_cancel`）。実行スレッドが PowerShell で詰まっていても、次の周の頭で拾って止まる

### プロンプトの作り方

1周目のプロンプトには次を入れます（`snippets/エージェントループ開始.txt` を参考に）。

- **スニペットを `#start <数字ID>` 〜 `#end <同じID>` で囲ませる。** 言語フェンス検出より確実で、実行漏れ・重複実行の検知にもなる
- **「エラーを貼ったら、原因の一言 + 修正後のスニペット全体だけ返して」** と縛る。回答が長引くと1周が10分単位で伸びる
- **完了語**（例 `<DONE>`）を仕込むと `--finish-word=<DONE>` で正常終了できる

### 実測

3案を比べた結果はコードのコメントに残していますが、実運用で効いた設計判断だけ抜粋:

- **応答テキストは `FindAll` の並びのまま `Text` 要素を連結する**（座標順に並べる／`TextPattern.DocumentRange` はどちらも壊れる）
- **`wait_until_idle` は「busy を見てから idle」ではなく「idle が settle_seconds 連続」で判定**（busy を見逃す事故を避ける）
- **応答は送信直前の全文長を控えて、そこより後ろだけ扱う**（会話が長くなると `rsplit` は27文字などの短片を返す）

### 業務PC（M365 Copilot）への移植

`copilot_loop.BUILTIN_PROFILES` にアプリごとのプロファイルが並んでいて、実行時に「動いている窓に合うもの」が選ばれます。手元PCの Copilot（`mscopilot.exe`）と業務PCの M365 Copilot（`M365Copilot.exe`）の両方が入っているので、同じコードがどちらでも動きます。

PCごとに値が違うときは、コードを触らず `settings.json` の `copilot_profiles` で上書きできます（同じ `name` なら設定側が勝ちます）。

調べる候補は同梱の `tools/uia_probe.py` が出してくれます。詳しくは [`tools/README.md`](tools/README.md)。

**Claude Code の無い業務PCでは、監視モード（`--watch` またはトレイメニュー）が本命の使い方**です。人が M365 Copilot にお題を貼って Enter → トレイの「監視モード開始」を押す → 以降は自動、という流れになります。

### ログ

`copilot_loop.log`（JSON Lines）に、1周ごとの送信・応答・スニペット・実行結果・停止理由を全部残します。個人の使用履歴なので `.gitignore` に入れて追跡対象外にしています。

### メニューに出る条件

**このメニューは、トークンを登録済みのPCにだけ出ます。** 複数のPCで同じコードを動かしていると、業務用の端末に個人の通知先の入口が並ぶことになり、使い道がないためです。

まだ登録していないPCで使い始めたいときは、`settings.json` の `tools.pushover` を `true` にして再起動してください。判定に失敗した場合は「出さない」側に倒します。

**出ていないPCでも、外からのコマンド（`traytools_send.py pushover`）は使えます。** 隠しているのはメニューだけです。

### スマホ通知のテスト

トレイメニューの **📱 スマホ通知（Pushover）→ 📤 テスト送信** で1通送れます。届くかどうかをその場で確かめられます。

送信は別スレッドで行います。ネットワークは数秒かかりうるので、メインスレッドで待つとトレイも付箋もホットキーも固まるためです。結果の通知だけはシグナル経由でメインスレッドへ戻します（トーストは Qt の窓なので、ワーカーから直に作ると壊れます）。

### 操作の記録（`action.log`）

電源まわりの操作は `action.log` に1行ずつ残ります。**誰が操作したか**（`menu` / `external`）も一緒に残るので、「気づいたら寝ていた」ときに、自分の予約なのか外からの指示なのかが分かります。

```
2026-08-29 01:39:06  スリープ 予約  3分後  (external)
2026-08-29 01:41:20  スリープ 予約を取り消し  (menu)
2026-08-29 09:15:33  スリープ抑止 解除  (external)
```

外から送る口は一方向で結果が返らないため、**送った側はこれを見て確かめます**。`error.log`（例外）や `crash.log`（プロセス即死）と違い、こちらは正常に動いたことを残す側です。512KB を超えたら古いほうから捨てます。

## Teams の一人会議を立ち上げる（`teams_meeting.py`）

**ホットキー `Ctrl+Alt+N`（またはトレイの 🎙 一人会議を開始…）1つで、Teams の「今すぐ会議 → 会議名の入力 → 開始 → 参加 → 文字起こしの開始」まで進めます。**

一人会議のトランスクリプトを Copilot に渡して資料を作るとき、同じ会議で続けて話すとトランスクリプトの生成が遅れたり、Copilot が一つ前の会議をまとめたりします。毎回新しい会議を立てるための道具です。会議名に日時（とテーマ）を入れてユニークにしてあるので、Copilot には「『一人会議 10/08 14:30 設計レビュー』の内容をまとめて」と**名前で**頼めます。

### 流れ

1. 押すと「テーマ」を聞かれます（空でも可）。会議名は `一人会議 10/08 14:30 <テーマ>` になります
2. 「数秒間キー入力を控えてください」と出ます。**Teams の今すぐ会議のダイアログは開くとフォーカスを取る**ので、そのあいだ別の窓で打った文字が会議名に混ざることがあります（実際に起きました）。会議名は入れたあと読み戻し、違っていれば入れ直してから間を置かずに「会議を開始」を押します
3. あとは自動で進み、終わるとトーストで知らせます
   - 成功：会議名と「文字起こしを開始しました」または「見つからなかったので手で開始してください」
   - 失敗：止まった手順の名前。**そこから先は Teams で手で続けてください**

**キー送信・マウス操作・前面化（`SetForegroundWindow`）は一切しません。** UIA で要素を名指しして押すだけです（Teams の画面が前に出るのは Teams 自身の動きです）。

| 手順（key） | すること | 見つからないとき |
|---|---|---|
| `teams` | Teams の窓を探す。無ければ `ms-teams:` で起動して最大30秒待つ | 止まる |
| `open_chat` | 「今すぐ会議」が見えないときだけ、左端の「チャット」を押して画面を戻す | 飛ばす |
| `meet_now` | 「今すぐ会議」を押す（文字の無いビデオカメラのアイコン） | 止まる |
| `title` | 会議名を入れる（`meeting-title-input` に `SetValue`） | 止まる |
| `start` | 「会議を開始」を押す | 止まる |
| `prejoin` | 参加前の画面（新しい窓）が出るのを待つ | 止まる |
| `camera` / `mic` | ボタン名から今の状態を読み、設定と違えば押す（既定: カメラ オフ・マイク オン） | 飛ばす |
| `join` | 「今すぐ参加」を押す | 止まる |
| `joined` | 「退出」ボタンが出たことで参加を確かめる | 止まる |
| `close_invite` | 招待のダイアログを閉じる（**ダイアログの中の**「閉じる」だけを押す） | 飛ばす |
| `transcript` | その他 → 録画と文字起こし → 文字起こしの開始 | 飛ばす（無料版には無い） |

各手順の結果は `action.log` に `一人会議 …` の行で残ります（止まったときに、どこまで進んだかを後から辿れます）。

### 実装で気を付けた点

- **UIA は常駐の中で使いません。** 常駐は音声切替（pycaw）を持っていて、UIA と同居させると GC のたびに即死します（`copilot_watchdog.py` 冒頭の実測値。スレッドを分けても助からない）。実処理は `teams_meeting.py` を子プロセスとして起こして回し、進み具合を1行1件の JSON で受け取ります（`agent_loop.spawn` と同じ形）
- **「閉じる」はダイアログの中だけで探します。** 窓のタイトルバーにも同じ名前の「閉じる」が居るので、窓全体から探すと会議の窓そのものを閉じかねません。ダイアログが見つからなければ「閉じる」も探しません
- **会議の窓**は「会議名をタイトルに含む窓」と「会議を開始した後に新しく出た窓」で選びます。前の会議の窓が残っていても、そちらのボタンは押しません
- **上部の「録画」ボタンは既定の経路に入れていません。** 版によっては押した瞬間に録画が始まり、取り消しが利かないためです
- 実行中にもう一度押すと「実行中です」と出して無視します。立ち上げの最中は外からの再起動も断ります

### 業務PCで合わせる

業務版は文字起こしの場所やボタン名が違うかもしれません。**コードを触らず、`settings.json` の `teams_meeting.steps` で手順のキー単位に上書き・追加できます**（`copilot_profiles` と同じ考え方）。

```json
"teams_meeting": {
  "steps": [
    { "key": "meet_now", "timeout": 60 },
    { "key": "transcript", "routes": [[
        { "find": { "automation_id": ["callingButtons-showMoreBtn"] }, "action": "expand" },
        { "find": { "name": ["録画と文字起こし"] }, "action": "expand" },
        { "find": { "name": ["文字起こしの開始"] }, "action": "invoke" }
    ]] },
    { "key": "confirm_language", "after": "transcript", "action": "invoke",
      "window": "meeting", "find": { "name": ["確認"] }, "timeout": 5, "optional": true }
  ]
}
```

- 既定と同じ `key` は**書いた項目だけ**差し替わります（`find` を書けば `find` が丸ごと入れ替わる）。新しい `key` は `"after"` / `"before"` で位置を決めて足せます。`"disabled": true` で飛ばせます
- `find` には `automation_id` / `name`（完全一致）/ `name_prefix`（前方一致）/ `control_type` / `within`（この要素の中だけを探す）を書けます。どれもリストで、先頭ほど優先です
- 合わせた結果は `python teams_meeting.py --list` で、いまの Teams で見えるかは `python teams_meeting.py --check` で確かめられます（`--check` は**読むだけ**で、押しも起動もしません）

**調べる候補は `tools/uia_probe.py --teams` が出します。** Teams を開いた状態で走らせ、見張っているあいだに手で「今すぐ会議 → 開始 → 参加 → 文字起こしの開始」まで進めると、新しく出たボタン・メニュー・ダイアログを段階（メイン／参加前／会議中）つきで記録し、最後に「ここから下だけ読み上げれば足ります」のまとめと、`teams_meeting.steps` に貼れる JSON の断片を出します。

```
python tools\uia_probe.py --teams --watch 300
```

## マウスジグラー（`mouse_jiggler.py`）

### なぜスリープ抑止とは別に必要なのか

**スリープ抑止（☕）ではリモートデスクトップの切断を防げません。** あちらは `SetThreadExecutionState` で OS に「スリープするな・画面を消すな」と申告するだけの機能で、電源まわりにしか効きません。

一方、**リモートデスクトップのアイドル切断やロック画面は「入力があったかどうか」を見ています。** 電源の状態とは無関係なので、スリープ抑止をいくら効かせていても、キーもマウスも触らないまま放っておけば時間が来て切れます（会社の環境ではポリシーで 10〜15 分に設定されていることが多く、こちらは設定で伸ばせません）。

そこで、**入力そのものを起こす**のがこの機能です。カーソルを相対で **+1px 動かし、すぐ -1px 戻す**入力を 1 組送ります。差し引きゼロなのでカーソルは実質その場に留まりますが、OS から見れば確かに入力があったことになり、アイドルのカウントが 0 に戻ります。

### 無操作のときだけ動きます

**あなたが操作している最中は何もしません。** `GetLastInputInfo` で最後の入力からの経過を測り、**30秒以上**（`screen.jiggler_idle_seconds`）無操作のときだけ入力を送ります。操作中に割り込んでカーソルが跳ねると、ドラッグ中や細かい位置合わせ中に邪魔になるだけだからです。

送る間隔は **60秒**（`screen.jiggler_interval_seconds`）です。アイドルタイムアウトが通常 10〜15 分であることに対して十分な余裕があり、かつ普段の操作をまったく妨げない頻度として選んでいます。

### 使い方

画面アイコンの右クリックメニュー **「🖱 マウスジグラー」** から、`30分` / `2時間` / `無期限` / `解除` を選びます。**スリープ抑止とまったく同じ操作感で、すぐ下に並べてあります**（狙いが近いので、探すときに同じ場所を見れば済むようにしています）。

- 時限を選ぶと、**時間が来たときに自動で解除されます**（つけっぱなしを防ぐため、時限指定を既定の導線にしているのもスリープ抑止と同じです）
- 有効中はサブメニューの見出しが `🖱 マウスジグラー（残り25分）` のように**残り時間**を表示します
- アプリを終了すると自動的に止まります

**トレイアイコンの見た目は変わりません。** アイコン全周のリングはスリープ抑止が使っており、実質16px相当のアイコンに2つ目の目印を入れても潰れて読めないためです。動作中かどうかは**アイコンのツールチップ**（`Rapture（マウスジグラー動作中）`）とメニューの見出しで確認してください。

### 送れなかった場合

入力の送信（`SendInput`）は、**管理者権限で動いているウィンドウが前面にある間は Windows に弾かれます**（UIPI）。この場合はそのまま回しても毎回失敗するだけなので、**自動的に停止して 1 度だけ通知します**（`入力を送れないため停止しました`）。前面のウィンドウを切り替えてから、もう一度メニューで有効にしてください。

なお、座標を直接書き換える `SetCursorPos` は「入力」として記録されない場合があり、目的を達しません。旧 API の `mouse_event` も非推奨のため、`SendInput` を使っています。

## セカンダリのタスクバーウィジェット（`taskbar_widget.py`）

**Windows は通知領域（トレイ）をプライマリのタスクバーにしか出しません。** ノートPCの画面をプライマリ、正面の拡張ディスプレイをセカンダリにしている構成（拡張側をプライマリにすると別の不都合がある、という事情はよくあります）では、tray-tools を使うたびに視線と手が「正面ではない方の画面」へ行くことになります。セカンダリのタスクバーには `TrayNotifyWnd`（通知領域）そのものが存在しないため、設定で移せるものでもありません。

そこで、**セカンダリのタスクバーにトレイの代わりを自分で置く**のがこの機能です。

**普段はセカンダリの時計に重なって、時計のふりをしています。** マウスを乗せている間だけ、時計が消えて **Rapture と音声の2つのアイコンに入れ替わります**（隣に生えるのではありません）。タスクバーの上に自前のものが常時2つ増えて見えるのが邪魔なためで、狙いはあくまで「トレイの代わりを正面の画面に置くこと」です。

**既定では無効です。** セカンダリのタスクバーが無いPCで勝手に出さないためで、画面アイコンの右クリックメニュー「🖥 タスクバーウィジェット」で表示/非表示を切り替えます（切り替えると `settings.json` にも保存され、次回起動時もその状態で立ち上がります）。

### 操作

| 場所 | 操作 | 動作 |
|---|---|---|
| 左半分（Rapture アイコン） | 中クリック | 即キャプチャ（通知領域の画面アイコンと同じ） |
| 左半分（Rapture アイコン） | 右クリック | 画面アイコンのメニューをその場に出す |
| 右半分（音声アイコン） | 左クリック | 出力デバイスを切り替え |
| 右半分（音声アイコン） | 右クリック | 音声アイコンのメニューをその場に出す |
| 時計部分（アイコン非表示時） | 右クリック | 画面アイコンのメニュー |
| 全体 | **Ctrl+左ドラッグ** | 位置を微調整する（離した時点で `settings.json` に保存） |

**当たり判定は左右half分けです。** 59x31 の中に20px級の絵が2つ並ぶだけなので、絵の矩形そのものを判定にすると周りが死に領域になり「押したのに何も起きない」が頻発するためです。

**メニューは通知領域と同じものをそのまま出しています**（別に組み立てていません）。別々に作ると、項目やホットキー表記が片方だけ古くなるためです。

**移動が Ctrl+左ドラッグなのは、素の左ドラッグを音声の切替（クリック）判定に使っているからです**（付箋のペンが Ctrl+左ドラッグなのと同じ理由）。

### どこに出るか

**ディスプレイ1枚につき1つ出します。** 数えるのは「タスクバーの数」ではなく**画面の数**です。Windows の「タスクバーをすべてのディスプレイに表示する」がオフの環境ではセカンダリに `Shell_SecondaryTrayWnd` が存在せず、タスクバーを数えると2番目以降が1つも出ないためです（実際にそう報告されました）。

`all_displays` を `false` にするとプライマリの画面だけ外します（そちらには本物の通知領域があるため）。

### 位置とサイズ

**位置はディスプレイごとに独立して持ちます。** `settings.json` の `taskbar_widget.positions` が「画面のキー → `{"right": …, "top": …}`」の辞書です。値は絶対座標ではなく、**その画面のタスクバーの右端・上端からの距離**です（解像度や拡大率が変わっても右下との位置関係が保たれるため）。

**画面のキーはモニタ自身が持つ情報（EDID）から作ります。** `QScreen.name()` は Windows ではモニタの型番を返すので、これにシリアルを繋げて `EX-LDGCQ321HD#951` のようにします。接続順で決まる名前を使わないのは、モニタを繋ぎ替えても切替器で他のPCへ渡して戻しても**同じ名札が付く**ようにするためです。同じ型番でシリアルも読めない2台が並んだときだけ、画面の左上座標を混ぜて分けます（常に座標を混ぜると、モニタを並べ替えるたびに位置を忘れてしまうため）。

**設定にその画面のキーが無ければ、既定の余白（右端から 19px・上端から 10px）で自動配置します。** この値は、画面のピクセルから Windows 11 の時計の描画範囲を割り出したうえで、実機2枚で目視調整した結果に寄せたものです（濃淡から測る方法は、文字のアンチエイリアスの分だけ内側に見積もります）。**別のPCへ `settings.json` を持って行っても壊れません**（知らないモニタは既定位置に落ちるだけです）。

**Ctrl+左ドラッグで動くのは、動かしたウィジェット1つだけです。** 保存されるのもその画面の分だけで、他の画面のウィジェットは1pxも動きません。以前は余白1組を全画面で共有していたため、1つ動かすと全部そろって動き、さらにドラッグ中に別の画面のタスクバーへ入った瞬間に基準が乗り換わって**別の画面へワープ**していました。**基準にする矩形は、そのウィジェットが生成されたときのもので固定です**（途中で乗り換えません）。

**置ける場所に制限はありません。** タスクバーの外でも画面の中央でも、置いたまま保存されます。作業領域（`availableGeometry`）へクランプしないのは、この窓の居場所であるタスクバーの上がそもそも作業領域から除外されているためで、クランプすると必ずタスクバーの外へ弾き出されてしまいます。タスクバーの中へ引き戻す補正も入れていません（入れると「ある高さより下には置けない」ことになります。実際そうなっていました）。

唯一の歯止めは、**保存済みの位置が仮想デスクトップとまったく重ならなくなったとき**（モニタを外した等）だけで、そのときは既定位置に出し直します。二度と掴めない場所に出ると `settings.json` を手で直すしかなくなるためで、**1pxでも重なっていれば手を出しません**。

**タスクバーが見つからない画面では、その画面の下端に「タスクバーがあるとすればここ」という帯を仮定し、そこを基準にします。** 縦位置の基準になるものが他に無く、かつタスクバーは必ず画面の下端に接しているので、下端から逆算すれば既定の余白（上端から 6px 下）がそのまま通用します。帯の高さは**実在するタスクバー（たいていはプライマリ）のものを借ります**（Windows は全ディスプレイで同じ高さのタスクバーを出すため）。1つも見つからないときだけ、Windows 11 の既定値である 48px を使います。

### 背景色

**タスクバーの背景色は決め打ちにできません。** 透明効果が有効だと壁紙が透けるため、環境と壁紙で色が変わるからです（実測環境では `#DDF2B9` という緑がかった色でした）。そのため、**表示する直前に自分が乗る位置の画面を撮り、いちばん多い色（最頻色）で塗ります**。平均ではなく最頻色にしているのは、時計の文字が混ざった平均だと地の色からずれるためです。

文字色は背景の明るさ（BT.601 の輝度）から自動で決めます。上の実測値のような明るい背景では黒、暗い背景では白になります。

**壁紙を変えたら、メニューの「🎨 背景色を取り直す」で測り直してください**（ウィジェットが表示されているときだけ選べます）。測るときは自分をいったん隠し、OSが下を描き直すのを待ってから撮ります（隠した直後に撮ると自分の色をもう一度測ってしまうためです）。

**測り直した色は `settings.json` に書き戻しません。** `background_color` を `null` のままにしておけば起動のたびに実測されるので、壁紙を変えても放っておけば次回から合います。書き込んでしまうと以後その色に固定され、壁紙を変えるたびに手で取り直す羽目になるためです。

色を固定したい場合は `settings.json` の `background_color` / `text_color` に `#rrggbb` を書いてください。書いてあれば自動判定より優先されます。

### 最前面の維持

**タスクバーは常に最前面なので、その上に居続けるには押し上げ続けるしかありません。** 500ms ごとに `SetWindowPos(HWND_TOPMOST, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)` を呼んでいます。

**`SWP_NOACTIVATE` は必須です。** 付け忘れると 0.5 秒ごとにフォーカスを奪い、入力中の文字が飛びます。ウィンドウ自体にも `Qt.WindowDoesNotAcceptFocus` を付けてあるので、クリックしても作業中のウィンドウからフォーカスは移りません。

**非表示のときはタイマーを止めます**（時計の更新も、最前面への押し上げも）。他のウィンドウのZオーダーを触る操作を、見えていない間まで続ける理由が無いためです。

**全画面のアプリが前面に来たら、Zオーダーの後ろへ回ります**（`HWND_BOTTOM`。`hide()` はしません — 隠すと `hideEvent` でこのタイマーごと止まり、全画面が終わったことに気づけなくなります）。判定は `GetForegroundWindow` の矩形が自分の画面を丸ごと覆っているか。**自分の画面だけを見ます**（2枚目で動画を全画面にしているときに、1枚目のウィジェットまで引っ込む必要はありません）。

**[画面ミラー](#画面ミラーscreen_mirrorpy)のミラー窓だけは、この判定では捕まえられません。** あれは発表の邪魔をしないよう `WS_EX_NOACTIVATE`（`Qt.WindowDoesNotAcceptFocus`）＋ `WA_ShowWithoutActivating` で作ってあり、**決して前面にならない**窓だからです。前面のままなのは発表者が操作している手元のアプリで、その矩形はミラー先のモニタを覆いません。そのためウィジェットは 500ms ごとに押し上げ続け、同じく 500ms ごとに最前面を主張するミラー窓と**奪い合って、共有側のモニタでチカチカしていました**。今はミラー側から「この画面を覆っている」と名指しで教えてもらい（`MirrorController.attach_screen_cover` → `TaskbarWidget.set_app_covered`）、**ミラー先の1枚だけ**が引っ込みます。ミラーを終えれば元に戻ります。

### 時計の表示

Windows 11 のタスクバー時計に合わせて2行（上に時刻、下に日付）です。書式は `settings.json` の `clock_format_top` / `clock_format_bottom` で変えられます（`strftime` の書式）。

**先頭ゼロを落とすのは Windows では `%#H` です**（`%-H` は Linux 系のもので、Windows では例外になります）。書式を書き損じても時計が消えないよう、失敗したら既定の書式に落として標準エラーに1回だけ警告を出します。

`%a`（曜日）などを日本語で出せるよう、初回描画時に `locale.setlocale(locale.LC_TIME, "")` を試みます（失敗しても英語表記になるだけで、表示は続きます）。

**分単位の表示でも毎秒描き直しています。** 秒がずれた時計は見た目ですぐ分かって気持ち悪く、59x31 の再描画1回の負荷は無視できるためです。

### この機能が Feature ではない理由

`taskbar_widget.TaskbarWidget` はトレイアイコンを持たないので Feature ではありません（[機能の追加方法](#機能の追加方法)の方針どおり、アイコンは2つのままです）。生成と参照の保持は `ScreenFeature` が行い、音声側の参照（アイコンの絵・デバイス切替・メニュー）は Feature が全部そろってから `main._wire_taskbar_widget()` が渡します。

音声アイコンの絵は `AudioFeature.current_icon_pixmap()` から受け取り、こちらでは描き直しません。「トレイの代わり」である以上、色も形も本物と食い違ってはいけないためです。デバイスは他アプリ（Teams等）からも変えられるので、**マウスを乗せた瞬間だけ**状態を読み直します（描画のたびに読み直すと COM 越しの問い合わせがホバー中ずっと走ります）。

## 定型文

`snippets` フォルダに置いた `*.txt` / `*.md` を、絞り込んで選んでクリップボードへコピーします。`Ctrl+Alt+V`（既定）またはメニューから開きます。

**専用の編集UIはありません。ファイル名（拡張子を除く）がそのまま表示名です。** テキストエディタで足す・消す・リネームするだけで増減できます（フォルダは初回起動時に自動で作られます）。BOM付きUTF-8でも読めます。読めないファイルがあっても、そのファイルだけを飛ばして残りは表示します（理由は標準エラーに出ます）。

ウインドウの操作は次のとおりです。

| キー | 動作 |
|---|---|
| 文字入力 | **前方一致（大文字小文字を無視）**で絞り込む |
| `↑` `↓` | 選択を動かす |
| `Enter` | 変数を展開してクリップボードへコピー |
| `Ctrl+N` | 新規作成。名前を尋ねて `snippets\<名前>.txt` を**空で作り**、関連付けアプリで開く |
| `Ctrl+E` | 選択中のテンプレートを関連付けアプリで開く |
| `Ctrl+O` | `snippets` フォルダをエクスプローラで開く |
| `Esc` | 閉じる |

**絞り込みは候補そのものを減らします**（見えているものが選べるものと一致していないと、`Enter` の行き先が分からなくなるため）。

**`Ctrl+N` / `Ctrl+E` / `Ctrl+O` はファイルを開いた後、ピッカーを閉じます。** 外部エディタで直した内容を反映するには開き直すしかなく、開いたままにすると古い一覧が画面に残って中身と食い違うためです。`Ctrl+N` で同じ名前がすでにある場合は、**作り直さずにそのファイルを開くだけ**にします（打ち間違いひとつで書き溜めたテンプレートを消さないため）。テンプレートが1件も無いときはピッカー自体が開かないので、その場合はトレイメニューの「📂 定型文フォルダを開く」から辿ってください。

### プレビュー

一覧の下に、**選択中のテンプレートが実際にコピーされる姿**が出ます。`{clipboard}` や `{date}` は**展開した後の値**で表示されるので、「何がコピーされるか」を押す前に確かめられます。

**`{input}` だけは尋ねずに `【ラベル】` の形で表示します。** プレビューは選択が動くたびに作り直されるので、ここで入力ダイアログを出すと一覧を眺めることすらできなくなるためです（`snippets.expand_variables(本文, preview=True)` がこのモードです。実際にコピーするときの挙動は今までどおりで、`{input}` はちゃんと尋ねます）。

ウインドウの下端には変数の早見表とキー操作を小さく常時表示しています。

**プレビュー欄は折り返します。高さは 300px です。** もとは 150px・折り返し無しでしたが、それだと手元の 13 行のテンプレートで**縦に 6 行ぶん、横に 325px はみ出して見えていませんでした**。

折り返さずにいたのは「テンプレートは行単位で書かれているので、折り返すと実際にコピーされる形と見た目がずれる」ためでしたが、**見えない正確さより見える近似**を採りました。1行がどこで終わるかを字面で確かめたいときは `Ctrl+E` でファイルを開いてください。

**中身に合わせて伸縮はさせません。** `↑` `↓` を動かすたびに窓の高さと位置が変わると目が落ち着かないためです（項目数で一覧の高さを決めるのと同じ理由）。高さが合わないときは `settings.json` の `snippets.preview_height` で変えられます（80〜600px に丸めます）。

### なぜ定型文には別窓を出さないのか

書式落とし（`Ctrl+Alt+V` の先頭）は別窓を開きますが、**定型文は開きません。** 別窓が要るのは次の3つが揃うときだけです。

| 別窓が要る条件 | 書式落とし | 定型文 |
|---|---|---|
| 2つの状態を**見比べる** | 元のまま ↔ 落とした結果 | 比べる相手がいない |
| 排他の選択肢で**中身が変わる** | 3段階 | 選んだものがそのまま出るだけ |
| 押すと**元に戻せない**副作用 | コピー元の書式が消える | コピーするだけ |

定型文はどれにも当てはまらず、プレビューは比較ではなく確認の一瞥です。しかも**絞り込みながら見る**ので、窓を挟むと打鍵しながら中身を見る流れが切れます。共通していたのは「プレビュー欄が小さくて切れる」という症状だけで、その原因は別窓の有無ではなく欄そのものの作りでした。

### 並び順（最近使った順）

**コピーしたテンプレートが次から一覧の先頭に来ます。** 履歴は `settings.json` の `snippets.recent` に表示名のリストとして貯まり（新しいものが先頭・上限20件）、履歴に無いものはファイル名順で後ろに続きます。

保存はメモリ上の設定を丸ごと書き出すのではなく、`settings.json` を読み直して `snippets.recent` だけを差し替えます（丸ごと書くと未設定の既定値まで焼き込まれてファイルの姿が変わるためで、`launcher.bookmarks` の登録と同じ作法です）。

### 変数

本文には次の変数を書けます。

| 記法 | 展開されるもの |
|---|---|
| `{clipboard}` | 現在のクリップボードの文字列 |
| `{date}` | 今日の日付（`2026/08/22`） |
| `{date:書式}` | 書式指定の日付（`{date:%m月%d日(%a)}` → `08月22日(土)`）。`strftime` の書式 |
| `{time}` | 現在時刻（`14:30`） |
| `{datetime}` | 日時（`2026/08/22 14:30`） |
| `{input}` | その場で入力を求める（複数行可） |
| `{input:ラベル}` | ラベル付きで入力を求める。**ラベルはダイアログのタイトルにも出ます**（続けて複数聞かれたときに、いま何を聞かれているのか分かるように） |

**同じ `{input:ラベル}` が複数回出てきても、尋ねるのは1回だけです**（同じ内容を2回打たされないため）。入力をキャンセルすると、そのテンプレートは**コピーせずに**閉じます（中途半端に展開された文字列をクリップボードへ載せないため）。

**上の表に無い `{なにか}` はそのまま残ります。** テンプレートにコード片や JSON が混じっていても壊れません（`str.format()` を使わず、既知の変数名だけを正規表現で拾っているためです）。

## クリップボードの書式を落とす（`clipboard_format.py` / `clipboard_preview.py`）

**入口は `Ctrl+Alt+V` の一覧の先頭。選ぶとプレビュー窓が開き、段階を選ぶのも実際に載せるのもその窓で行います。**

M365 Copilot の出力を PowerPoint に貼ると改行が消えます。**改行コードの問題ではありません。** コピー元はクリップボードに2つの形を載せています。

```
CF_UNICODETEXT : iPhoneと簡易的にデータの
HTML Format    : <html><body><!--StartFragment--><p data-pm-slice="1 1 []">iPhoneと簡易的にデータの</p><!--EndFragment--></body></html>
```

**PowerPoint はテキストより `HTML Format` を優先します。** Copilot は `<p>` で段落を組んでおり、その段落解釈で改行が潰れます。そこで HTML を捨てる／削って、貼り先のテーマに従わせます。

| 段階 | 残すもの |
|---|---|
| **構造だけ残す**（既定・一覧の先頭） | 段落 `<p>` `<div>`・改行 `<br>`・箇条書き `<ul><ol><li>`・強調 `<b><strong><i><em>`・見出し `<h1>`〜`<h6>`・表。**属性は全部落とす** |
| **見た目だけ捨てる** | 上に加えてリンク・画像・取り消し線なども残し、`style` から**色・フォント・サイズの宣言だけ**削る |
| **テキストのみ** | HTML を丸ごと捨てる。いちばん確実 |

**クリップボードに `HTML Format` が載っているときだけ一覧に出ます。** 定型文だけを探しているときは、何か1文字打てば前方一致から外れて消えます。

**クリップボードが書き換わるのは、プレビュー窓で「この形にする」を押したときだけです。** 一覧に項目が出た時点でも、窓を開いただけでも、中身は変わりません。

**載せるところまでで、貼り付けはしません。** `Ctrl+V` は自分で押してください（キー送信は誤爆したときの被害が読めないため入れていません）。

### プレビュー窓（`clipboard_preview.py`）

左に「元のまま」、右に「落とした結果」を、どちらも `QTextEdit` へ `setHtml()` して**描画した状態**で並べます。

| キー | 動き |
|---|---|
| `1` `2` `3` | 段階を切り替える |
| `Enter` | その形にしてクリップボードへ載せ、窓を閉じる |
| `Ctrl+Z` | 整形する前の中身に戻す |
| `Esc` | 何もせず閉じる |

`HTMLを見る` を押すと、載る HTML そのものと `CF_HTML` のバイト数・オフセットが下に出ます。窓の大きさは変えたものを `settings.json` の `clipboard_format.preview_size` に覚えます（位置は毎回カーソルのある画面の中央に置き直します）。

**この窓で分かるのは「何が残って何が落ちるか」だけです。** 「PowerPoint で改行が潰れるかどうか」は再現できません — Qt のリッチテキストは `<p>` を素直に段落として描くので、**潰れる側の元 HTML も左ではちゃんと改行されて見えます**。潰れるかどうかは貼り先の実装の話で、手元のどんな描画エンジンで見ても答えは出ません。そこは載せて → 実際に貼って → 違えば戻す、で確かめます。窓の中にもその旨を書いてあります。

もとは一覧の下段プレビューに相乗りさせていましたが、**生の HTML を並べても読み取れず、高さが固定（150px）・折り返し無しで下が切れる**ので、別窓に出しました。

### 元に戻す

整形するとコピー元のリッチテキストは失われます。**クリップボードに履歴は無く、`Ctrl+Z` も効きません。** そこで整形の直前に中身を丸ごと退避しておき、後から書き戻せるようにしてあります。

| 戻し方 | |
|---|---|
| `Ctrl+Alt+V` →「📋 クリップボードを元に戻す」 | 窓を閉じた後に気づいたとき。**戻る中身の頭 40 文字が項目に出ます** |
| プレビュー窓の「元に戻す」 / `Ctrl+Z` | 窓を開いたまま試すとき |

- **退避は1つだけ・そのプロセスが生きている間だけ**です。何段も持つと、どれに戻るのか分からなくなります。TrayTools を再起動すると消えます。
- **ファイルには残しません。** クリップボードには資格情報が載ることがあり、ディスクへこぼしたくないためです。
- 戻した後も退避は残します。**戻す → やっぱり整形する、を往復できます。**
- 合計 16MB（`SNAPSHOT_MAX_BYTES`）を超えるときは**退避せず、整形もしません**。画像を貼った直後などは巨大な `CF_DIB` が載っていることがあり、戻せないまま壊すよりは何もしない方がましだからです。
- **「元に戻す」だけは HTML の有無で絞りません。** 「テキストのみ」に落とした直後こそ戻したくなるのに、そのときクリップボードに HTML は載っていないためです。

### 段階の線引きについて

`構造だけ残す` に `<div>` と表を入れてあります。`<div>` で行を組む書き出し元があり、落とすと行が繋がって**まさに直したかった「改行が消える」を自分で作ってしまう**ためです。表も、セルを落とすと全セルが1行に繋がります。属性を捨てる時点で罫線も色も消えるので、残るのは構造だけです。

`見た目だけ捨てる` で `font-weight` / `font-style` は**残します**。太字・斜体は見た目というより強調の情報で、`<b>` / `<i>` を残すのと揃わなくなるためです。削るのは `color` / `background*` / `font-family` / `font-size` / `line-height` などと、Word が撒く `mso-*` です。`class` / `id` / `data-*` は一律で落とします（貼り先で意味を持たないうえ、`data-pm-slice` のような書き出し元固有の印が付いて回るため）。`href` は `javascript:` などを落とし、`src` を落とした `<img>` はタグごと捨てます（貼り先に壊れた画像の枠だけが出るため）。

### `CF_HTML` のオフセット

`HTML Format`（`CF_HTML`）は先頭に**バイトオフセットのヘッダ**を持ちます。

```
Version:0.9
StartHTML:0000000105     ← <html> が始まる位置
EndHTML:0000000209       ← 文書の終端
StartFragment:0000000137 ← <!--StartFragment--> の直後
EndFragment:0000000177   ← <!--EndFragment--> の直前
<html><body><!--StartFragment--><p>…</p><!--EndFragment--></body></html>
```

**中身を書き換えたらここを再計算しないと、貼り先が壊れた位置を読みます**（「一部しか貼られない」という分かりにくい壊れ方になります）。**数えるのは文字数ではなく UTF-8 のバイト数です** — 「あ」は1文字でも3バイトなので、文字数で数えると日本語が入った途端に全部ずれます。`build_cf_html()` / `parse_cf_html()` がこの計算を持っています。

**クリップボードの読み書きは Qt に任せていて、`ctypes` で Win32 を直に叩いていません。** Qt の Windows 実装は、読むときに `StartHTML`〜`EndHTML` を切り出して `text/html` として返し、書くときに `text/html` から `CF_HTML` を組み立ててオフセットを UTF-8 バイトで数え直します。自前で `GlobalAlloc` / `SetClipboardData` を触る理由がありません（ハンドルの `restype` 指定漏れでアクセス違反を出した実績があるので増やしません）。読み取り側だけは、ヘッダ付きの生の `CF_HTML` が来る経路にも備えて `parse_cf_html()` で両方受けられるようにしてあります。

**ヘッダの数字より `<!--StartFragment-->` の目印を先に信じます。** 目印は中身と一緒に動くのでずれようがないのに対し、数字は書き換え漏れでずれるためです。

### 検証時の注意（実機の不具合ではありません）

`QT_QPA_PLATFORM=offscreen` で `setMimeData()` を使うと**プロセス終了時にセグメンテーション違反（終了コード139）が出ます。** offscreen にはクリップボードの実装が無く、基底の `QPlatformClipboard` が `Q_GLOBAL_STATIC` に `QMimeData` を抱えるため、**Python の終了処理が終わった後**の静的デストラクタで `delete` が走るのが原因です（`faulthandler` が何も出さないのがその証拠）。Windows では `QWindowsClipboard` が `mimeData()` / `setMimeData()` を両方 override していてこの静的変数を使わないので、常駐アプリ側にこの経路はありません。

## 背景を透過（`bg_remove.py` / `bg_remove_launch.py`）

**AI に描かせた画像などの背景を抜き、クリップボードへ戻す前にプレビュー窓で確かめて調整します。**

| 入口 | 読む画像 |
|---|---|
| `Ctrl+Alt+E`／画面アイコンの「🪄 背景を透過…」 | クリップボードの画像。無ければエクスプローラでコピーした画像ファイルの先頭 |
| 付箋の右クリック「背景を透過...」 | その付箋の絵（描き込みも焼き込んで渡す。クリップボードは書き換えない） |

窓は**別プロセス**で開きます（`pythonw bg_remove.py --clipboard` / `bg_remove.py <画像のパス>`）。numpy / OpenCV（AI を使えば rembg と onnxruntime）を常駐本体に持ち込まないためで、本体と付箋が import するのは起動役の `bg_remove_launch.py`（numpy すら読まない）だけです。

### 窓の配置

左に画像（**元の画像｜結果**を左右に並べる）と、その下に状態欄（ホバーした画素の色・ΔE、警告は橙・エラーは赤）。**右に設定の縦1列のパネル**（幅 310px 固定。窓が低いときはパネルの中だけスクロールし、出力ボタンは下に固定）。パネルは作業の順に並んでいます。

| セクション | 中身 |
|---|---|
| 抜き方 | 「色で抜く｜AIで抜く」のセグメント。**AIで抜くを選ぶと、まだ結果が無ければそのまま実行を始めます**。AI を選んでいるときだけ、モデル・「実行」（実行後は「やり直す」）・所要時間が出る。下に、そのモードで何が効くかを1行で |
| 背景色 | スウォッチ（× で外す）と「自動推定に戻す」。AI のときは「色かぶり除去にだけ使います」と添える |
| 残す色／点 | `Ctrl`+クリックで足した残す色と点の一覧（空のときは「Ctrl+クリックで追加」） |
| 調整 | 色で抜く：許容量（＋自動）・境目を精密に計算・境界のぼかし（精密 OFF のときだけ）・内側の近い色（残す／抜く）・ムラ追従。AI：2本のスライダー。どれも「ラベル……数値」の1行の下にパネル幅のスライダー |
| 仕上げ | 色かぶり除去・余白を切り詰める・アイコンに分ける（ON のときだけ、まとめる距離のスライダーと「アイコン N 個」が出る）・ベクタ化（ON のときだけ、色数のスライダー・「ベクタの結果を表示」・パス数が出る） |
| 表示 | 結果の下に敷く背景（市松・白・黒・緑） |
| （下に固定） | **クリップボードへ**（主ボタン）、その下に「保存…」「キャンセル」。キーは各ボタンのツールチップに書いてある |

以前は設定を画像の上に横長の行で並べていて、視線があちこちに飛び、スライダーが窓の幅いっぱいに伸びてラベルと数値が両端に離れていました。

**配色はこの窓のプロセスの中だけで1か所に決めています**（`bg_remove.THEME`）。Fusion スタイルにして、パレットを Active / Inactive / Disabled の全部について塗り、スタイルシートも同じ色から組み立てます。以前は一部だけを暗くしていたため、残りの部品（無効のラジオ、コンボの一覧、ツールチップ）が Windows の既定の配色で描かれ、暗い地に黒文字が沈んでいました。本文・補足説明・警告は地とのコントラスト比 4.5 以上、無効の文字は 3.0 以上を `tests/test_bg_remove.py` が機械的に確かめます（`CONTRAST_REQUIREMENTS`）。付箋や常駐本体は別プロセスなので影響しません。

### 窓の操作

### 抜き方ごとに効く項目

**効かない項目はグレーにせず隠します。** 抜き方のセグメントを切り替えると、「調整」セクションがモードの項目に入れ替わります（セグメントの下にも「何で決まるか」を1行で出します）。点（残す点・抜く点）のリストは両モード共通で、色で打った点はそのまま AI でも使われます。

| 項目 | 色で抜く | AIの結果 |
|---|---|---|
| 背景色（スポイト） | 抜く判定に使う | **色かぶり除去にだけ使う**（見出しが「背景色（色かぶり除去に使用）」になる） |
| 許容量・境目を精密に計算・境界のぼかし（精密 OFF のときだけ） | 効く | 隠れる |
| 画像の内側にある背景色に近い色 | 効く | 隠れる |
| これより薄い部分は消す／これより濃い部分は不透明にする | 隠れる | 効く |
| `Ctrl`+クリック（ここは残す） | **残す色**として、背景色よりその色に近い画素を背景から切り離す（外周の背景とつながっていても効く）。点を含む成分も残す | AIの判定の、点を含む半透明の部分を不透明にする（色は使わない） |
| 許容量の「自動」・背景のムラに追従 | 効く | 隠れる |
| `Shift`+クリック（ここも抜く） | 点を含む背景色の成分を抜く | 被写体に囲まれた薄い判定（脚の間など）を抜く。ただのクリックの点は使わない |
| 色かぶり除去・余白の切り詰め・右の背景 | 効く | 効く |

#### 色で抜く

- **背景色の初期値**は、画像の外周2pxで最も多い色（量子化してから数える）。
- **境目を精密に計算（推奨・既定ON）**：背景と色の近い淡い図形（明るいグレー・淡いピンクなど、ΔE 3〜5 しか違わないもの）が抜ける問題への対策。人がそれを背景と見分けられるのは、画素ごとの色の差ではなく「面の色が揃って違うこと」と「境目で色が切り替わること」による。そこで
  1. **ノイズを均した面で領域を決める**。画像のざらつきを外周で測り（`estimate_pixel_noise`）、その大きさに応じた強さ（ガウスの σ 1.0〜3.0）で均した Lab で背景色との差を測る。ムラの当てはめも均した画像で行う。スポイト・残す色・カーソルの ΔE も、1画素ではなく均した値を読む（1画素の値はノイズでぶれる）。
  2. **境目だけは混ざり具合から透明度を出す**（`matte_edges`）。領域の境目から 2σ+1px の帯を未確定にし、近くの被写体の色 F と背景の色 B に対して、画素の色がどちらにどれだけ寄っているかを不透明度にする。アンチエイリアスの縁は F と B の混ざりなので、その割合がそのまま出て、色かぶり除去で B を差し引くと縁の色も戻る。F と B の差がノイズに比べて小さい縁は、画素ごとの割合がノイズで暴れて毛羽立つので、均した画像から割合を読み、ぼけたぶんの傾きを締め直す。
  3. **背景に残った淡い粒を消す**（`drop_faint_specks`）。均した範囲（πσ²）より小さく、背景との差が許容量の2倍に届かない粒だけ。文字の点のような濃い粒は残る。
  - 許容量は **0.5 刻み**。精密モードの自動の値は「均した画像の外周の ΔE の p99 × 1.15 + 0.3」（下限 1）。均した距離はノイズで揺れないので詰めてよく、1 刻みの切り上げでは強いノイズの画像で明るいグレーの箱ごと抜けた。境界のぼかしは効かないので隠れる。
  - 効果（合成の図解：オフホワイトにビネット、枠線の無い淡い図形6つ、ノイズ σ 1.2〜6 を足して JPEG 品質85）。図形の内側が残った割合は、以前の方式だとノイズ σ4 で明るいグレー 3%・淡いピンク 4%・淡い緑 3%・やや薄い青 39%、σ6 では6つ中5つが 65% 以下だった。精密モードでは σ1.2〜6 のすべてで6つとも 99% 以上、背景は 99.9% 以上が透明。縁の不透明度の誤差（真の値との差の平均）も 0.29 → 0.15（σ4）に下がった。
  - 速さ：1200×800 のプレビューの描き直しは 170〜250ms（以前の方式は 80ms 前後）。原寸の確定は 2400×1600 で 1.4 秒。
  - OFF にすると以前の方式（画素ごとの色の差と境界のぼかし）に戻る。
- **許容量**：背景色との色差（Lab の ΔE）がこれ以下なら完全に透明。**境界のぼかし**：そこからさらにこの差までを線形に半透明にする（既定 2）。RGB ではなく Lab で測るのは、暗い色と明るい色で同じ数字が同じ見た目の差になるようにするため。カーソルを乗せた画素の ΔE が下に出るので、つまみの目安にできます。
- **許容量の「自動」**（既定で押された状態）：外周4pxの画素と背景色との ΔE を集め、外周に掛かった被写体（ΔE 20 超）を除いて p99 を取り、少し余裕を足した値にする。AI の図解の白っぽい背景はムラが ΔE 1〜3 しかないのに、上に載る薄いボックスとの差も ΔE 5〜15 しかないので、固定の初期値（以前は 12・ぼかし 10）では箱ごと抜けていた。押されている間は、背景色や残す色を変えたときにも測り直す。**つまみを手で動かすと「自動」が外れ、以後は勝手に上書きしない**。許容量は覚えない（画像ごとに測る）。
- **背景のムラに追従**（既定ON）：背景を一定の色ではなく、画像全体でゆるく変わる面（Lab のずれを (x, y) の2次多項式で当てはめたもの）として推定し、各画素はその場所での背景の色から測る。ビネット（四隅が暗い）やグラデーションのせいで、中央と四隅で同じ許容量が合わない問題への対策。当てはめはまず外周の帯（幅8%）だけで行い、面からの残差が小さい内側の画素を足して数回当て直す（最初から全体を使うと、大きな薄い箱に面が引っ張られる）。ムラの無い画像では面がほぼ平らになり、何も変わらない。縮小プレビューで当てはめて原寸にも同じ係数を使う（1200×800 で当てはめ 14ms、距離の計算込みで 80ms 程度）。
  - 既定を ON にした根拠（合成素材：オフホワイトに四隅で10%暗いビネット・ノイズ・JPEG）：OFF だと外周から推定した背景色と中央の背景が ΔE 4.5 ずれ、自動の許容量が 6 に膨らんで、ごく薄い箱（差 ΔE 6）は 4% しか残らなかった。残す色を足すと箱は残るが、今度は明るい中央の背景が残す色のほうに近くなり、背景の 36% が残った。ON なら許容量 2 で、3つの箱が全部そのまま残り、背景も 99.99% が透明になった。
- **残す色**（`Ctrl`+クリック）：背景色との距離 d_bg と残す色との距離 d_keep から r = d_bg / (d_bg + d_keep) を作り、r が 0.25 以下なら背景、0.5 以上（＝背景色より残す色のほうに近い）なら背景にしない、その間は半透明にする。**許容量の内側でも効く**ので、枠線の無い薄いボックスが外周の背景とつながっていても切り離せる。境目のアンチエイリアスの画素は半透明になり、色かぶり除去で背景色を差し引くので白く光らない。r は JPEG のムラで画素ごとに揺れるので、5×5 の中央値で均してから使う（箱の縁は鈍らせず、ぽつぽつした外れだけを消す）。残す色はムラへの追従にも使われ、拾った場所のずれを差し引いてから各場所のずれを足して比べる。
  - **背景とほぼ同じ色は残す色として使いません。** 拾った場所の背景の色（ムラに追従していれば面の値）との差が、背景のムラの大きさ（外周の画素の ΔE の p99。許容量の「自動」と同じ測り方）と ΔE 3 の大きいほう以下なら使わない。背景そのものを `Ctrl`+クリックすると、背景とほぼ同じ色が残す色になって背景がまだらに残っていたため。一覧のその行は薄く「背景とほぼ同じ色のため使っていません」と出し、状態欄にも橙で「背景ではない部分を Ctrl+クリックしてください」と出す。**基準に許容量のつまみは使いません**。残す色は許容量を上げたときに内側へ入ってしまう薄い箱を救うためのもので、許容量で無効にすると、いちばん必要な場面で効かなくなるため（AIの結果では点の位置だけを使うので、この判定は関係ない）。
- **画像の内側にある背景色に近い色**：被写体の中に背景と似た色（白背景に対する白目やハイライトなど）があるとき、それを透過対象にするかの一括の切り替え。「残す（外周からつながった背景だけ抜く）」（既定）か「抜く（画像全体の同色を抜く）」。**この設定だけは覚えません**（「抜く」のまま次の画像を開くと、白目まで抜けたのに気づかず載せる事故が起きるため）。
- **1か所ずつの指定**：「残す」のままでも、外周に接していない背景（腕と胴の隙間・文字の穴）は `Shift`+クリックで抜ける。「抜く」のままでも、守りたい部分は `Ctrl`+クリックで残せる。両方の点が同じ部分にあれば「残す」が勝つ。残す色で切り離したうえで、まだ**外側の背景とつながっている部分には「残す点」が効きません**（残すと外の背景まで丸ごと残るため。背景そのものを `Ctrl`+クリックした場合など）。状態欄に理由が出ます。
- **分かっている限界**：箱の外に直接書かれた濃い文字は、縁のアンチエイリアスの画素が「背景から遠い＝不透明」と判定されるので、暗い背景に置くと文字の周りに薄い明るい縁が残る（境界のぼかしを大きくすると和らぐが、薄い箱も溶けやすくなる）。JPEG の画像では、箱の縁のすぐ外に 8×8 ブロックのリンギングが1〜2px の小さな出っ張りとして残ることがある。

#### AIの結果

- **AIの判定の調整**：「これより薄い部分は消す」（既定 0%）と「これより濃い部分は不透明にする」（既定 100%）で、判定 a を `clip((a − 薄) / (濃 − 薄))` に引き伸ばす。**白い被写体が背景と取り違えられて半透明になったら「濃い」を下げる**、背景に薄いもや（接地影など）が残ったら「薄い」を上げる。点を打たずに一括で直したいとき用。画像ごとに変わる値なので覚えません。
- **`Ctrl`+クリック（ここは残す）**：点の値の半分より濃く、まだ不透明でない部分のうち、点からつながる範囲を不透明にする（縁は1px ほどぼかして元の判定となじませる）。**すでに不透明な部分（隣の黒い牛など）は橋にしません**。橋にすると、離れた所の接地影まで同じ範囲になって残ってしまうためです。不透明な所に打った点は、そこに接している半透明の部分を戻します。
  - **効かない場合**：AI が完全に背景と判定した所（5% 以下）、または範囲が画像の半分を超える（背景ごと拾っている）場合。状態欄に理由が出るので、そのときは「濃い」を下げてください。
- **`Shift`+クリック（ここも抜く）**：判定が 95% 未満の部分のうち、点を含む範囲を消す。**外側の背景とつながっている範囲には効きません**（輪郭のなめらかさまで削れるため。そのときは「薄い」を上げてください）。

#### 共通

- **色かぶり除去**（既定ON）：半透明の縁から背景色の混ざりを除く（`C' = (C − (1−a)·B) / a`）。白背景から抜いた縁が暗い背景で白く光るのを防ぐ。
- **余白を切り詰める**：不透明な部分の外接矩形でトリミング。
- **アイコンに分ける**（既定 OFF・覚える）：AI に描かせたアイコンの一覧などを、1つずつ別の絵に分ける。右の結果にアイコンごとの枠と番号が出る。
  - 分け方：不透明度が 8 を超える画素を「まとめる距離」だけ膨らませてから、つながった塊ごとに分ける。1つのアイコンの離れた部品（下に添えた文字のラベル、小さな飾り）を1つにまとめるため。外接矩形は膨らませる前の画素で決め、矩形に隣のアイコンが入り込んでいてもそこは透明にして切り出す。画像の 0.005%（1024×1024 で 52px）未満の小さな塊は捨てる。並びは上から下・左から右（行のまとまりで判断）。
  - まとめる距離の既定は **12px**。AI のアイコン一覧（1024〜1536px 四方に3〜5列）では、アイコン同士の間は 30px 以上空き、アイコンとラベル・飾りの間は 5〜15px 程度なので、その間を取った。0 にすると、ラベルの文字が1字ずつ別のアイコンになる（合成素材で 6 個 → 31 個）。
  - **クリップボードへ**：Office の図形用の形式 `Art::GVML ClipFormat` に、各アイコンを元の位置で並べたデータを載せる。PowerPoint・Excel・Word に貼ると、**アイコンが1つずつ別々の図として、元の並びのまま貼り付く**（アルファ・半透明も保つ）。同時に、1枚にまとめた透過PNG（`PNG` / `image/png` / DIB）も載せる。Office 以外の貼り先や、独自形式を読めない Office のオンライン版への逃げ道。
  - **保存…**：選んだ名前をもとに `名前_01.png`、`名前_02.png` … と連番で保存する。同じ名前のファイルがあれば、上書きしてよいか聞く。
- **ベクタ化（図形として貼る）**（既定 OFF・覚える）：抜いた絵を、PowerPoint・Excel・Word で**色や大きさを編集できる図形（フリーフォーム）**にする。AI に描かせたアイコンを、資料の配色に合わせて塗り替えたいとき用。**vtracer が入っていなければチェックは押せません**（`setup.py --with-vector` か `pip install vtracer`。setup.py は途中で入れるか聞きます）。
  - 手順（`vectorize`）：アルファを二値にする（>127）→ 透明の画素の色を近くの不透明の画素の色で埋める（抜いた背景の白が縁に混ざって、輪郭線の外側に一段明るい別の色の帯ができるのを防ぐ）→ `cv2.pyrMeanShiftFiltering`（sp 6・sr 14）で、輪郭を保ったまま JPEG のノイズで揺れた色を平らにする（これが無いと、破片を消す設定に細い線が巻き込まれて消えた）→ 3倍に拡大（LANCZOS。作業用の長辺は 4500px まで）→ 不透明の画素だけを Lab の k-means で**色数**（8〜32、既定 20、覚える）にまとめる（12・16色では似た色が混ざり、肌の色が灰色に吸収された）→ VTracer でなぞる（color / stacked / spline、filter_speckle 10 など）→ 座標を倍率で割って元に戻す。
  - **VTracer は子プロセスで動かします。** pip の vtracer 0.6.15 は、メモリ上の画像を渡す関数（`convert_raw_image_to_svg` / `convert_pixels_to_svg`）が呼んだだけで Segmentation fault でプロセスごと落ち、`convert_image_to_svg_py` もキーワード引数を1つでも渡すと落ちる（位置引数なら動く）。落ちても窓は生き残り、「ベクタ化に失敗しました」と出すだけ。下ごしらえは別スレッド、トレースは同じ venv の python を `-I -c` で起こし、一時ファイルでやりとりする。
  - **いつ走るか**：数秒かかるので、つまみを動かすたびには走らせない。チェックを入れたときはすぐ、色数や透過の設定を変えたときは 0.8 秒止まってから、原寸の結果で走らせ直す。結果は「どの透過の結果から作ったか」（原寸とプレビューの RGBA の指紋）と組で持ち、アイコンに分けるの切り替えのように透過の結果が変わらない操作では走らせ直さない。同じ設定で失敗したら、設定が変わるまで繰り返さない。実行中は結果の上に回る輪と「ベクタ化しています… N秒」を出す（AI と同時なら AI を優先して出す）。
  - **表示**：「ベクタの結果を表示」（既定 ON）で、右の結果を SVG を描き直したもの（`QSvgRenderer`）に切り替える。状態欄とパネルにパス数と所要時間を出す。設定を変えてまだ追いついていない間は、透過の結果（画素）を出す。
  - **クリップボードへ**：図形の GVML、1枚にまとめた透過PNG（いつもの形式）、`image/svg+xml`（SVG の文字列）を同時に載せる。ベクタ化が終わっていなければ、終わった時点で載せて閉じる（状態欄に「終わったらクリップボードへ載せます」）。アイコンに分けていれば**アイコンごとのグループ**、分けていなければ全体で1つのグループとして貼れる（何千もの図形がばらばらに貼られると、動かすのも消すのも大変なため）。パスは外接矩形の重なりがいちばん大きいアイコンへ入れる。
  - **保存…**：ファイルの種類で PNG と SVG を選べる（ベクタ化が ON なら SVG を先に選んである）。アイコンに分けていれば `名前_01.svg` … と連番で、座標はそれぞれのアイコンの左上を原点にする。
  - 実測（1408×768 のアイコン28個の画像）：下ごしらえ 1.3 秒 + トレース 3 秒前後、パス 1,500〜1,800 個、SVG 2.5MB。細い線も色も元にかなり近く、輪郭がわずかに波打つ程度。**Excel への貼り付けは図形が多いと遅い**（1,600 個で 30 秒近く。Excel が図形を1つずつ作るため）。
- **右の背景**：市松／白／黒／緑。抜け残りは黒、縁の白い光りは黒か緑で見ると分かりやすい。
- **AIで抜く**：rembg で被写体を切り抜く（「色で抜く」へはセグメントで戻せる。AI の結果は残るので、戻っても実行し直しにはならない）。実行中は、右の結果に色で抜いた結果を出したまま、状態欄にその旨を出す。モデルは `isnet-general-use`（標準）と `birefnet-general`（高品質・遅い）。別スレッドで動くので窓は止まらない。効く項目は上の表のとおり。**rembg が入っていなければボタンは押せません**（`setup.py --with-ai` か `pip install rembg onnxruntime` で使えます。setup.py は途中で入れるか聞きます）。初回は import だけで数十秒かかります（2回目以降は3秒前後）。
  - **実行中の表示**：結果の上を暗くして、回る輪と「いま何をしているか・経過秒数」を重ねる（ライブラリの読み込み → モデルの準備 → 判定。rembg は進み具合を返さないので、段階と秒数で止まっていないことを伝える）。パネルでもボタンが「実行中…」になり、その下で帯が動き続ける。「クリップボードへ」「保存」で原寸を計算し直す間も、結果の上に「原寸で仕上げています…」を出す。

つまみを動かしている間は長辺1200pxの縮小画像で計算し（60msのデバウンス付き）、クリップボードへ載せる／保存するときだけ原寸で計算し直します。

窓の大きさと、境目を精密に計算・境界のぼかし・背景のムラに追従・色かぶり除去・切り詰め・アイコンに分ける・ベクタ化・色数・モデル・右の背景は `settings.json` の `bg_remove` に覚えます（位置は毎回カーソルのある画面の中央）。許容量・内側の近い色の扱い・残す色・AIの判定の調整は覚えません。

### クリップボードに載せる形

`QClipboard.setImage()` だけだと DIB になり、貼り先の多くがアルファを無視して透明部分が黒や白に潰れます。そこで **PNG のバイト列を Windows の登録形式 `PNG`（Office やブラウザが読む）と `image/png` で載せ**、DIB 系（`CF_DIB` / `CF_DIBV5`）は Qt の画像変換に任せて併載しています。`tests/check_bg_remove_clipboard.py` が実際のクリップボードに `PNG` が載り、アルファが保たれていることを確かめます（**本物のクリップボードを一瞬書き換えます**。退避して書き戻しますが、Win+V の履歴には1件残ります）。

アイコンに分けたときは、さらに `Art::GVML ClipFormat` を載せます（Qt には `application/x-qt-windows-mime;value="Art::GVML ClipFormat"` の名前で生のバイト列を渡すと、その名前の Windows の形式になる）。中身は OPC の zip で、Office が自分で出すものからテーマだけを省いた形です。

```
[Content_Types].xml                          png / rels / xml と、drawing1.xml の Override
_rels/.rels                                  rId1 → clipboard/drawings/drawing1.xml
clipboard/drawings/drawing1.xml              a:graphic > lockedCanvas の中に a:pic を N 個
clipboard/drawings/_rels/drawing1.xml.rels   rIdn → ../media/imagen.png
clipboard/media/imagen.png                   各アイコンの透過PNG
```

各 `a:pic` は cNvPr の id が 2 からの連番（グループが 0）、name は `icon n`、位置と大きさは EMU（1px = 9525 EMU、96dpi 相当）で、左上のアイコンを原点にずらしてあります。`tests/check_bg_remove_gvml.py` が、このデータを載せて画面に出さない Excel（`Visible=False`、保存せずに閉じて `Quit`）へ貼り、**N 個の別々の図（`Shape.Type = 13` msoPicture）になり、位置関係が合い、画像が RGBA のまま（半透明も）であること**を確かめます（Excel 2013 で確認）。

ベクタ化したときは、`lockedCanvas` の中が `a:pic` ではなく**図形とグループ**になります（画像は入らないので `media` も無い）。

```
a:grpSp（アイコンごと。分けないときは全体で1つ）
  a:sp × パスの数（重ね順は VTracer の出力のまま。stacked なので、上に載る色は後ろに来る）
    a:custGeom > a:pathLst > a:path（w/h = 図形の大きさの EMU）
      a:moveTo / a:lnTo / a:cubicBezTo / a:close（SVG の M / L / C / Z に対応）
    a:solidFill > a:srgbClr、a:ln > a:noFill（線なし）
```

SVG の `d` は、相対命令・H/V・S・Q（3次ベジエへ正確に上げる）・T も絶対座標の M/L/C/Z に直して読みます（`parse_svg_path_d`。VTracer が実際に出すのは `M`・`C`・`Z` と `transform="translate(x,y)"`）。ドーナツ形の穴は、1本のパスの中の2つ目の部分パス（`M…Z M…Z`）として出てくるので、そのまま1つの `a:path` に続けて書きます。Office はこれを穴として描きます（Excel でグラフへ貼り直して画像に書き出し、穴が抜けていることを目で確かめた）。座標は図形の外接矩形（制御点も含める。ベジエは制御点の凸包に収まる）の左上からの EMU です。`tests/check_bg_remove_vector_gvml.py` が、合成画像（穴のある赤いドーナツ形・白い窓の重なった緑の四角・青い円）をベクタ化して見えない Excel へ貼り、**アイコンの数のグループ（`Shape.Type = 6`）の中が全部 Freeform（5）で線が無く、元の色に近い塗りの図形があること**、分けないときは1つのグループになることと、`image/svg+xml` が載っていることを確かめます。

## プレゼン支援（`presenter_overlay.py`）

画面の上に重ねて使う道具です。**対象を選びません** — ウェブサイトでも PowerPoint でも PDF でも、何を映していても効きます。

| 機能 | 既定のキー | 動き |
|---|---|---|
| 🔴 レーザーポインタ | `Ctrl+Alt+L` | マウス位置に赤い光点。**下のアプリは普通に操作できます** |
| 💡 スポットライト | `Ctrl+Alt+O` | マウス周辺だけ残して暗くする。半径と暗さは設定で変えられます（[画面ミラー](#画面ミラーscreen_mirrorpy)中なら**ツールバーのホイールで発表中に変えられます**） |
| ⬛ 黒画面 | `Ctrl+Alt+B` | 画面を黒く覆う。話に集中させたいときに（[画面ミラー](#画面ミラーscreen_mirrorpy)中は**ミラー先だけ**を覆います） |
| ⬜ 白画面 | `Ctrl+Alt+W` | 同じく白で |

**レーザーとスポットライトはクリックが素通しします。** `WA_TransparentForMouseEvents` だけでは Qt 内部の配送が止まるだけで下のアプリには届かないので、`WindowTransparentForInput`（`WS_EX_TRANSPARENT`）も付けています。そのぶん自分ではマウス位置を受け取れないため、カーソルは 16ms 間隔のポーリングで追います。

**黒画面と白画面は逆にクリックを受け、押すと解除されます。** 覆ってしまえば下は操作できず、クリックを吸っても失うものがない一方、「透過すると閉じる手段が無くなる」ほうが困るためです。ただしフォーカスは奪わないので、解除後もそのまま矢印キーでスライドを送れます。

出るのは**カーソルのある画面**だけです。マルチディスプレイで全画面を覆うと、手元の資料や発表者ツールまで見えなくなります（`presenter_overlay.target_screen` を `"all"` にすれば全画面も選べます）。

### `presenter.html` との使い分け

| | 対象 | できること |
|---|---|---|
| **presenter.html** | ローカルの HTML 資料 | スライド検出・送り・次スライド・カンペ・タイマー・レーザー |
| **プレゼン支援**（こちら） | **何でも** | レーザー・スポット・黒画面 |
| **画面ミラー** | **何でも** | 手元の一部を別モニタへ全画面で。レーザー・スポット・カーソル・クリック波紋 |

あちらは資料を `about:blank` に書き出して親と同一オリジンにすることで、DOM を直接操作しています。だからスライドを検出できる代わりに、対象がローカルの HTML に限られます。こちらは画面に重ねるだけなので、何に対しても使える代わりに中身は知りません。

## 画面ミラー（`screen_mirror.py`）

**手元の画面の一部を切り取り、別のモニタへ全画面で映します。** 画面共有（Teams 等）に出しているモニタへ向けて使うための道具です。

```
モニタ1（手元）              モニタ2（画面共有に出している）
┌────────────────┐        ┌──────────────┐
│  ┌──────────┐  │        │              │
│  │ 選択範囲   │──┼───────▶│  全画面ミラー  │
│  │(操作できる) │  │        │ ＋カーソル    │
│  └──────────┘  │        │ ＋レーザー等   │
└────────────────┘        └──────────────┘
```

**範囲を選んだあとも、その中は普通に操作できます。** ミラーは見ているだけなので、ブラウザでリンクを辿ろうが PowerPoint を送ろうが、そのまま向こうに映ります。対象がブラウザでも PowerPoint でも PDF でも関係ありません。

トレイメニューの **🖥 画面ミラー（別モニタへ）▸ ▶ 範囲を選んで開始**、または `Ctrl+Alt+P` から。

### 操作の一覧

| したいこと | 方法 |
|---|---|
| **始める** | `Ctrl+Alt+P` ／ トレイメニュー **▶ 範囲を選んで開始** |
| **映す範囲を変える** | `Ctrl+Alt+P`（**映したまま**範囲選択がやり直せます）／ 手元のツールバーの 🔲 ／ トレイメニュー **🔁 範囲を選び直す（映したまま）** |
| **静止させる** | `Ctrl+Alt+F` ／ 手元のツールバーの ⏸ ／ トレイメニュー **⏸ 静止（一時停止）** |
| **終わる** | `Ctrl+Alt+Q` ／ 手元のツールバーの ✕ ／ トレイメニュー **⏹ 終了** |
| **選び直しをやめる**（ミラーは続く） | 範囲選択中に `Esc` |

**`Ctrl+Alt+P` はミラーを止めません。** 以前は押すたびに開始／終了のトグルでしたが、発表の途中で映す場所を変えたくなったときに、いったんミラーを畳むことになっていました。画面共有に出しているモニタが一瞬黒くなるので、見ている側からは事故に見えます。**今は映したまま範囲だけを選び直します。** 終わらせる手段は上のとおり3つ用意してあります。

> 選び直している間、ミラーは**自動で静止します**。範囲選択の減光オーバーレイは全モニタを覆うので、撮り続けたままだと向こうには「減光した自分の画面」が映ってしまうためです。選び終える（または `Esc` でやめる）と元に戻ります。

ランチャ（タスクバーウィジェット）にも `screen_mirror` として登録してあります。ただし**既定の並びには入れていません**（パネルは縦に伸びる一方なので）。使うなら `settings.json` の `launcher_items` に足してください。

### 範囲の選び方

範囲選択はキャプチャと同じオーバーレイです（ドラッグ、`Esc` でキャンセル、クリックでその位置のウィンドウ全体）。違いは**縦横比が固定される**ことと、**プリセットが選べる**ことです。

| キー | 比率 |
|---|---|
| `1` | 自由 |
| `2` | 4:3 |
| `3` | 16:9（既定） |
| `Space` / `Tab` / ホイール | 順送り |

**大きさは自由です。** 固定されるのは比率だけなので、800×450 でも 1600×900 でも 1920×1080 でも選べます。**ドラッグの途中でも比率を切り替えられます**（今引いている枠がその場で合わせ直されます）。

#### プリセット — 決まった矩形を一発で

範囲選択中、画面の左上に**プリセットの一覧**が出ます。**クリック**するか **`Ctrl`+数字**で、その矩形がそのまま確定します（比率には合わせません。大きさまで決めたものなので）。

| 既定のプリセット | 大きさ | 始点 |
|---|---|---|
| **等倍（ミラー先と同じ）** | ミラー先のモニタと同じ解像度 | そのモニタの中央 |
| **上を100空ける** | 1600×900 | (0, 100) |
| **HD** | 1280×720 | 中央 |
| **FHD** | 1920×1080 | 中央 |

**`x` / `y` は「今カーソルがあるモニタの左上」からの相対です。** (0, 100) と書けば、作業しているモニタの上端から 100px 下——タスクバーやブラウザのタブ・アドレスバーを外した位置になります。絶対座標にすると、プライマリでないモニタで作業している人の手元では別のモニタを指してしまうためです。特定のモニタに固定したいときは `screen` に `QScreen.name()` を書いてください。

**中身は `settings.json` の `screen_mirror.presets` で増やせます。**

```json
"screen_mirror": {
  "presets": [
    {"label": "等倍（ミラー先と同じ）", "size": "target"},
    {"label": "上を100空ける", "x": 0, "y": 100, "width": 1600, "height": 900},
    {"label": "左半分", "x": 0, "y": 0, "width": 1280, "height": 1440}
  ]
}
```

| キー | 意味 |
|---|---|
| `label` | 一覧に出す見出し |
| `width` / `height` | 大きさ（論理px） |
| `size: "target"` | 大きさを**ミラー先のモニタと同じ**にする（＝等倍。**滲みません**） |
| `x` / `y` | 始点。省略するとその画面の中央 |
| `screen` | 基準にするモニタ名（`QScreen.name()`）。省略すると今カーソルのあるモニタ |

指定した大きさが画面に収まらないときも**縮めません**（等倍のために指定した大きさを勝手に変えては意味が無いため）。始点だけ画面の中へ寄せます。書き損じた行はその行だけ落ちます。

### 負荷 — 範囲が大きいほど重くなります

映すたびに手元の範囲を撮り直すので、**選ぶ範囲が大きいほど1枚あたりの時間が延びます**。このPCでの実測（既定 30fps・ミラー先 2560×1440）：

| 範囲 | 1枚の取得 | 30fps で回したとき |
|---|---|---|
| 1280×720 | 16.9 ms | **約 30 fps / CPU 60〜75%**（1コア換算） |
| 1920×1080 | 33.5 ms | 約 26〜30 fps / CPU 65〜110%（**コマ落ちします**） |

**1280×720 前後がこのPCの快適な上限です。** それより大きく映したいときは `screen_mirror.fps` を落としてください（1920×1080 なら 20fps で CPU が 5 割ほどに、15fps で 4 割ほどに下がります）。**画面の拡大率を上げている環境（`QT_SCALE_FACTOR=1.5` など）ではさらに重くなります**（撮る実ピクセルも描く実ピクセルも増えるため。1280×720 で 28fps、1920×1080 で 20fps 程度）。

自分で加減できるよう、目安を2か所に出しています。

- **範囲選択中**：その大きさで出せそうな fps（`比率: 16:9　目安 30fps`）
- **ミラー中**：実測 fps（手元の枠に添えた帯。**帯もミラーには映り込みません**）

### ミラー先のモニタ

**モニタが3枚以上ある構成でも、どれに出すかを選べます。** サブメニュー **🖵 ミラー先** から選ぶと `screen_mirror.target_screen_name` に保存され、次回以降もそこに出ます。「自動」に戻すと、**選択範囲が乗っていないモニタ**の先頭を使います。

選んだモニタに全画面で出し、**アスペクト比は保ったまま余白は黒**にします。

**選択範囲がミラー先のモニタに重なっているときは始まりません**（自分を撮ることになり、無限に入れ子になるため）。通知でその旨をお知らせします。モニタが1台しかないPCでも同じ理由で始まりません。

### ミラー先に描かれるもの

| | 動き |
|---|---|
| **カーソル** | 白い矢印を自前で描きます（実カーソルは画面キャプチャに写りません）。**大きさは拡大率によらず一定**なので、どの範囲を選んでも見え方が揃います |
| **レーザーポインタ** | `Ctrl+Alt+L`。ミラー先に赤い光点。**出している間はカーソルを隠します**（同じ位置に2つ重ねない） |
| **スポットライト** | `Ctrl+Alt+O`。ミラー先で周囲を暗くします。**大きさと暗さは発表中にその場で変えられます**（下記） |
| **クリック波紋** | クリックした瞬間、押した位置に輪が広がります。画面共有では「今押した」が伝わりにくいため |
| **黒画面・白画面** | `Ctrl+Alt+B` / `Ctrl+Alt+W`。**ミラー先だけ**を覆います。手元は普通に見えたままです（下記） |

**ミラー中は、4つとも行き先が自動でミラー先へ切り替わります。** ホットキーもメニューも[プレゼン支援](#プレゼン支援presenter_overlaypy)と共通で、キーは増えていません。レーザーとスポットライトを振り替えるのは、手元の画面に重ねるとそれがそのまま撮られて向こうへ二重に映る（スポットライトは減光ごと焼き込まれて戻せない）ためです。ミラーを止めれば、どれも従来どおり手元に重なります。

#### 黒画面・白画面は共有側だけ

**ミラー中の `Ctrl+Alt+B` / `Ctrl+Alt+W` は、ミラー先のモニタだけを覆います。手元はそのまま見えています。** 以前は手元（カーソルのある画面）を覆い、覆われた結果がミラーにも映る作りでしたが、それでは**手元まで真っ黒になって次に何を見せるか準備できません**。覆っている間はキャプチャそのものを止めるので、そのぶんCPUも空きます。

覆っていることは**手元の3か所**に出ます（静止と同じ流儀）。手元が普通に見えている以上、ここに出さなければ気付きようがないためです。

- **枠の色が青（`#00c8ff`）から紫（`#a855f7`）に変わる**
- 枠の帯が `⬛ 共有側だけ黒画面（手元は見えています）` になる
- ツールバーの ⬛ が点灯し、右側に `⬛ 共有側は黒画面` と出る

**ミラーしていないときは従来どおり**、カーソルのある画面を覆います。

#### スポットライトの大きさと暗さをその場で変える

**手元のツールバーの上でホイールを回すと半径、`Shift`（または `Ctrl`）+ホイールで暗さが変わります。** スポットライトのアイコンの上なら消えていても効き、点いている間はツールバーのどこで回しても効きます。変えた値は右側に `スポット 半径 170 / 暗さ 72%` のように出ます。

**変えた値は `presenter_overlay.spotlight_radius` / `spotlight_dim` へ書き戻されるので、次回も同じ設定で始まります。** 書き戻しは最後の操作から少し置いてから1回だけ行います（ホイールは目盛りが連続で飛んでくるため）。半径は 20〜1200、暗さは 0〜95% で止まります（100% にすると周りが完全に潰れ、資料の一部に注目させるという目的から外れるため）。

色や大きさの設定は `presenter_overlay` セクションと共通です（同じ道具の同じ光点を2か所で設定させないため）。

**カーソルが選択範囲の外に出たら、ミラーには何も描きません。** 端に貼り付けて見せることもできますが、実際には指していない場所に光点や矢印が居座るのは見ている側への嘘になります。消えること自体が「発表者はいま範囲の外を触っている」という正しい情報になり、戻ってくれば同じ位置に現れます。

### 手元の枠

いま映している範囲が手元で分かるよう、**範囲のまわりに薄い枠**を出し続けます（`screen_mirror.source_frame` で切れます）。

**枠は範囲の外側にあり、ミラーには映り込みません。** 枠の窓そのものに `setMask` で範囲ぶんの穴を開けているので、撮る範囲にこの窓のピクセルは1枚もありません（毎フレーム隠して出し直すとちらつくうえ、1枚17msの予算に窓の表示切替が乗ります）。穴の部分のクリックもそのまま下へ抜けます。

### 手元のツールバー

**枠の下（範囲の外）に、プレゼン支援の操作をアイコンで並べます**（`screen_mirror.toolbar` で切れます）。トレイメニューまで手を伸ばさずに押せるようにするためのものです。

| アイコン | 機能 |
|---|---|
| 🔴 | レーザーポインタ（`Ctrl+Alt+L` と同じ。ミラー先に描かれます） |
| 💡 | スポットライト（`Ctrl+Alt+O` と同じ） |
| ⬛ | 黒画面（`Ctrl+Alt+B` と同じ。**ミラー先だけ**を覆います） |
| ⬜ | 白画面（`Ctrl+Alt+W` と同じ） |
| ⏸ | **静止**（下記） |
| 🔲 | 範囲を選び直す（映したまま） |
| ✕ | ミラーを終了 |

**点いている機能はアイコンが点灯します**（下地に色が敷かれて縁取られます）。ホットキーやトレイメニューから切り替えても追随します。マウスを乗せると右側に名前が出ます。

**ツールバーも範囲の外にあり、ミラーには映り込みません。** 枠の真下（入らなければ真上）に置き、それでも撮影範囲に掛かってしまう場合は**出しません**（映り込むと、映った自分をまた撮る入れ子になるため）。枠がマウスを透過する窓なので、押せるものは別の窓として出しています。

### ミラー範囲を動かす — ツールバーのタイトルバーをドラッグ

**ツールバー右側（点々の付いた説明欄）がタイトルバーです。そこを掴んでドラッグすると、映す範囲ごと動きます。** 手元の枠とツールバーも一緒に付いてきて、**ドラッグしている間もミラーは動いた先を映し続けます**（範囲を選び直すのと違い、共有が途切れません）。**大きさは変わりません**（移動だけ）。

**アイコンの上のドラッグでは動きません。** 押すつもりで少し滑っただけで範囲ごと動いては困るためです（付箋で「画像部分のドラッグで動く」をやめたのと同じ判断）。

歯止めは2つです。

- **ミラー先のモニタには重ねられません**（自分を撮ると無限に入れ子になるため）。突き当たったら、その向きの成分だけ捨てて残りは動きます（縁に沿って滑らせられます）
- **範囲の中心は画面の中に残ります。** 画面の外へ丸ごと送れてしまうと掴む手段が無くなるうえ、ツールバーの置き場所も「範囲の中心にあるモニタ」を基準に探しているので、中心が画面外だと離した瞬間にツールバーが画面外へ行ってしまいます

離したところで、枠とツールバーを新しい範囲に合わせて作り直します（帯を範囲の上下どちらに置くか、ツールバーが下に収まるかは位置ごとに変わるため）。

### ミラー範囲の大きさを変える — ツールバー右端の ◢ をドラッグ／ホイール

**説明欄のさらに右端、斜め線3本（◢）が大きさを変える掴みしろです。** 掴んでドラッグすると、映す範囲が大きくなったり小さくなったりします。**◢ の上ではホイールも効きます**（1目盛りで幅 64px、`Shift`／`Ctrl` を押しながらで 16px）。ドラッグは狙った大きさへ一息に持っていく道、ホイールは「あと少しだけ」を数字を見ながら詰める道です。

**少し広げたいだけのときに、`Ctrl+Alt+P` で選び直さずに済ませるための機能です。** 選び直すと減光オーバーレイが全モニタを覆うぶん共有側が一瞬止まるので、微調整には大げさすぎました。

- **左上を固定して、右下だけが動きます。** 窓の大きさを変えるときの当たり前の作法であるうえ、上端を動かさないことに実利があります——手元の枠は「範囲の上に帯を置けるか」で外形が決まっているので、上端が動かなければ掴んでいる間に帯が上下へ飛びません
- **比率は掴んだときのものを保ちます。** ミラー先のモニタは決まった比率なので、崩すと上下か左右に黒帯が増えます（映像は引き伸ばさず、余りを黒で残す作りです）。**`Shift` を押している間だけ自由**になります
- **ドラッグしている間もミラーは続きます。** 手元の枠・ツールバー・カンペも一緒に付いてきます（カンペは、その大きさでは置き場所が無くなったら引っ込みます。撮影範囲に掛けるくらいなら出さない、という方針は変わりません）
- **推定フレームレートが説明欄に出ます**（`1280x720　目安 30fps` のように）。大きくするほど重くなるので、選んでいる最中に数字が見えている必要があります。手元の枠の帯にも新しい大きさが即座に反映されます

歯止めは4つです。

- **小さすぎ**：`240x135` より小さくできません（そこまで拡大すると何を映しても滲んで読めません）
- **大きすぎ**：`3840x2160` より大きくできません（1枚の取得に 122ms かかり 8fps 相当です）。**デスクトップ全体より広くもできません**
- **ミラー先のモニタには重ねられません**（移動と同じ。自分を撮ると無限に入れ子になります）
- **範囲の中心は画面の中に残ります**（移動と同じ）

**ツールバーが置けなくなる大きさにはできません。** 掴んでいる最中にツールバーを引っ込めると、掴んでいたものが消えてドラッグが切れるためです。

**なぜ掴みしろがツールバーなのか。** 手元の枠の角や辺を掴ませるのが素直ですが、あの窓はマウスを透過する（`WindowTransparentForInput`）ので自分ではクリックを受け取れず、透過をやめると撮影範囲の外周でクリックを吸い始めます（映しながら操作する、というこの機能の前提が壊れます）。四隅に小さい窓を4枚置く案は、最前面の押し合いと「撮影範囲に掛からない置き場所探し」が4つ増えます。ツールバーは既に「撮影範囲の外に置けた矩形」なので、その右端を分けるのがいちばん安く付きました。

### 静止（一時停止）— 手元を見せずに切り替える

`Ctrl+Alt+F` ／ ツールバーの ⏸ ／ トレイメニューの **⏸ 静止（一時停止）** で、**ミラーを静止させられます**。止めている間は撮りに行かないので、向こうには最後の1枚が出たままになります。手元で資料を切り替えたり、見せたくないものを開いたりする間に使ってください。もう一度押すと現在の画面に戻ります。

**静止していることは手元の3か所に出ます。**

- **枠の色が青（`#00c8ff`）から橙（`#ff8c00`）に変わる**
- 枠の帯が `⏸ 静止中（動いていません）` になる
- ツールバーの ⏸ が点灯し、右側に `⏸ 静止中` と出る

気付かずに静止したまま話し続けるのがいちばん困るので、ここは目立たせてあります。**ミラー先には何も出しません**——静止していることを知る必要があるのは発表者だけで、向こうに印を出したら「今は見せていない」と宣言することになります。

静止中は**カーソルもレーザーも波紋も描きません**。絵が止まっているのに指先だけ動くと、指している場所が嘘になるためです。

### 手元のカーソルのちらつき対策

ミラー中に手元のマウスカーソルがちらつく、という報告への対策として2つ手を打っています。**どちらが効いたかは目視でしか確かめられないので、断定はしていません。**

**① 毎フレームの `BitBlt` から `CAPTUREBLT` を外しました。** mss は `SRCCOPY | CAPTUREBLT` で撮ります。`CAPTUREBLT` は「上に重なっているレイヤードウィンドウも結果に含める」フラグで、そのために Windows は撮る直前に**画面からカーソルをいったん取り除きます**。1枚撮るだけなら誰も気付きませんが、**毎秒30回撮り続けると目に見えるちらつきになります**（`gdigrab` などの画面録画でも知られた症状です）。

ミラーはそもそもレイヤードウィンドウを撮りたくない（自前の枠やツールバーが写ると入れ子になる）ので、外して困るものがありません。**このPCで実測しても、可視のレイヤードウィンドウ6枚の矩形を `CAPTUREBLT` あり／なしで撮り比べて1バイトも違いませんでした**（DWM 合成の画面から `BitBlt` する以上、フラグの有無で中身が変わらないため）。付箋（Rapture）側の1枚撮りは従来どおり `CAPTUREBLT` を付けたままです（`grab_region(..., include_layered=False)` を指定したときだけ外れます）。

なお `GetCursorInfo` の `CURSOR_SHOWING` は、`CAPTUREBLT` 付きで撮り続けている間も一度も落ちませんでした（3.3秒・180万サンプル中0件）。**この取り除きはウィンドウごとの表示カウントには表れない**ということなので、この計測は仮説を否定する材料にはなりません。

**② 最前面への押し上げを「実際に覆われているときだけ」にしました。** 以前は枠・ツールバー・ミラー窓の3枚が、500ms ごとに無条件で `raise_()` していました。Zオーダーを触る操作は毎回 Windows に並びを組み替えさせ、**カーソルの下にあるウィンドウへ当たり判定とカーソル形状の問い合わせを出し直させます**。いまは `GetWindow(GW_HWNDPREV)` で自分より手前を遡り、**自分の矩形に重なる可視ウィンドウが1枚も無ければ押し上げません**。

**判断が付かないときは押し上げる側に倒します**（矩形が取れない、遡りが上限に達した等）。ここが誤って「覆われていない」と答えると、ミラー窓が会議アプリの裏へ回って共有先に何も映らなくなり、ちらつきよりはるかに重い事故になるためです。

これに[タスクバーウィジェットの引っ込め](#最前面の維持)を合わせて、ミラー中に 500ms 周期でZオーダーを触る箇所は 4 か所から実質 0 になりました。

### 滲み — 拡大する以上は避けられません

**手元の範囲を引き伸ばして映す以上、補間による滲みは原理的に避けられません。** Qt が持っている拡大方法は2つだけで、その間はありません。

| 方式 | 見え方 |
|---|---|
| `SmoothTransformation`（双線形） | 滑らかだが**滲む**（元に無い中間色が生える） |
| `FastTransformation`（最近傍） | **鮮明**だがブロック状になる |

**本当の解は「等倍で映すこと」です。** 範囲選択の**プリセット「等倍（ミラー先と同じ）」**を選べば、手元の範囲とミラー先の解像度が一致するので**拡大も縮小も起きず、1画素も滲みません**（等倍では上の2方式の出力が完全に一致することを実測で確認しています）。**滲みが気になるときは、まずこれを選んでください。**

等倍にできないときのために `screen_mirror.scaling` を用意しました。`auto`（既定）／`smooth`／`fast`。**`auto` は倍率が整数のときだけ `fast` にします。** 640×360 の文字と細線を実際に拡大して画素を数えた結果：

| 倍率 | 方式 | 元に無い中間色 | 隣接画素の差の平均（輪郭のコントラスト） |
|---|---|---|---|
| 2倍 | Smooth | 16.8% | 9.42 |
| 2倍 | **Fast** | **0%** | **12.15**（約1.3倍鮮明） |

整数倍なら元の1画素がそのまま正方形へ分かれるので、中間色が1つも生えません（2倍では1px幅の線がすべて2pxになることも確認済み）。一方 **1.33倍のような半端な倍率で `fast` にすると、1px幅の線が 1px と 2px に割れて**（実測で 58本と28本）、行によって太さの違う文字になります。だから半端な倍率では `smooth` に落とします。

いま何倍で、どちらの方式で描いているかは、**手元の枠の帯に出ます**（`拡大 2.00倍 鮮明`）。

### なぜ画面をそのまま映すのか

同梱の `presenter.html` は**ローカル HTML 資料専用**で、リンク遷移をすると制御から外れます。WebEngine を内蔵して自前のブラウザにする案もありましたが、それは実質ブラウザを作ることになります。**画面をそのまま映せば、操作の問題が丸ごと消えます。** `presenter.html` はローカル資料用としてそのまま残します（併存）。

### 手元だけに見えるカンペ（`mirror_notes.py`）

ミラー中、手元のツールバーの **📝 カンペ** で開きます。**共有側には映りません**（撮影範囲の外にしか置かないため。右に入らなければ左へ回し、それも無理なら出しません）。

`notes/` フォルダの `.md` を切り替えて読みます。**読むだけ**で、書くのは外部のエディタです（発表中に文章を書き足すことは稀で、書くのは事前に慣れたエディタのほうが速いため）。

| ボタン | |
|---|---|
| **編集** | ファイルが無ければ雛形を作ってエディタで開く |
| **再読込** | 外部で直したものを反映 |
| **◀ ▶** | `#` 単位で章を送る |
| **目次** | `##` も含めて一覧。クリックでジャンプ |
| **A+ / A−** | 文字の大きさ |

目次には `##` も入れますが、**◀▶ が辿るのは `#` だけ**です。中身は「# 章」ではなく「## 話すこと」の側に書かれるので目次から落とすと辿り着けませんが、送りボタンで小見出しまで刻むと押す回数が増えて通り過ぎます。

見出しは正規表現ではなく `setMarkdown` 後の文書構造から拾うので、表示と目次がズレず、コードブロック内の `#` も誤検出しません。

`notes/` は追跡していません（個人のカンペが入るため）。

## 発表者ツール（`presenter.html`）

HTML のプレゼン資料に、PowerPoint の発表者ツール相当を付ける単一ファイルのビューアを同梱しています。カンペ、次スライドのプレビュー、タイマー、レーザーポインタ、スポットライト、サムネ一覧。

トレイメニューの **📽 発表者ツール**、またはタスクバーウィジェットのランチャから開きます。**サーバー不要**で、既定のブラウザに投げるだけで動きます（`file://` で単独動作するよう作られています）。

資料は**開いた先へドラッグ＆ドロップ**してください。tray-tools から資料を渡す仕組みは持たせていません。`file://` からパス指定で資料を読ませるには、ブラウザのファイルアクセス制限を緩める必要があるためです。

使い方とキー操作は [presenter_README.md](presenter_README.md) を参照してください。

**開くブラウザは Edge です**（`settings.json` の `tools.browser` で `chrome` / `firefox` / 実行ファイルのフルパスに変えられます）。既定のブラウザに任せないのは、**Firefox では真っ白になる**ためです。`presenter.html` は `about:blank` へ `document.write` して親と同一オリジンにする作りで、Firefox の `file://` の扱いと噛み合いません。Chrome と Edge では動きます。

別の場所に置いたものを使いたいときは、`settings.json` の `tools.presenter` にパスを書けば差し替えられます。空なら同梱のものを開きます。

### 任意のサイトを取り込んで開く（`web_presenter.py`）

トレイメニューの **🌐 サイトを取り込んで開く** で URL を尋ねられます。入力すると、そのページを取り込んで**発表者ツールの資料として**既定のブラウザで開きます。ローカルの HTML 資料と同じように、カンペ・次スライド・タイマー・レーザーが使えます。

**なぜ一手間かかるのか。** `presenter.html` は資料を `about:blank` へ `document.write` して親と同一オリジンにすることで DOM を直接操作しています。他所のサイトを `iframe` で直接開くとクロスオリジンで何も触れません。そこで **tray-tools 側がブラウザ（`QtWebEngine`）を持ちます**。こちらでサイトを開いてレンダリング後の DOM を文字列として取り出し、それを資料として渡す——相手のサーバから見れば普通の閲覧なので壁はありません。取り出した後はただの HTML 文字列なので、`presenter.html` はローカル資料と区別せずに扱えます。

流れは次のとおりです。

1. `QInputDialog` で URL を尋ねる（一度取り込んだ URL は履歴として入力欄に並びます）
2. **非表示の** `QWebEngineView` でそのページを開く（窓は出ません）
3. `page().toHtml()` で**レンダリング後の DOM** を取り出す（JS が組み立てた内容も入ります）
4. `<head>` の先頭に `<base href="元のURL">` を挿す。これで画像・CSS・フォントの相対参照が元のサーバから引けます
5. `presenter.html` の中身＋「起動時に `loadHtml()` を呼ぶ `<script>`」を `%TEMP%\traytools-presenter\` に書き出す
6. そのファイルを既定のブラウザで開く

**`presenter.html` は1バイトも変えていません。** 「単一ファイルを `file://` からダブルクリックで動かせる」ことがあのファイルの存在理由なので、こちらの都合を持ち込まない方針です。足すのは末尾の `<script>` だけで、それも `%TEMP%` に書き出すコピーに対してだけ行います。**`QtWebEngine` は PySide6 のフルインストールに最初から入っている**ので追加依存もありません（読み込みが重いので `import` は使うときまで遅らせています。実測 45ms）。

#### 制約

- **認証の要るサイトは取り込めません。** 取り込みに使う `QWebEngine` は窓を出さずに動かしており、**中で対話的にログインする手段がありません**（クッキーも都度空です）。ログイン後のページを資料にしたい場合は、ブラウザで「名前を付けて保存（完全）」してから **📽 発表者ツール** にドラッグ＆ドロップしてください。ログイン用の窓を出す・プロファイルを保存する、という道もありますが、「画面に勝手に窓を出さない」ほうを優先して採っていません。
- **取り込みはスナップショットです。** 取り込んだ後に元のサイトが変わっても追随しません。最新にしたいときは取り込み直してください（履歴から同じ URL を選べます）。
- **SPA や凝った動的サイトは崩れることがあります。** 取り込んだ `<script>` は発表者ツールの `iframe` の中で改めて実行されるため、ルーティングや「元の URL 前提」の処理が暴れることがあります。そういうサイトは `settings.json` の `tools.web_presenter_strip_scripts` を `true` にすると `<script>` を落として静止させられます。
- **JS で後から書き足すページ**は、読み込み完了から `tools.web_presenter_settle_ms`（既定 800ms）だけ待ってから取り出します。骨組みしか取り込めないときはここを伸ばしてください。
- **読み込みが終わらないサイト**があるので、`tools.web_presenter_timeout_seconds`（既定 30 秒）で必ず打ち切ります。失敗しても通知が出るだけで、常駐アプリは落ちません。

#### 設定

| キー | 既定 | 意味 |
|---|---|---|
| `tools.web_presenter_timeout_seconds` | `30` | 読み込みの打ち切り（秒）。`loadFinished` が来ないサイト対策 |
| `tools.web_presenter_settle_ms` | `800` | 読み込み完了から DOM を取り出すまでの追加の待ち（ミリ秒） |
| `tools.web_presenter_strip_scripts` | `false` | `true` で取り込んだ `<script>` を落とす |
| `tools.web_presenter_recent` | `[]` | 入力欄に出す履歴。取り込みに成功したときだけ増える（最大10件） |

ランチャ（タスクバーウィジェット）にも `web_presenter` として登録してあります。ただし**既定の並びには入れていません**（パネルは縦に伸びる一方なので）。使うなら `settings.json` の `launcher_items` に足してください。

```json
"launcher_items": ["capture", "audio", "ruler", "color_picker", "snippets", "bookmarks", "web_presenter"]
```

#### 実装で気を付けた点

- **`toHtml()` も `runJavaScript()` もコールバック方式**です。同期では取れないので、`document.baseURI` → `toHtml()` の順に入れ子で呼んでいます。`<base>` に `view.url()` ではなく `document.baseURI` を使うのは、ページ自身が `<base href>` を持っていた場合にその解決結果を尊重するためです（元からある `<base>` は `<head>` の中からだけ消します。文書順で最初の `<base href>` だけが効くうえ、相手が相対 href だと `%TEMP%` の `file://` を基準に解決されて全部壊れるため）。
- **`QWebEngineView` の参照を握り続けます。** 読み込みは非同期なので、掴んでいないと関数を抜けた瞬間に GC で消えて何も起きません（`web_presenter._ACTIVE`）。
- **取り込んだ HTML を JS に埋めるとき、`<` をすべて Unicode エスケープ（バックスラッシュ + `u003c`）へ逃がします。** `JSON.stringify` 相当だけでは足りません。資料の中に `</script>` が現れると**そこで囲っている `<script>` タグが閉じてしまい**、以降が本文として垂れ流されます（HTML パーサは JS の文字列リテラルの中かどうかを見ません）。生の `<` を残さなければ `</script>` も `<!--` も HTML パーサからは見えなくなります。
- **一時ファイルは溜まるので掃除します。** 取り込むたびに `%TEMP%\traytools-presenter\site_*.html` が1枚増え、ブラウザに投げた後は誰も片付けません。次に取り込むついでに**6時間より古いものを消します**（付箋の受け渡し PNG が5分なのに対して長いのは、こちらはタブが生きている限り再読み込み（F5）の対象で、消すとタブが白くなるためです）。
- **履歴の保存は「指定キーだけを書き戻す」**作法です。メモリ上の設定は既定値をマージ済みなので、丸ごと書き出すと未設定の既定値まで `settings.json` に書かれて姿が変わります（`launcher.save_bookmark` と同じ）。
- **入力に `picker.py` は使いません。** あれは「用意された一覧から1つ選ぶ」窓で自由入力の口がなく、ここで欲しいのは毎回違う文字列だからです。ただし「同じサイトをもう一度」は頻繁に起きるので、履歴があるときは `QInputDialog.getItem(..., editable=True)` の編集可能なコンボボックスにして、選ぶことも打ち直すこともできるようにしています。ダイアログには `Qt.WindowStaysOnTopHint` を足しています（呼び元にタスクバーウィジェットがあり、あれは枠なし・最前面の窓なので、素のダイアログだとその陰に隠れて「押したのに何も起きない」ように見えます）。

## フォルダブックマーク（あふｗ／エクスプローラ）

登録したフォルダを絞り込んで選ぶと、そのフォルダへ移動します。`Ctrl+Alt+B`（既定）またはメニューから開きます。ウインドウの操作は定型文と同じです（同じ選択ウインドウ `picker.py` を使っています）。

移動先は二画面ファイラ **[あふｗ](https://akt.d.dooo.jp/afxw.html)** と、Windows の**エクスプローラ**の2つです。どちらへ送るかは `settings.json` の `launcher.target` で決めます。

| `launcher.target` | 動作 |
|---|---|
| `auto`（既定） | **ブックマークを開いた時点で前面だったウィンドウ**がエクスプローラなら、その窓を移動させる。それ以外（あふｗ・ブラウザ・エディタなど何でも）ならあふｗへ送る |
| `afxw` | 常にあふｗへ送る（この機能を足す前の動作） |
| `explorer` | 常にエクスプローラ。前面がエクスプローラでなければ**新しい窓を開く** |

**判定に使うのは「開いた時点」の前面ウィンドウです。** ピッカーが出た瞬間に前面はピッカー自身へ移るので、`ScreenFeature.start_launcher()` の**いちばん最初**に `GetForegroundWindow()` で掴んでから `launcher.create_picker()` へ渡しています（ホットキー・メニュー・IPC の3経路すべて同じ）。前面が取れない場合は掴まなかったことにして、従来どおりあふｗへ落ちます。

エクスプローラを移動させるときは**新しい窓を開かず、今見ている窓の中身を差し替えます**（あふｗの `-s -p` と同じ考え方）。ピッカーを開いている間にその窓が閉じられていた場合や、移動に失敗した場合は新しい窓を開きます（黙って何も起きないのが一番困るため）。

あふｗへの移動は `AFXW.EXE -s -p"パス"` の形で呼び出します。`-s` は二重起動せず既存のあふｗに渡す指定、**小文字の `-p`** は「そのフォルダの中を表示」です（大文字の `-P` は親フォルダを開いてカーソルを合わせる別の動作なので使いません）。`launcher.afxw_path` の実行ファイルが見つからない場合は、その旨を通知します。

登録は `settings.json` の `launcher.bookmarks` に貯まります。**削除・並べ替え・名前の変更は `settings.json` を直接編集してください**（定型文をフォルダに置くのと同じで、専用の編集UIは持ちません）。

### エクスプローラとのやり取り（`explorer_nav.py`）

エクスプローラが今どこを開いているかは、`Shell.Application` の `ShellWindows`（COM）越しに読みます。`explorer_nav.py` がその窓口で、トレイアイコンは持ちません（`window_tools.py` と同じ立ち位置）。実装で踏んだ点：

- **パスは `LocationURL` から組み立てます。** `w.Document.Folder.Self.Path` で直接取る手もありますが、comtypes の遅延バインディングでは `AttributeError` になって届きません。
- **`file:///C:/Users/...` は URL エンコードされています。** 日本語やスペースを含むパスは `%E3%83%89...` の形で入っているので、`unquote` を通さないと化けたパスができます。
- **`file:` 以外は対象外です。** コントロールパネル・ごみ箱・「PC」などの特殊フォルダ（`::{GUID}` 形式）はパスが無いものとして扱います。
- **`ShellWindows` はエクスプローラと Internet Explorer の両方を列挙します。** `FullName` が `explorer.exe` で終わるものだけを見ます（IE に `Navigate` すると見当違いのページを開かせてしまうため）。
- **`comtypes.COMError` は `OSError` のサブクラスではありません。** 両方を捕まえないと素通りします（`mic_control.py` と同じ罠）。ここの関数は例外を投げず、取れなければ `None`／失敗なら `False` を返します（**PySide6 はスロットから例外が抜けると常駐アプリごと終了する**ため）。
- **COM オブジェクトは呼ぶたびに作り直します。** エクスプローラを再起動すると以前の参照は無効になり、以後ずっと `COMError` を返す抜け殻になります。ブックマークを選んだときにしか呼ばない＝1操作につき1回なので、掴み続ける価値がありません。

対象とみなすのはウィンドウクラスが `CabinetWClass` のフォルダウィンドウだけです（デスクトップや「ファイルを開く」ダイアログは別クラスなので動かしません）。

### 「＋ ここを登録」

一覧の末尾に **「＋ ここを登録   `<いま見ているパス>`」** が並ぶことがあります。選ぶと名前を尋ねられ（既定はフォルダ名）、`launcher.bookmarks` に追記されます。パスの決め方は次の優先順位です。

1. IPC で渡されたパス（あふｗが `$P` で明示してきたカレント）
2. 前面のエクスプローラが開いているパス
3. どちらも無ければ、この項目は出ません

つまり**ホットキーやメニューから開いた場合でも、前面がエクスプローラなら登録できます**（あふｗから呼んだときだけ、という制限は無くなりました）。登録項目を全角の `＋` で始めているのは、英字を打った時点で候補から外れるようにするためです（ブックマークを選ぶつもりで `Enter` を押して誤登録するのを防ぎます）。

### 入力欄でできること

絞り込みのほかに、打った文字がフルパスならそこへ移動できます。フォルダの直下も一覧に出るので、キーボードだけで掘り下げられます。

| 打つ/押す | 起きること |
|---|---|
| フルパス | `→ このパスを開く` が先頭に出る。ファイルのパスならその置き場所を開く。引用符・`%USERPROFILE%`・`~`・`/` 区切りも受ける |
| 途中まで | その親の直下を前方一致で絞り込む（`📁` の行） |
| `Tab` | 選択中のフォルダの中へ潜る（ブックマークの行でも効きます） |
| `Ctrl+D` | 選択中のブックマークを削除（確認あり） |
| `Ctrl+↑` / `Ctrl+↓` | 選択中のブックマークを並べ替え。どちらも `settings.json` へ即保存 |

**ネットワークドライブと UNC では、存在確認もフォルダの列挙もしません。** 相手が落ちていると `isdir` / `scandir` は数秒ブロックし、1文字打つごとに走るこの経路が止まると入力そのものが固まるためです（ドライブの種別は `GetDriveTypeW` で見ます。割り当て表を引くだけなのでサーバには触りません）。大きいフォルダは 200 件で列挙を打ち切ります（実測: `C:\Windows\WinSxS` は上限なしで 3,049ms、打ち切ると 4.9ms）。

削除したブックマークは `bookmark_deleted.log` に1行1件で控えます（`{"time": ..., "name": ..., "path": ..., "index": ...}`）。`settings.json` は世代バックアップを取らないので、誤って消したときはこの控えから手で戻します。`index` は**消した時点の並びでの位置**なので、複数件を戻すときは新しい行から順に当ててください。

### あふｗから呼ぶ（`$P` で今いるフォルダを渡す）

あふｗ側からはコマンド送信用の極小スクリプト `traytools_send.py` を叩きます。`AFXW.key` に次のように書きます（`$P` はあふｗのカレントパス）。

```
K00xx="4074C:\Users\<ユーザー名>\.venvs\tray-tools\Scripts\pythonw.exe R:\claude\tray-tools\traytools_send.py bookmark "$P""
```

`traytools_send.py` は **PySide6 を import しません**。Qt の import だけで1秒近くかかり、キーを押してからウインドウが出るまでの体感がそのぶん遅くなるためです（標準ライブラリだけで書いてあります）。tray-tools が起動していない場合は標準エラーにメッセージを出して終わります（**勝手に常駐アプリを起動したりはしません**）。

### 外部からのコマンド受付（IPC）

多重起動を防ぐための待ち受け（`QLocalServer`／Windows では名前付きパイプ `\\.\pipe\traytools.single-instance`）が、そのまま外部コマンドの入口を兼ねています。接続して**UTF-8 の JSON を1行**書くと、常駐中の本体がその機能を開きます。

```json
{"command": "bookmark", "args": ["C:\\いまのパス"]}
```

| `command` | 動作 |
|---|---|
| `bookmark` | フォルダブックマークを開く。`args[0]` があれば、そのパスで「ここを登録」を添える（無い場合は前面のエクスプローラから読む） |
| `keep-awake` | スリープ抑止の入切。`on` ／ `on 90`（90分だけ）／ `off` |
| `sleep` | スリープ・休止の予約。`1800`（30分後）／ `1800 hibernate` ／ `cancel` |
| `status` | いまの状態（抑止・予約・画面ミラー・付箋の枚数・ジグラー）を返す |
| `log` | 操作ログ（`action.log`）の末尾を返す。`args[0]` で行数（既定20、上限500） |
| `notify` | トーストを1枚出す。引数は繋いで本文にし、`\n` の2文字は改行に直す |
| `beep` | 音を1つ鳴らす。`ok` ／ `done` ／ `warn` ／ `error` ／ `ask` |
| `pushover` | スマホへプッシュ通知。`<本文> [--title T] [--priority N] [--sound S]` |

何も書かずに切れた場合は、従来どおり「すでに起動しています」と通知します（＝ただの二重起動）。知らない `command` は通知で知らせるだけで、常駐は続きます。

**この表を増やすときの線引き。** ここは外から叩ける口で、**増やすほど誤操作の被害が広がります**。足してよいのは「常駐しているこのプロセスでなければできないこと」だけです。アプリの起動やファイル操作のたぐいは足しません——呼ぶ側が直接できるので常駐を経由させる利点が無く、口を通る危険だけが増えます。

### 応答（この口は双方向）

**以前この口は一方向で、送った側は結果を受け取れませんでした。** 予約が入ったのか引数を間違えて無視されたのかが分からず、「エラーが出ていないから多分成功」という確かめ方しかできず、実際には `action.log` を直接読んで確かめていました。いまは**1接続につき1つ応答**を返します。

```
1行目 : "OK ..." なら成功／"ERR ..." なら失敗（後ろに1行の要約が付くことがある）
2行目〜: 本文（status / log のように中身を返すコマンドだけ）
書き終わったら本体側が切断するので、受け取る側は EOF まで読めばよい
```

```
> python traytools_send.py keep-awake on 90
OK スリープ抑止: 有効（残り90分）

> python traytools_send.py sleep あああ
ERR 秒数を解釈できません: あああ（何もしませんでした）

> python traytools_send.py status
OK
スリープ抑止: なし
スリープ予約: なし
画面ミラー: 停止中
付箋: 1枚
マウスジグラー: なし
```

`traytools_send.py` は応答をそのまま標準出力へ出し、`OK` なら終了コード 0、`ERR` なら 1 を返します。**応答が来ないまま時間切れになった場合は 0 で終わります**（応答を返さない古い本体が常駐していても、あふｗからの呼び出しが失敗扱いにならないようにするため）。

実装で押さえている点：

- **応答を読まずに切る客が居ても壊れません。** 相手が居なくなった `QLocalSocket` への書き込みは例外にならず `-1` を返すだけなので、この機能を足す前の送り方（書いて即閉じる）のままでも本体は何事もなく次へ進みます。
- **名前付きパイプは双方向です**（`QLocalServer` は `PIPE_ACCESS_DUPLEX` で開く）。`traytools_send.py` は同じハンドルを `r+b` で開いて書いて読みます。**PySide6 は相変わらず import しません**（Qt の import だけで1秒近くかかる＝このスクリプトの存在理由）。
- **読み取りは別スレッドへ追い出しています。** 名前付きパイプの読み取りに時間切れは無く、応答を返さない相手に当たると永久に待つことになるため、待つ側で見切れるようにしています（デーモンスレッドなので残したまま終われる）。
- **ソケットは応答を書いてから閉じます。** ハンドラが別スレッドを使う場合（`pushover`）は `_handle_connection` を抜けたあとに書かれます。応答役（`main._Reply`）は**モジュール側の集合で参照を保持**します（ローカル変数だけだと GC で消え、応答が返らなくなる）。忘れられた接続は20秒で回収します。
- **応答はシグナル経由で必ずメインスレッドから書きます。** ソケットに触ってよいのは作ったスレッドだけなので、ワーカーから直接書きません。

### スマホへプッシュ通知（`pushover.py`）

トーストは目の前の画面にしか出ません。長い処理を回して席を外しているときに終わりを知る手段として **[Pushover](https://pushover.net/)** へ投げます。API は POST が1本あるだけなので `urllib` で足り、**依存は増やしていません**。

```
python traytools_send.py pushover "変換が終わりました" --title 変換 --priority 1
```

タイトルを位置引数にせず `--title` にしているのは、本文の続きと見分けが付かないためです。`--priority` は **1（高）が上限**です（2＝緊急は `retry`／`expire` が要るうえ、受け取る側が確認するまで鳴り続けるので、外から叩ける口で出せる強さではありません）。

**送信は別スレッドで行います。** ネットワークは数秒かかりうるので、Qt のメインスレッドで待つとトレイも付箋もホットキーも全部固まります。応答は送信が終わってから返ります（`traytools_send.py` 側もこのコマンドだけ待ち時間を長くしてあります）。

#### トークンは `settings.json` に書かない

`settings.json` は手で編集する前提の平文ファイルで、そこへ API トークンを書くとバックアップにも差分にもそのまま乗ります。**Windows の資格情報マネージャ**へ預けます（`credential_store.py`）。

- 登録・削除はトレイメニューの **「📱 スマホ通知（Pushover）」** から。**入力欄は User Key・API Token とも伏せ字（`QLineEdit.Password`）です。**
- 資格情報マネージャ上の名前は **`traytools:pushover`**（種類は「汎用資格情報」）。`UserName` に User Key、秘密のブロブに API Token を入れます。
- **未登録なら送信を試みずに `ERR` を返します**（無効なトークンで叩いて 4xx をもらうだけなので、通信する前に断る）。
- **ログにも通知にもトークンは出しません。** `action.log` に残るのは「登録した」「送った（本文の文字数）」という事実だけです。
- `keyring` は入れていません。必要なのは `advapi32` の `CredWriteW` ／ `CredReadW` ／ `CredDeleteW` の3つだけで、`ctypes` で直に叩けば依存が増えません。ブロブの文字コードは `keyring` の Windows バックエンドに合わせて **UTF-16LE** にしてあるので、あとで `keyring` を入れても同じ資格情報を読めます。
- `CredReadW` が返す領域は API 側の持ち物です。**必要な値を Python の文字列へ写してから必ず `CredFree` で返します**（忘れると呼ぶたびに漏れます）。

### 音で知らせる（`beep.py`）

トーストより強い合図です。画面を見ていなくても気づけます。`winsound.MessageBeep` を1回呼ぶだけで、鳴る音はシステムのサウンド設定に従います（消してあれば鳴りません。こちらで音量やデバイスは触りません）。

`winsound.Beep(周波数, 長さ)` は**使いません**——鳴り終わるまで戻らないので、その間 Qt のメインスレッドを止めてしまいます。知らない名前を渡したときは**鳴らさずに `ERR`** を返します（勝手に別の音を鳴らすと、何を知らせたのか分からなくなるため）。

## あっふ（Affx）（`filer.py` / `filer_core.py` / `filer_shell.py` / `filer_launch.py`）

**あふｗ（AfxW）を入れられない PC でも、あふｗと同じ指の動きでファイルを扱うための2画面ファイラです。** 名前はあふｗへのオマージュで「あっふ（Affx）」。キー割り当ては、あふｗ標準にユーザー自身の `AFXW.key` のカスタマイズを重ねたものに寄せてあります。

| 入口 | |
|---|---|
| 画面アイコンの「あっふ…」（専用アイコン付き） | 開く。**既に開いていれば新しく起こさず前面に出す**。ホットキーは既定で無し（開きっぱなしで使う前提。以前の `Ctrl+Alt+A` は Claude のデスクトップアプリの「アーカイブ」と重なったので外した。`hotkeys.filer` で割り当てられる）。アイコンは本家 AfxW のアイコン（白地・上に青文字・下に黒のドット明朝）に寄せたもので、`affx_icon.py` が画素の文字マップとして持ち、窓・タスクバーにも同じものを使う |
| `pythonw filer.py` | 単体でも起動できる |

窓は**別プロセス**（`pythonw.exe` + `DETACHED_PROCESS`）で開きます。ファイル操作（`SHFileOperationW`）は終わるまで呼んだスレッドを止めるので、常駐のメインスレッドで呼ぶとその間ホットキーも付箋も止まるためです。常駐を再起動しても、開いているファイラは道連れになりません。

- **開いているかの判定**は名前付きミューテックス（`Local\traytools.filer`）。前面に出す依頼だけを `QLocalServer`（`traytools.filer`）で届ける（判定には使わない。[CLAUDE.md](CLAUDE.md)「単一起動の判定」）
- **COM は使いません。** コピー/移動/削除は `SHFileOperationW`（上書き確認・進捗・ごみ箱・元に戻すは Windows 標準のもの）、デスクトップは `SHGetKnownFolderPath`、どちらも ctypes。コンテキストメニューのような COM が要る機能は入れていません
- **一覧の読み取りは毎回別スレッド**で、`filer.list_timeout_seconds`（既定5秒）で見切ります。UNC や切断されたネットワークドライブで窓が固まらず、見切ったら元のフォルダに留まってメッセージ窓に出します。アクセス拒否も同様
- **表示中のフォルダは自動で監視**します。2秒ごとに別スレッドで中身の指紋（名前・サイズ・更新時刻）を取って比べ、外部（エクスプローラ・他のアプリ・同期ツール）で変わっていたら、その窓だけ再読込します。カーソルは名前で戻り、マークは保持します。フォルダ自体が消えたら親へ遡ります。モーダル表示中・名前変更や絞り込みの入力中・ドラッグ中は見送ります。対象は通常のフォルダだけで、書庫の中・フラット表示・検索結果は監視しません（フラットは配下全部が対象で重く、検索結果は問い合わせの写しなので、要れば `F5` で再読込）
- 窓の位置・大きさ、左右のパス、窓ごとの並べ方、フォルダ履歴は `settings.json` の `filer` に**キーだけ差し替えて**保存し、次回復元します。保存したパスが消えていれば残っている親まで遡り、全部だめならユーザープロファイル
- J のブックマークは**フォルダブックマーク（`launcher.bookmarks`）をそのまま使います。** 入力欄にフルパスを打てる・Tab で掘れるのも同じ。ただし `launcher` は `explorer_nav` 経由で comtypes を読み込むので、**J を初めて押したときに読み込みます**（ファイラの起動を軽く保つため。COM のオブジェクトは作りません）

### 画面

あふｗの画面と同じ並びです。上から、左右2つのファイル窓、メッセージ窓（操作のログ）、ファンクションキーの段、ステータスバー。メッセージ窓はマウスで範囲選択でき、選択中は `Ctrl+C` でその文字列をコピーできます（選択が無いときの `Ctrl+C` は従来どおり頭文字ジャンプ）。

```
┌ C:\Program Files\ *.*      ┐┌ C:\Users\...\Desktop\ *.*   ┐  ← 1行目: パスとマスク(常に)
│ Windows                    ││ Windows                     │  ← 2行目: ドライブのラベル
│ 7-Zip     <DIR> 26/04/09 … ││ ..                          │
│ …                          ││ …                           │
│ 58 Dirs   0 File   475.69 GB ( 100.38 GB)                  │  ← 件数・容量(空き)・マーク
└────────────────────────────┘└─────────────────────────────┘
  メッセージ窓
 [    ][    ][    ][    ][    ][    ][Menu][    ][PowerShell][Explorer][    ][    ]  ← F1〜F12
 Ready.   7-Zip              <DIR>   26/04/09 19:52:53   D         ← 状態・名前・大きさ・日時・属性
```

- **窓の上の2行**: 1行目はパスとマスク（`C:\Program Files\ *.*`。書庫の中なら書庫の中のパス。並べ方が既定以外ならその印、Shift+Z で隠しているものがあれば `〈隠/シ 非表示〉` も右に足す）。2行目はドライブのボリュームラベル（無ければ「ローカル」「ネットワーク」などの種別、UNC なら `server\share`、書庫の中なら書庫のあるドライブ）。アクティブな窓はこの2行の地と枠が青
- **窓の下の行**: `58 Dirs   0 File   475.69 GB ( 100.38 GB)`（あふｗの書式。ファイルは1件以下なら File、2件以上なら Files。`..` は数えない）。容量はドライブの総容量、括弧の中は空き。マークがあれば後ろに `Mark 3 (12,345)`（件数と合計バイト）。書庫の中は件数だけ。インクリメンタルサーチ中は入力中の文字も
- **ラベルと容量は別スレッドで読みます**（`GetVolumeInformationW` / `GetDiskFreeSpaceExW`）。切断されたネットワークドライブで止まっても、窓は止まらずその欄が空のままになるだけです。ラベルはドライブごとに一度だけ読んで覚え、容量は読み直し（ファイル操作の後を含む）のたびに読み直します
- **ファンクションキーの段**: F1〜F12 の12区画に、そのキーに割り当てたコマンドの短い名前（`filer_core.COMMAND_SHORT_NAMES`）を出します。キー表（`filer.keys` の上書き込み）から作るので、割り当てを変えれば表示も変わり、割り当ての無いキーは空欄です。**Shift / Ctrl を押している間はその修飾付きの割り当てに切り替わります**（あふｗと同じ。Alt は Alt+F4 の終了くらいしか無いので切り替えない）。区画をクリックすると、そのキーを押したのと同じコマンドが走ります（ファイル窓のマウスは効かない方針とは別の、明示的なボタン。フォーカスはファイル窓に残る）。表示名だけを `filer.fkey_labels` で上書きでき（`{"F7": "右クリ", "Shift+F10": "再読込"}`）、段ごと `filer.show_fkey_bar` で隠せます
- **ステータスバー**: 左から、状態（待機中は `Ready.`、展開・圧縮・複写などの最中は `展開中 3/10` のように）、アクティブ窓のカーソルの名前、`<DIR>` か大きさ（3桁区切り）、日時、属性（D=フォルダ R=読み込み専用 H=隠し S=システム A=アーカイブ）。`..` の上では名前だけ。色は `filer.colors` の `status_background` / `status_text`（Fキーの段は `fkey_background` / `fkey_text` / `fkey_border`）
- 2行目・下の行・Fキーの段・ステータスバーの字はメッセージ窓と同じ基準の大きさ、1行目は窓ごとの一覧の字。どれも高さは字の高さちょうどで、長い文字列でも窓の最小幅を押し広げません

一覧は `..`（ルートでは無し）→ フォルダ → ファイルの順で、列は 名前 / 拡張子（`.url` のように点付き）/ サイズ（フォルダは `<DIR>`）/ 更新日時 `yy/mm/dd HH:MM:SS`（あふｗと同じ書式）。長い名前は名前の側を `…` で省き、拡張子は必ず見えるようにします。窓が狭いときは日時 → サイズ → 拡張子の順に列を隠します。

配色の既定は本人のあふｗの「表示色」設定に合わせてあります。濃紺の地（`#00001c`）に、通常ファイルは白・システムは灰・隠しはやや暗い灰・読み込み専用はピンク寄りの赤（`#ff0080`）・フォルダは属性に関係なく水色（`#80ffff`）。**カーソル行は背景を塗らず下線だけ**（アクティブ窓はシアンの太線、非アクティブ窓は暗く細い線）、マークした行は灰色のグラデーションの背景（字の色はそのまま）。カーソルがマーク行に乗るとマーク背景＋下線。色は `filer.colors` で1色ずつ上書きできます（名前は `filer.DEFAULT_COLORS`）。

**拡張子別表示色**（あふｗの「各種登録 > 拡張子別表示色」）: **色が付くのは拡張子の列だけ**で、名前は種類の色のままです。隠し・システム・読み込み専用の行は行全体の属性色を優先し（`desktop.ini` が行全体灰色になるのと同じ）、フォルダにも付けません。既定はあふｗの設定画面から拾った色で、上の行が勝ちます。`Z` の設定ダイアログで変えられ、`filer.ext_colors` に保存されます。

### 設定（`Z` / `filer_settings.py`）

あふｗの `Z`（設定プログラム起動）に当たる設定ダイアログです。将来ほかの設定も入れられるようタブにしてあり、いまは「拡張子別表示色」だけです。

- 「登録内容」の一覧（左に色の帯、右に拡張子を空白区切り。長いものは … で省略）、その下に [新規(N)] [変更(C)] [削除(D)] と右寄せの [上(U)] [下(S)]、「表示色」の枠に [色(X)]、最下段に [初期値(R)] [決定] [中止]。`Alt+頭文字` で押せます。一覧の上では `Enter` で変更、`Del` で削除
- 新規・変更では拡張子を空白区切りで入れます（`*.Zip .7z` のような書き方も、点や `*` を除いた小文字に揃える）。ほかの行にもある拡張子は「ほかの行から外しますか」と尋ねます（外さなければ上の行の色が使われる）。色は Windows の色の選択画面。削除と初期値は確認付き
- **決定**で `settings.json` の `filer.ext_colors` だけを書き換え、両窓をその場で描き直します（読み直しは不要）。**中止**なら何も変わりません
- この画面は Windows 標準の見た目のままにしてあります（ファイラの濃紺に寄せると、色の帯の見え方が地の色に引っ張られて判断しにくいため）。ダイアログの中ではマウスも普通に使えます

| `R` | ファイル情報の編集（名前・大小の変換・更新日時・属性）。マークがあれば一括変更（下の節） |
| `Shift+R` | 一括改名（Renemo 風。下の節） |
| `Alt+R` | 改名メニュー（先頭が一括改名なので `Alt+R` → `Enter` で開く。あふｗで Renemo を起こしていたのと同じ指。2番目は `R` と同じファイル情報の編集） |
| `Ctrl+Ins` / `Ctrl+Del` | クリップボードへファイルを「コピー」/「切り取り」（エクスプローラに貼れる） |
| `Shift+Ins` | クリップボードのファイルを貼り付け（切り取りなら移動。同じフォルダへのコピーは別名で複製） |
| `Alt+←` `Ctrl+←` / `Alt+→` `Ctrl+→` | 左右の窓の境界を左へ / 右へ（1回で窓幅の3%。片方が15%より細くならない）。Ctrl+←→ は本人の `AFXW.key` の置き換え（`2037:4037` / `2039:4039`） |
| `Alt+↑` / `Alt+↓` | メッセージ窓を1行大きく / 小さく（1行〜窓の半分ほど） |
| `Shift+↑` `Ctrl+↑` / `Shift+↓` `Ctrl+↓` | アクティブ窓の一覧の字を小さく / 大きく（左右別々。8〜32pt。行間は空けず、行の高さは字の高さちょうど）。本人の `AFXW.key` で INS（縮小）/ DEL（拡大）に置き換えている割り当て |
| `F9` | いまのフォルダで PowerShell を新しい窓で開く（`filer.shell` で `pwsh.exe` などに変えられる）。書庫の中なら書庫のあるフォルダ |
| `F10` | いまのフォルダをエクスプローラで開く。書庫の中なら書庫のあるフォルダ |
| `F7` | エクスプローラの右クリックメニュー（下の節）。対象はマーク、無ければカーソル行、`..` の上ならいまのフォルダ自身。本人の `AFXW.key` の F7（`0118:0226`）と同じ |
| `Q` / `Alt+F4` | 閉じる（状態を保存） |
| `Esc` | 各処理の中止だけ（サーチの終了・ダイアログの取消）。**窓は閉じない**（あふｗと同じ） |

`C` / `M` / `Shift+Z` / `Alt+R` のメニューは**先頭の項目が選ばれた状態**で開くので、`Enter` 一発で先頭（反対窓へコピー/移動など）が実行できます。**文字キーはその項目を選ぶだけで、実行はしません。**たとえば `C` → `P` では「フルパスをクリップボードへ」が選ばれるだけで、コピーは `Enter` を押して初めて行われます（クリックでも実行できます）。

**マウスは基本的に効きません**（あふｗと同じく、対象はキーで決める）。ファイル窓のクリック・ダブルクリック・右クリックではカーソル行は動かず、何も実行されません。ただし**クリックした側のファイル窓がアクティブになります**（窓の切り替えだけはマウスでもできます。Tab の代わりとして）。ホイールは一覧のスクロールで、カーソル行は基本動きません。ただしカーソルが画面の外へ出そうになると、画面に見えている端の行（上へ外れるなら一番上、下へ外れるなら一番下）へ付いてきます（あふｗと同じ）。左右・上下の境界はドラッグで動かせます。

**ドラッグ&ドロップは送り出しだけ**：ファイル窓の上でドラッグすると、**マークしたもの**を外のアプリ（エクスプローラ・メールなど）へ運びます。押した位置の行もカーソル行も運ばず、**マークが無ければドラッグは始まりません**。既定はコピーで、落とし先が移動を選んだときに備えて終わったら両窓を読み直します。書庫の中からはドラッグできません。ファイラへのドロップ（受け取り）はありません。

左右の境界（`filer.split_ratio`）・メッセージ窓の行数（`log_lines`）・左右それぞれの一覧の字の大きさ（`left_font_size` / `right_font_size`。無ければ以前の共通の `font_size`）は、キーで変えてもドラッグで変えても、閉じるときに保存して次回に戻します。

キーは `filer.keys` で上書きできます。あふｗの `AFXW.KEY` と同じ4桁（前1桁が `SHIFT=1` / `CTRL=2` / `ALT=4` の和、後3桁が仮想キーコード）をキーに、コマンド名（`filer_core.DEFAULT_KEYMAP` の値）を書きます。空文字でその割り当てを外せます。

```json
"filer": { "keys": { "0071": "edit", "0046": "" } }
```

#### ソート（`S`）

タイトルは「ソート(左)」/「ソート(右)」。**先頭の文字を押すと即決定**（あふｗと同じ）、`↑↓` で選んで `Enter` でも決定できます。`Esc` で取消。今の種類は枠で示します。

| キー | 並べ方 |
|---|---|
| `N` | ソートなし（OS の列挙順） |
| `F` | ファイル名 |
| `E` | 拡張子名（同じ拡張子の中は名前順） |
| `S` | サイズ |
| `T` | タイムスタンプ |
| `A` | 属性 |
| `X` | ファイル名(番号)＝自然順（`file2` < `file10`） |
| `←` `→` / `Tab` | 昇順 / 降順の切り替え |
| `G` | フォルダを上に集める（既定 ON。降順でもフォルダは上のまま） |
| `C` | 大文字小文字区別無し（既定 ON） |

並べ方は**窓ごと**に持ち、閉じるときに `filer.left_sort` / `right_sort` へ保存します。`..` は常に先頭。

#### 同名ファイル比較マーク（`W`）

反対窓に同名（大文字小文字は無視）のものがあれば、アクティブ窓の側をマークします。**ファイルとフォルダの組でも同名ならマーク**、フォルダ同士は「フォルダ同士も同名があればマーク」が ON のときだけ（そのときは条件を見ずにマーク）。**左右が同じフォルダなら何もしません**（ダイアログも出さず、メッセージ窓に一言だけ）。あふｗの `AFXW.TXT`「同名ファイル比較マークについて」に合わせてあります。

| 操作 | |
|---|---|
| `↑↓` / `←→` | 行の移動 / その行の選択肢（サイズ: 小さい・大きい・異なる・無関係・同じ、タイムスタンプ: 古い・新しい・異なる・無関係・同じ。既定はどちらも無関係） |
| `Space` | 「フォルダ同士も同名があればマーク」の切り替え（`filer.compare_include_dirs` に覚える） |
| `Enter` | 決定。最下行「除：拡張子」で決定すると拡張子を除いた名前で比べる（候補が複数ありうるのでサイズ・時刻の条件は無効） |
| `A` / `N` / `S` / `T` / `E` | 条件プリセットの選択（決定は `Enter`）: サイズも時刻も同じ / どちらも異なる / サイズが同じ / 時刻が同じ / 除拡張子 |
| `Shift` を押しながら決定 | 逆に、該当するもののマークを外す |
| `Esc` | 取消 |

「小さい/古い」はアクティブ窓の側が反対側より小さい/古い、の意味。時刻は `filer.time_tolerance_sec`（既定2秒。FAT は2秒刻み、ネットワーク越しでもずれる）以内の差を「同じ」とみなし、古い/新しい/異なるもこの誤差を超えたときだけ成り立ちます。Shift なしで決定したとき、既にマークがあれば「クリアしてからマーク／重ねてマーク／取消」を尋ねます。結果はメッセージ窓に「比較マーク: 12件」のように出ます。

### エクスプローラの右クリックメニュー（`F7` / `filer_contextmenu.py`）

**`F7` でエクスプローラと同じ右クリックメニューが、カーソル行の左下に出ます。** 「開く」「送る」「新規作成」「切り取り」「コピー」「削除」「プロパティ」、圧縮ソフトなどのシェル拡張の項目もそのまま並び、↑↓・Enter・Esc・下線付きの文字で操作できます。選んだ項目の処理は Windows（シェル拡張）に任せ、メニューが閉じたら両窓を読み直します（マークは残す）。複数マークしたときは、エクスプローラで複数選んで右クリックしたのと同じ1つのメニューになります。書庫の中では「書庫内ではコンテキストメニューは使えません」と出るだけです。

**メニューは子プロセス（`filer_contextmenu.py`）が出します。** このメニューは COM（`IShellFolder` / `IContextMenu`）でしか出せず、しかも開いた瞬間に、入っているシェル拡張（圧縮ソフト・クラウド同期・ウイルス対策など）がまるごとそのプロセスに読み込まれます。[CLAUDE.md](CLAUDE.md) のとおり COM の寿命の誤りはプロセスを跡も残さず即死させ、拡張側の不具合も同じ死に方をします。ファイラ本体に持ち込むと左右の窓ごと消えるので、ファイラ本体は COM を読み込みません（`import filer` で comtypes は読まれない）。子プロセスが落ちても「メニューが出なかった」とメッセージ窓に出るだけです。

- ファイラは対象のパス・画面座標（物理ピクセル）・自分の HWND を引数で渡し（多すぎるときは一時 JSON）、前面化の権利を譲ってから起こして、終わりは待たずに戻ります。終わりは別スレッドで待ち、シグナルで読み直します
- 子は OLE を初期化（STA）し、`SHParseDisplayName` → `SHBindToParent` → `GetUIObjectOf(IContextMenu)` → `QueryContextMenu` → `TrackPopupMenuEx(TPM_RETURNCMD)` → `InvokeCommand` と進めます。「送る」「新規作成」の中身は、メニューの持ち主にした非表示のトップレベル窓で `WM_INITMENUPOPUP` などを `IContextMenu3::HandleMenuMsg2`（無ければ `IContextMenu2::HandleMenuMsg`）へ渡して作らせます
- **プロパティ窓など、シェル拡張が処理を続ける窓のために、`InvokeCommand` の後は「このプロセスの見える窓が残っている間」待ちます**（窓が3秒出なければ終わる）。`SHSetInstanceExplorer` で参照を数える方法もありますが、Python で IUnknown を実装して COM オブジェクトをこちらが持つことになり、拡張が参照を返し忘れると終われなくなるので選びませんでした
- 「切り取り」「コピー」でクリップボードに載せたデータは子プロセスの持ち物なので、終わる前に `OleFlushClipboard` で実体にします（しないとプロセスと一緒に消える）
- COM の約束（`ctypes.cast` しない・COM オブジェクトを関数の外に出さない・`argtypes` / `restype` 必須）を守っています。`tests/test_com_gc.py` の cast の見張りの対象にも入ります
- 診断用に `python filer_contextmenu.py --list [--repeat N] -- パス...` で、メニューを組み立てて項目を標準出力に出して終わります（画面には何も出さない）。テストはこれで、gc.collect を挟んだ繰り返しでも落ちないことを確かめています
- 「名前の変更」はエクスプローラの表示の中でその場で名前を変える仕組みなので、ここからは効かないことがあります（ファイラの `R` を使ってください）

### 簡易テキストビュア（`filer_viewer.py`）

あふｗの簡易内蔵テキストビュアに当たるものです。**`Enter` で、拡張子が `filer.viewer_extensions`（既定: log txt csv tsv md json xml ini cfg conf yaml yml py ps1 bat cmd sql html htm css js ts c h cpp java sh）にあるファイルを開きます。** それ以外は従来どおり関連付け、`Ctrl+Enter` は常に関連付け、`E` / `V` / `Shift+Enter` はエディタのままです。書庫の中のファイルは一時フォルダへ取り出してから開きます（題名は書庫の中のパス）。

- ファイラと同じプロセスの別窓で、ファイラを止めません。いくつ開いてもよく、閉じるとファイラへ戻ります。窓の位置と大きさは `filer.viewer_geometry` に覚えます。配色はファイラと同じ濃紺の地に白、字はアクティブ窓の大きさから始まります
- **何百 MB のログでも固まらないように作ってあります。** 全文は読み込みません。別スレッドで「行の始まりの位置」の索引だけを作り（手元で50万行・約13MB が0.2秒弱）、画面には見えている行だけをその都度ファイルから読んで描きます。索引を作っている最中もスクロールでき、題名とステータス行に進み具合が出ます。1行が 64KB を超える分は表示しません
- 検索も別スレッドで、数千行ずつまとめて読んで当たりを付けます（大文字小文字は無視）。ヒットした行へ移り、その箇所を色で示します。検索中の `Esc` は検索の中止です
- 文字コードは BOM（UTF-8 / UTF-16LE / UTF-16BE）→ 先頭 4MB が UTF-8 として正しいか → cp932 の順に決めます。読めないバイトは置換文字で出します
- 折り返しはせず、横はスクロールです

| キー | 動作 |
|---|---|
| `Enter` / `Esc` / `Q` / `BS` | 閉じる（`BS` は本人の `AFXW.key` の TVIEW の置き換え。検索中の `Esc` は検索の中止） |
| `↑` / `↓` | 1行スクロール |
| `PgUp` `←` / `PgDn` `→` | 1ページ |
| `Home` `Ctrl+PgUp` `Ctrl+←` `F1` / `End` `Ctrl+PgDn` `Ctrl+→` `F2` | 先頭 / 末尾（索引の途中なら、分かっている所まで） |
| `J` `F3` | 行番号を指定してジャンプ |
| `F` `F4` / `Shift+F` `B` `Shift+F4` | 検索語を入れて下へ / 上へ |
| `Space` `L` `F5` / `Shift+Space` `H` `Shift+L` `Shift+F5` | 下方次検索 / 上方次検索 |
| `Shift+O` / `S` / `U` / `I` / `E` / `J` | UTF-8 / SJIS(cp932) / UTF-16LE / UTF-16BE / EUC-JP / JIS で読み直す |
| `Shift+N` | 行番号の表示を切り替える |
| `2` / `4` / `8` | タブ幅 |
| `Shift+↑` `Ctrl+↑` `Ins` / `Shift+↓` `Ctrl+↓` `Del` | 字を小さく / 大きく（ファイラと同じ割り当て。`Ins` / `Del` はあふｗ標準） |
| `E` / `Shift+Enter` | エディタで開く（`filer.editor`） |
| `Ctrl+C` | **画面に見えている行**をまとめてクリップボードへ（キャレットや範囲選択は持たないので、見えている所を写す） |

### ライブ絞り込み（`/`）

XYplorer の Live Filter / yazi の filter に当たるものです。`/` で窓の下に入力欄が出て、**打つたびにアクティブ窓の一覧を「名前にその文字列を含むもの」だけに絞ります**（大文字小文字は無視、空白区切りで AND、フォルダは常に残す）。

- `Enter` で確定（絞ったまま入力欄を閉じ、ふだんの操作に戻る。パス表示に `[絞込: 文字列]`）。`Esc` で解除。確定した後に `/` でもう一度直せます。入力欄が閉じているときの `Esc` では解除しません（Esc は中止だけ、の方針）
- 解除は `/` → 空にして `Enter`、`:`（マスクを `*.*` に戻す）、フォルダの移動でも
- マスク（`Shift+:`）とは別に重ねがけできます。カーソル・マーク・ソートは絞った一覧で普通に動きます
- **絞り込みで見えなくなったマークは消さずに持っておきますが、コピー・削除などの対象になるのは見えているマークだけ**です（見えないものまで消したりコピーしたりしないよう、安全な側に倒した）
- 3,000 件を超える一覧では、打ち終わりを 0.15 秒待ってから絞ります（数万件でも打鍵ごとに並べ直さない）

### よく行くフォルダ（`Shift+H`）

zoxide と同じ考え方（frecency）で、よく・最近行ったフォルダへ飛びます。

- フォルダを移るたびに、パスごとの回数と最後に訪れた時刻を記録します（再読込は数えない。書庫の中は記録しない）。スコアは「回数 × 最近さ」（1時間以内 ×4、1日以内 ×2、1週間以内 ×0.5、それより前 ×0.25）。500件を超えたらスコアの低いものから間引きます
- `Shift+H` で選択窓が出て、打った語（空白区切り）を**すべて含む**パスをスコアの高い順に並べます。**最後の語がフォルダ名（パスの末尾）に入るものが先**（zoxide と同じ。最後に打つのはたいてい行き先の名前なので）。`Enter` でアクティブ窓をそこへ
- ローカルの固定ドライブでもう無いフォルダは候補から外し、記録からも消します。ネットワーク上のものは開いてみて開けなければ消します（確かめに行くと止まりうるため）
- **記録はリポジトリの外（`%LOCALAPPDATA%\traytools\filer_frecency.json`）に置きます。** このリポジトリは公開なので、訪れたフォルダの一覧をうっかりコミットしないよう、作業ツリーの中には作りません（`.gitignore` に頼らない）。一括改名の履歴も同じ場所です
- `H`（履歴ジャンプ）と `J`（ブックマーク）はこれまでどおりです

### フラット表示（`Alt+B`）

Total Commander のブランチビュー（Ctrl+B）に当たるものです。**いまのフォルダより下のファイル（フォルダ自体は出さない）を全部集めて1つの一覧に**し、名前の列はサブフォルダからの相対パス（`2026-10\log_001.txt`）で出します。パス表示に `[フラット]`、窓の下の行は件数と合計サイズです。

- ソート・マスク・ライブ絞り込み・マーク・コピー/移動/削除・ZIP（フォルダ構成を保って入る）・W・Alt+W・ビュア・F7 などがそのまま効きます（対象は相対パスを解決したフルパス）。F7 は同じフォルダのものだけ（エクスプローラのメニューは別々のフォルダのものを1つにまとめられないため）
- **`R`・`Shift+R`・`K` はフラット表示中は断ります**（名前が相対パスなので、改名がフォルダをまたぐ移動になったり、どこに作るかが曖昧になったりするため）
- 集めるのは別スレッドで、窓の下の行に件数が出ます。`Esc` で中止（通常の表示に戻る）。20万件で打ち切って知らせます。シンボリックリンク・ジャンクションのフォルダはたどりません（ループ防止）。隠し・システムは `Shift+Z` の設定に従います
- もう一度 `Alt+B`・`BS`・フォルダの移動で通常の表示に戻ります。再読込（`End` / `F5`）はフラットのまま集め直します。書庫の中では使えません

### 文字列検索（`G`）

いまのフォルダより下（サブフォルダも含む）のファイルの**中身**から語を探し、ヒットしたファイルをフラット表示と同じ形（相対パス）で並べます。パス表示に `[検索: 語]`、窓の下の行は「検索結果の件数 / ヒット行数」です。

- 文字コードは UTF-8（BOM付き含む）→ cp932 の順に判定し、大文字小文字は区別しません。判定できないファイルはバイト列のまま探します（ヒット行の文字列は出ません）
- 探すのは別スレッドで、窓の下の行に走査したファイル数が出ます。`Esc` で中止（通常の表示に戻る）。ヒット 2,000 件で打ち切って知らせます。32MB より大きいファイルは中身を見ません。書庫の中は探しません
- メッセージ窓に、ヒットしたファイルの先頭行（最初の50件まで）を「相対パス（ヒット行数）: 行」で出します
- 結果の一覧ではフラット表示と同じ操作が効きます（マーク・コピー/移動/削除・ビュアなど）。`R`・`Shift+R`・`K` はフラット表示と同じく断ります
- `Alt+B`・`BS`・フォルダの移動で通常の表示に戻ります。再読込（`End` / `F5`）は同じ語で探し直します

### プレビュー（`F3`）

Files / OneCommander / yazi のプレビューに当たるものです。**`F3` で反対窓の場所をプレビューに差し替え**、アクティブ窓のカーソルの中身を出します（反対窓のパスやマークはそのまま持っていて、`F3` でもう一度押すと戻る）。カーソルが止まってから 0.12 秒待って読むので、連打で重くなりません。**画像を表示中は `←` / `→` でも前・次のファイルへ移れます**（あふｗのビューアと同じ。通常の `←` / `→` は窓の切り替えですが、画像ビューア中だけこちらが優先します）。

| 種類 | 出すもの |
|---|---|
| テキスト（ビュアと同じ拡張子） | 先頭 200 行（読むのは最大 256KB。文字コードはビュアと同じ判定） |
| 画像（png jpg jpeg gif bmp webp ico） | 窓に収まる大きさ（縮めて読むので、巨大な画像でも全部は展開しない） |
| フォルダ | 中のフォルダ・ファイルの数と、先頭 40 件の名前 |
| そのほか | 名前・サイズ・日時・属性 |

- 読み込みは別スレッドで、ネットワーク越しでも止まりません。書庫の中のファイルは 4MB 以下だけ一時フォルダへ取り出して見せ、それより大きいものは情報だけです
- プレビュー中もキーはアクティブ窓に効きます。**プレビューを出している側へ移ろうとしたら（`Tab` / `←` `→`）、プレビューを終えてその窓へ移ります**（隠れた窓へキーが行って、見えない所で操作してしまわないように）
- プレビュー中のコピー・移動などの「反対窓」は、隠れている反対窓のフォルダのままです

### 一括改名（`Shift+R` / `Alt+R` → `Enter`）

Renemo の画面に寄せた一括改名の窓です（`filer_renemo.py`。改名の中身の判断は `filer_rename.py`）。対象はマーク（見えているもの）、無ければいまの一覧の全部（`..` 以外）。

- 列は「名前」（元の名前・拡張子付き・読み取り専用）｜「編集名」（1行1ファイル。行頭に行番号とファイルの種類のアイコン）｜「サイズ / 更新日時 / 種類」（種類はエクスプローラと同じ名前）。3つの列は行がそろい、スクロールもいっしょに動きます。下のステータスバーにカーソル行のフルパスとサイズ（KB）
- **編集名は既定で拡張子を隠します**（`data.txt` → `data`）。ツールバーの **`.ext`** で拡張子も編集の対象に、**`C:¥`** で名前の列をフルパスに。名前の部分と拡張子の部分を分けて持つので、切り替えても編集した内容は残ります
- 編集した行は黄色。行の追加・削除はできません（`Enter` は何もしない、行頭の `BS`・行末の `Del` で行をつながない）。改行を含む貼り付けは、いまの行から下へ1行ずつ差し替えます（Excel などの名前の一覧を貼る用）
- **変換**（選んだ文字、選んでいなければ全行。右クリックとメニュー）: 大文字 / 小文字 / 全角→半角 / 半角→全角（英数・記号・カナ）
- **置換**（`Ctrl+H`）: 検索・置換、正規表現、大文字小文字の区別、拡張子を除く。結果は編集欄にそのまま入るので、確定前に `Ctrl+Z` で戻せます
- **連番**: 選んだ行（無ければ全行）に `{n}` を含む書式で番号を振ります（開始番号・増分・桁数。`photo_{n:03}` のようにも書ける。拡張子は残す）
- **並べ替え**（表示メニュー）: 名前順 / 元の並び / 編集済みを先に。並べ替えても元の名前との組は崩れません
- **実行**は `Ctrl+Enter` かツールバーの「実行」。実行の前に、使えない文字（`\ / : * ? " < > |`）・空の名前・末尾の空白やピリオド・予約名（CON / PRN / AUX / NUL / COM1〜9 / LPT1〜9）・結果の重複・ほかのファイルとの衝突・行数の不一致を確かめ、**問題のある行を赤で示して実行しません**
- 改名は「いったん全部を一時名にしてから本来の名前にする」2段階で行うので、**名前の入れ替え（a→b, b→a）や大文字小文字だけの変更も通ります。途中で失敗したら、それまでの改名を元に戻します**（戻せなかったものがあればそれを知らせる）
- **履歴**: 行った一括改名を（元のフルパス → 新しいフルパスの組で）50件まで記録し、窓の「履歴」から選んで元に戻せます（戻すときも、元の名前が埋まっていないかなどを確かめる）。記録はリポジトリの外（`%LOCALAPPDATA%\traytools\filer_rename_history.json`）
- `Esc` で閉じます（未実行の編集があれば確かめる）。書庫の中・フラット表示中は使えません
- この窓だけ Renemo と同じ白地の配色です（文字を打って直すエディタなので、濃紺より白地に黒の方が長い名前を読み書きしやすい）

### ファイル情報の編集（`R`）

あふｗの「ファイル情報の編集」に合わせたダイアログです（`filer_fileinfo.py`）。上にアイコンと元の名前、その下に「ファイル名」、左に「変換」と「タイムスタンプ」、右に「属性」。

- **ファイル名**: 開いた時点では何も選ばず、キャレットは拡張子の手前（`.webp` の `.` の前。拡張子の無い名前・フォルダ・`.gitignore` のような名前は末尾）。大文字小文字だけの改名（`a.txt` → `A.TXT`）もできます
- **変換**: 「全体」「拡張子」それぞれに [小文字] [⇔（大小の入れ替え）] [大文字]。押すと入力欄の名前に反映されるだけで、決まるのは OK のとき
- **タイムスタンプ**: 左に今の更新日時、右に 年 月 日 / 時 分 秒。存在しない日付（2/30 など）や 1980年より前は、OK のときに理由を出してダイアログに戻ります。アクセス日時は今のまま
- **属性**: Read Only / System / Hidden / Archive。**`Alt+R` / `Alt+S` / `Alt+H` / `Alt+A` で切り替え**（フォーカスは動かない）
- `Enter` で OK、`Esc` でキャンセル。`Tab` は 名前 → 変換 → 日時 → 属性 → OK の順
- OK では**変わった項目だけ**を当てます（何も変わっていなければ何もしない）。読み込み専用のファイルでも名前・日時を変えられるよう、先に読み込み専用を外し、名前・日時を変えてから、最後に属性を決めます（属性を変えないなら読み込み専用は元に戻る）。名前がほかと重なる・当てるのに失敗した、などのときは理由をダイアログに出して開いたままにします（打った内容は残る）。終わったら読み直して新しい名前にカーソルを合わせ、変えた内容をメッセージ窓に1行で出します
- **マークがあるときは一括変更**（あふｗの「ファイル情報の一括変更」）。名前は直接は打たず、「変換」が全件に当てる変換の指定になります（行ごとにどれか1つを押して選ぶ。押し直すと外れる）。日時は「変更する」を付けたときだけ全件に同じ日時を設定し、**年月日を 0 にすると、それぞれのファイルの年月日のまま時刻だけを変えます**（あふｗと同じ）。属性は3つの状態（変えない／ON／OFF）で、ON/OFF にしたものだけを全件に当てます。一括で小文字にしたら2つが同じ名前になった、のような重なりは、何も変えずに知らせます
- 書庫の中では「書庫内では編集できません」と出すだけです

### ZIP 圧縮（`P`）

マーク（無ければカーソル行。`..` は除く）を、**反対窓のフォルダに ZIP で作ります。** フォルダは中身ごと（空のフォルダも入る）で、書庫の中の名前はいまのフォルダからの相対パスです。

- 名前は入力欄で確かめます（既定は、対象1件ならその名前から拡張子を除いたもの、複数ならいまのフォルダ名に `.zip`）。既にあれば上書きを確かめます（既定は「いいえ」）
- 標準の `zipfile`（`ZIP_DEFLATED`）で作り、ASCII 以外の名前には UTF-8 の印を付けます（Windows 標準の展開でも化けない）。更新日時は元のファイルのまま
- **`Shift+Z` で隠し/システムファイルを非表示にしていても、対象のフォルダの中のものは入れます**（表示の絞り込みは見え方の設定で、中身を選ぶものではないため）
- 別スレッドで作り、進み具合を出して中止できます。隣の `.filer-part` に書いてから置き換えるので、**中止・失敗のときに作りかけの ZIP は残りません**。読めないファイル（使用中など）は飛ばして続け、メッセージ窓に出します
- 作ろうとしている ZIP 自身は入れません。終わったら反対窓を読み直して、作った ZIP にカーソルを合わせ、件数と大きさをメッセージ窓に出します
- 自窓・反対窓のどちらかが書庫の中なら作りません

### WinMerge で比較（`Alt+W`）

本人の `AFXW.key` で `Alt+W` は比較メニューなので、ここでは **WinMerge に直接渡します。**

- 左窓に1件・右窓に1件マーク → その2つ（左が左）。片方の窓だけに2件マーク（もう片方は0件） → その2件。それ以外は「左右に1件ずつ（または片側に2件）マークしてください」と出すだけ。フォルダ同士の比較も可
- 書庫の中のものは一時フォルダへ取り出してから渡します。左右の表示名（`/dl` `/dr`）にはファイラ上のパス（書庫の中なら書庫の中のパス）を渡します
- `WinMergeU.exe` は `filer.winmerge` → レジストリの App Paths（HKLM・HKCU）→ `%ProgramFiles%\WinMerge` / `%ProgramFiles(x86)%\WinMerge` / `%LOCALAPPDATA%\Programs\WinMerge` の順に探します。見つからなければ「WinMerge が見つかりません（filer.winmerge で指定できます）」
- 引数はリストで渡すので、空白を含むパスでも壊れません

### 書庫の中を見る（`filer_archive.py`）

あふｗの仮想フォルダと同じように、**`.zip` / `.7z` の上で `Enter` を押すと書庫の中へ入ります。** ZIP は標準の `zipfile`、7z は `py7zr`（`requirements.txt`）で読みます。py7zr は書庫を開くときに初めて読み込み、入っていなければ「7z を開くには py7zr が必要です」とメッセージ窓に出るだけです（ZIP はそのまま使えます）。

- パスは `D:\x\foo.zip\sub\` のように**書庫のパス＋中のパス**で出ます。ふつうのフォルダと同じ形なので、カーソル移動・マーク・`F`・マスク・`S`・`W`・履歴（`B` `,` `.` `H`）・`O` / `Shift+O` / `Alt+O`（相手が書庫の中でも）がそのまま効きます。サイズと更新日時は書庫のエントリの値
- `BS` / `..` で一つ上へ。書庫のルートで `BS` すると書庫ファイルのあるフォルダへ戻り、書庫ファイルにカーソルが合います
- **ZIP のファイル名**は、UTF-8 の印が無ければ cp932 として読み直します（`zipfile` は cp437 で読むので、日本の ZIP はそのままだと文字化けする）。ディレクトリのエントリを持たない ZIP でも、途中のフォルダを合成して見せます
- `..` や絶対パス・ドライブ名を含む**危ないエントリ（zip slip）は一覧に出さず、展開もしません**（入ったときに件数だけメッセージ窓に出ます）
- 中のファイルで `Enter` / `E` / `V` / `Shift+Enter` を押すと、`%TEMP%\traytools-filer\` の下へ取り出してから開きます。この一時フォルダは、ファイラを閉じるときと次の起動で片付けます（開いたままのファイルは消せずに残り、次の起動で片付く）
- **`C` の `O` と `Alt+C` は反対窓（実フォルダ）への展開**になります。フォルダは中身ごと。同じ名前があれば「上書き / スキップ / 取消」を尋ね、「残り○件にも同じ扱いをする」で以降を省けます。進み具合は小さな窓に出て、中止できます
- **書き込み系（`D` `M` `R` `K` `Ctrl+Ins` `Ctrl+Del` `Shift+Ins` など）は「書庫内では使えません」と出すだけ**。反対窓が書庫の中のときの `Alt+C` / `Alt+M` も「書庫内へは書き込めません」
- **パスワード付き**: ZIP（ZipCrypto）と、ファイル名が見える 7z は、一覧は出して展開のときにパスワードを尋ねます（取消可。違っていれば失敗をメッセージ窓に出す）。ファイル名まで暗号化された 7z は一覧が出せないので「未対応」と出します。ZIP の AES 暗号は `zipfile` が読めないので、展開のときに「未対応の圧縮・暗号です」と出ます
- 一覧の読み取りは、ふつうのフォルダと同じ別スレッド＋見切りの仕組みに乗せ、見切りを `filer.archive_timeout_seconds`（既定30秒）に延ばします。開いた書庫の目録は覚えておくので、中を移動するたびに読み直しません（書庫ファイルが変われば読み直す）
- 閉じるときに書庫の中にいれば、**その書庫の中のパスをそのまま保存**し、次回もそこが開きます（書庫が消えていれば、残っているフォルダまで遡る）

## 付箋は本体とは別のプロセス（`capture_process.py`）

**付箋（Rapture のキャプチャウインドウ）は、常駐アプリ本体とは別のプロセスで動きます。** 本体が落ちても、機能を足して**再起動しても、開いている付箋はそのまま残ります**。手順書を作るために連番キャプチャで何枚も並べている最中に本体を再起動すると付箋が全部消える、という道連れを防ぐためです。

- 付箋1枚につき1プロセス（`pythonw.exe capture_process.py ...`）。閉じるとそのプロセスは終わります。
- 画像はプロセス境界を越えられないため、一時フォルダ（`%TEMP%\traytools-rapture\`）へ PNG を書いて渡します。**付箋は読み込んだ時点でその PNG を消します**（起動に失敗して取り残された分は、次に付箋を開くときにまとめて掃除されます）。
- 付箋は起動時に**自分専用の名前付きパイプ** `\\.\pipe\traytools.rapture.<作成時刻ms>.<pid>` を開いて待ち受けます。中身の約束事は本体の IPC と同じ、UTF-8 の JSON 1行です。

| `command` | 動作 |
|---|---|
| `capture_sequence` | 連番キャプチャを1枚進める（右クリックメニューの「キャプチャ＆保存」と同じ） |
| `ping` | 何もしない。生きているかを確かめるためだけのもの |

`Ctrl+Alt+S` を押すと、本体は `\\.\pipe\` の一覧からこの名前を探し、**作成時刻がいちばん新しい付箋**へコマンドを送ります。一覧から毎回引き当てるので、**本体を再起動しても対象を見失いません**。

### 待機プロセス（付箋が出るまでの待ちを消す仕組み）

別プロセスにした当初は、**付箋を1枚出すたびに Python と Qt を読み込む**ため、範囲を選んでから付箋が出るまで 0.4 秒ほどかかっていました（別のPCでは3秒以上という報告もあります）。その7割強は「Qt を読み込んで最初のウインドウを出す」固定費で、コードの書き方では縮みません。

そこで、**その費用を待たされない時間帯へ前払いします。**

1. 本体の起動から3秒後、付箋プロセスを1つ **待機役** として起こしておきます（`capture_process.py --prewarm`）。待機役は Qt を読み込み、付箋ウインドウの実体まで作り、**画面外・不透明度0・タスクバーにも出さない状態で一度だけ描画してから隠れて待ちます**。
2. キャプチャのときは、その待機役へ**画像と表示位置を送るだけ**。受け取った待機役は隠していたウインドウを出して、普通の付箋になります。
3. 本体は続けて**次の待機役を裏で起こします**。

実測（このPC。範囲を選んでから付箋の待ち受けが立つまで、5回の平均）:

| | 実測 |
|---|---|
| 待機役あり（既定） | **9.9 ms** |
| 待機役なし（従来どおり1枚ごとに起動） | 354.9 ms |

**待機役が居ないときは必ず従来どおりの起動に落ちます。** 待機役が死んでいてキャプチャが失敗する、ということはありません（そのぶん 0.4 秒かかりますが、確実に出ます）。落ちた場合も、次の1枚のために待機役の補充を試みます。

代償は**常時1プロセスぶんのメモリ**です。実測で**専有 27MB 前後**（ワーキングセットは 56MB ですが、大半は Qt の DLL で本体と共有しています）。惜しい場合は `settings.json` の `capture.prewarm` を `false` にすると、1枚ごとにプロセスを起こす従来の形へ戻ります。

- 待機役は `\\.\pipe\traytools.rapture-warm.<起きた時刻ms>.<pid>` で待ち受けます。付箋の名前（`traytools.rapture.<...>`）とは**別の名前空間**なので、`Ctrl+Alt+S` が画面に出ていない待機役へ飛ぶことはありません。
- 待機役は**本体を終了すると一緒に終わります**（まだ何も表示していないので残す理由がありません）。本体が落ちて合図を送れなかった場合も、待機役自身が本体の待ち受けを15秒ごとに見ていて、2回続けて見つからなければ自分で終わります。**付箋になったあとはこの見張りを止める**ので、表示中の付箋が本体の終了で消えることはありません。
- 待機役を使うと `Ctrl+Alt+S` の宛先が立つのも速くなるため、「キャプチャ直後に間髪入れず押すと1つ前の付箋が対象になる」問題も起きにくくなります。
- **画面取得（mss の実体）も前払いします。** mss の生成（GDI 関数の解決とモニタ列挙）は安くなく、初回のキャプチャの瞬間に払うと「押してから撮れるまで」が目に見えて遅れました。本体は起動から3秒後（待機役を起こすのと同じタイミング）に、待機役と通常の付箋は待っている間・表示直後に、それぞれ自分のプロセスの mss を作っておきます（`capture_grab.prewarm_sct`）。初回の範囲キャプチャも、付箋の初回の連番キャプチャも、2回目以降と同じ速さになります。

### 連番キャプチャ（`Ctrl+Alt+S` / Space）

手順書を作るときのように、**同じ範囲を何度も撮る**使い方のための機能です。

範囲を1回選んで付箋を出したら、あとは「操作する → `Ctrl+Alt+S` → 操作する → `Ctrl+Alt+S`」と繰り返すだけで撮り溜められます。押すと、付箋自身が写り込まないよう一瞬隠れてから**その付箋が今いる位置**を撮り直し、保存して、付箋の表示を新しい画像に差し替えます（描き込んだ内容はクリアされます）。

**`Ctrl+Alt+S` は付箋がアクティブでなくても効きます。** ブラウザやアプリを操作する側にフォーカスを置いたまま撮れる、というのがこの機能の本命の使い方です（付箋は常に最前面で位置を保っているので、フォーカスが無くても狙った範囲がそのまま撮れます）。

**対象は「いま開いている中でいちばん新しい付箋」です。** 付箋は同時に何枚でも開けますが、ホットキーが撮るのはその1枚だけです。その付箋を閉じると、対象は**残っている中で次に新しい付箋**へ移ります。1枚も開いていなければ `Ctrl+Alt+S` は「付箋がありません」と通知します。

> 付箋を別プロセスに出す前は「最後に作った付箋」をオブジェクトとして掴み続けていたため、それを閉じると他の付箋が残っていても対象は無しになっていました。いまは押されるたびに待ち受けの一覧から選び直すので、次に新しいものへ引き継がれます（そのかわり本体を再起動しても対象を見失いません）。

**キャプチャ直後に間髪入れず押すと、1つ前の付箋が対象になることがあります。** その付箋の待ち受けがまだ立っていないためです（付箋が1枚のときは「付箋がありません」と出るだけです）。待機プロセスが使われた場合は待ち受けが 10ms 前後で立つので、まず起きません。従来どおりの起動に落ちたときだけ 0.4 秒ほどの隙があります。

**付箋がアクティブなときは Space も使えます。** 手元で付箋を触っているときの近道で、実行される処理は `Ctrl+Alt+S` とまったく同じものです。Space をグローバルホットキーにすると全アプリの文字入力を奪ってしまうため、非アクティブでも効く方は `Ctrl+Alt+S` に分けています。

**撮っている最中に押しても二重には走りません。** 隠す → 少し待つ → 撮る、という流れなので、待っている間の入力は無視されます（連打しても同じ絵が2枚保存されたりしません）。

**付箋1枚が1つの「セッション」**です。ファイル名のタイムスタンプは付箋を作った時刻で固定され、撮るたびに末尾の連番（3桁ゼロ埋め）だけが増えるので、一連の作業がファイル名でまとまります。

```
rapture_20260823_140919-001.png   ← キャプチャ直後の自動保存
rapture_20260823_140919-002.png   ← Ctrl+Alt+S
rapture_20260823_140919-003.png   ← Ctrl+Alt+S
```

- **直前に保存した画像と変化が無ければ、保存も連番の加算もしません。** 同じ絵が溜まらないようにするためです。見送ったときは「変化がないので保存しませんでした」と通知が出ます（付箋の表示もそのまま＝描き込みは消えません）。
- 付箋の**左上に、そのセッションで何枚目かのバッジ**が出ます。これはウインドウ上に描いているだけなので、**保存される画像やコピーした画像には含まれません**。ズームしても大きさは変わりません。
- 「再キャプ」（右クリックメニュー）は従来どおり、保存せずに撮り直すだけです。連番は進みません。
- Ctrl+S の「保存」は描画内容を焼き込んだ別物の保存なので、連番セッションには入らず `rapture_YYYYMMDD_HHMMSS.png` として保存されます。

## 診断（`diagnostics.py` / `diagnostics_window.py`）

トレイメニューの「**🩺 診断…**」で、落ちた手掛かりを短いテキストにまとめ、**テキストと QR コード**で出します。業務PCからはデータを持ち出せないので、**スマホのカメラで QR を読み取って、そのまま Claude とのチャットに貼る**ためのものです。まれにしか使わないのでホットキーはありません。

```
[tray-tools diag] 2026-10-21 23:20
ver 9a54a1a 2026-10-09 22:33 main          ← HEAD のコミット（git コマンドを使わず .git を自前で読む）
src 52 files, newest 2026-10-21 23:20 ...  ← いちばん新しい .py の更新日時
lost none                                  ← import しているのに実ファイルが無いもの
os win 10.0.26200.9711 25H2
py 3.14.4
pkg PySide6 6.11.1 pycaw 20251023 ...      ← 入っていなければ「なし」
boot 7d 1 last 10-15 21:39 up 0d03h12m     ← 直近7日の起動回数・最後の起動・今回の起動からの経過
cfg hk 15/17 tbw on prewarm on audio 2 ... ← 設定はオンオフと件数だけ
run jig off awake off cop off ...          ← いま動いているか
evt 30d tray 0 other 1                     ← Windows のイベントログの異常終了
crash fatal 26 (last 6)                    ← crash.log の Windows fatal exception
 09-12 14:36 0x8001010d? main.py:971 main < main.py:975 <module>
err 12 (last 6)                            ← error.log の例外
 09-11 01:01 x5 command=agent-loop NameError: name 'screen' is not defined
```

### 何を見ているか

| 行 | 中身 |
|---|---|
| `ver` | `.git/HEAD` → refs（`packed-refs` を含む）→ コミットの日付。業務PCに git が無くても読める。`.git` が無ければ `ver git なし`（ZIP で配った版） |
| `src` / `lost` / `broken` | リポジトリ直下と `tools/` の `.py` を **ast で静的に読み**、import しているのに実ファイルもインストール済みのパッケージも無いものを「抜け」として挙げる。`try: … except ImportError` の中の import（任意の依存）は数えない。構文として読めないファイル（コピーの途中で切れたもの）は `broken` に出る。**「期待するファイル一覧」はコードに持たない**（足すたびに直す表は必ず古くなる） |
| `evt` | Application ログの ID 1000（アプリのクラッシュ）と 1002（ハング）、過去30日、python を含むもの。日時・アプリ名・障害のあるモジュール名・例外コード。読み方は `wevtutil`、だめなら PowerShell の `Get-WinEvent`（`.ps1` は使わず `-Command` に本文を渡す。GPO で `.ps1` が止められている PC がある）。権限やポリシーで拒まれたら `読めず` とだけ書き、他の項目は出す |
| `crash` | crash.log の直近の `Windows fatal exception`。直前の起動見出しの日時・例外の種類・**落ちたスレッド（`Current thread`）**の上位3フレーム。`GC → comtypes の Release` で落ちた形は上位3フレームがいつも同じなので、代わりに **GC を呼び込んだ側の3フレーム**を `GC>Release @ …` として出す。同じ落ち方が続いたら `x2` のようにまとめる |
| `err` | error.log の直近の例外の型とメッセージの1行目 |

**イベントログの「tray」と「other」の分け方。** 落ちるのは venv のスタブが起こした本物のインタプリタなので、イベントのアプリのパスは venv ではなく Python 本体を指します（障害のあるモジュールも本体の `_ctypes.pyd` などが多い）。パスだけでは決めきれないため、パスに tray-tools の venv かリポジトリが出るか、**プロセスの作成時刻の直後（90秒以内）に crash.log の起動見出しがある**ものを tray-tools とします。それ以外（lan-drop など）は件数だけ出します。付箋などの子プロセス（起動見出しを書かない）が落ちた場合は「other」に入ります。

**`?` の印。** crash.log の `code 0x8001010d` のような HRESULT（`0x8…`）や C++ 例外（`0xE…`）は、faulthandler が拾っただけで実際には処理され、プロセスは生きていることがあります。これには `?` を付けます。異常終了だったかは `evt` と突き合わせて判断してください。

### 伏せ字

まとめの**全文に最後にかけます**（項目ごとに気を付けるだけだと、1か所の漏れがそのまま出るため）。

- ホームのパスは `~` に、他の絶対パスはファイル名だけに
- ユーザー名・コンピュータ名・ドメイン名（`USERNAME` / `COMPUTERNAME` / `USERDOMAIN`、ホームのフォルダ名、ホスト名）は `*` に。大文字小文字は区別しない
- メールアドレス・URL・IP アドレスも伏せる
- Pushover のトークンなどの秘密情報は**そもそも読まない**。settings.json もオンオフと件数しか見ない

それでも、**読み取る前に窓のテキストを目で確かめてください**（QR の上に注意書きを出しています）。

### 窓

- 上にテキスト（読み取り専用・等幅・選択とコピーができる）、下に QR。間の仕切りは動かせる
- QR は誤り訂正 M、1枚あたり 960 バイトまで（version 25 以下。画面から読むので上げすぎない）。収まらなければ行の切れ目で分け、各ページの先頭に `[tray-tools diag 1/2]` を付ける。「前へ／次へ」で切り替える
- 「コピー」は全文をクリップボードへ、「保存…」はテキストファイルへ（既定はドキュメント。リポジトリの外）、「再取得」で取り直す
- **窓は常駐とは別のプロセスです**（`diagnostics.spawn_window`。`pythonw.exe` + `DETACHED_PROCESS`、背景を透過と同じ形）。常駐から渡すのは「いま動いている機能」と常駐の起動時刻だけ。最初は常駐の中に窓を出していましたが、**実機で開いた直後に常駐ごと落ちました**。QR を作る最中の GC が、常駐の抱える comtypes のオブジェクトの `__del__ → Release` に入って access violation（crash.log とイベントログの両方に残った）。大量にオブジェクトを作る処理は GC を呼び込むので、COM オブジェクトの居る常駐の中ではやらない
- イベントログの読み取りは数秒かかることがあるので、まとめは窓のプロセスのワーカースレッドで作ります（取得中は「取得中…」）
- 窓の大きさは `settings.json` の `diagnostics.window_size` に覚えます。位置は毎回カーソルのある画面の中央
- 配色は背景を透過（`bg_remove.THEME`）と同じ値。常駐の中で `bg_remove` を import すると cv2 / numpy まで読み込むので、値だけ写してあり、食い違いとコントラスト比はテストが確かめます
- 常駐は `diagnostics` をメニューを押したときに初めて import します。診断はファイルが抜けている PC で使うものなので、診断のファイル自体が抜けていても常駐の起動を巻き添えにしないため
- 窓を2回開くと2枚出ます（別プロセスなので、開いているかを常駐からは見ていません）

窓を出さずに確かめるときは:

```
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe diagnostics.py            # まとめを標準出力へ
%USERPROFILE%\.venvs\tray-tools\Scripts\python.exe diagnostics.py --pages    # QR のページ単位で
%USERPROFILE%\.venvs\tray-tools\Scripts\pythonw.exe diagnostics_window.py    # 窓だけを開く（起動からの経過はこのプロセスのもの）
```

QR には `segno` を使います（`requirements.txt` に入っているので `setup.py` で入ります。既存の venv なら `pip install segno`）。

### テスト


伏せ字・crash.log / error.log の解析・イベントログの XML（英語と日本語の項目名）・`.git` の読み取り（ばらの ref、packed-refs、pack の中のコミット）・import の抜け・ページ分け・QR の生成（version と QImage）・窓の配色を、合成した入力で確かめます。

## 機能の追加方法

`feature_xxx.py` に、次の規約を満たすクラスを1つ書きます（抽象基底クラスは無く、ダックタイピングです）。

- コンストラクタ `__init__(self, app_settings, settings_path)` で `QSystemTrayIcon` を1つ構築し、`self.tray_icon` に保持する
- `hotkeys()` メソッドで `{"設定キー名": 呼び出す関数}` の辞書を返す（不要なら空辞書 `{}` を返す）

書けたら `main.py` の `FEATURE_CLASSES` リストにクラスを追加するだけです。ホットキーの実体（`ctrl+alt+x` のような文字列）は `settings.json` の `hotkeys` セクションに追記してください。

**Feature を増やすのは「アイコンの見た目を占有する状態」を持つ場合だけにしてください。** アイコンを持たない機能は普通のモジュール（`color_picker.py` / `snippets.py` / `launcher.py` / `taskbar_widget.py` など）として書き、既存 Feature のメニュー項目から呼びます。開いたウインドウの参照は呼び出し側（`ScreenFeature`）が保持します（**ローカル変数だけだと GC で即消えます**）。

`taskbar_widget.py` は「画面に出っぱなしになる窓を持つが、Feature ではない」例です。トレイアイコンを持たないので Feature の条件に当てはまらず、生成と参照の保持は `ScreenFeature` が行います。他の Feature の参照が要る場合は、**Feature が全部そろってから** `main.py` 側で渡してください（`_wire_taskbar_widget()` がその例です。コンストラクタは1つずつ呼ばれるので、その中では相手がまだ居ません）。

「一覧から絞り込んで1つ選ぶ」UIが要る場合は `picker.PickerWindow(タイトル, [(表示名, データ), ...], on_accept)` を使ってください。決定すると `on_accept(表示名, データ)` を呼び、その後**必ず**ウインドウを閉じて `closed` を出します（定型文とフォルダブックマークが同じ窓を共有しています）。

`PickerWindow` には任意の引数がいくつかあり、**渡したものだけが姿を現します**（既定では今までどおり「絞り込んで選ぶだけ」の窓です）。定型文には要るがフォルダブックマークには要らない、という差をここで吸収しています。

| 引数 | 渡すと |
|---|---|
| `preview_provider(データ) -> str` | リストの下に読み取り専用のプレビューが出る。選択が動くたびに呼ばれる。窓の横幅も広がる |
| `hint` | ウインドウ下部に小さな説明の行が出る（改行可） |
| `on_new()` / `on_edit(表示名, データ)` / `on_open_folder()` | `Ctrl+N` / `Ctrl+E` / `Ctrl+O` が効くようになる。いずれも**実行後にウインドウを閉じます** |
| `dynamic_items(入力欄のテキスト) -> [(表示名, データ), ...]` | 入力から作った項目が一覧の**先頭**に並ぶ。1文字打つごとに呼ばれる。渡すのは生のテキストで、`picker` は中身を解釈しません |
| `tab_text(表示名, データ) -> str` | `Tab` で入力欄をその文字列に差し替える（フォルダブックマークの掘り下げに使っています）。窓は閉じません |
| `on_delete(表示名, データ)` / `on_move(表示名, データ, step)` | `Ctrl+D` / `Ctrl+↑↓` が効くようになる。**窓は閉じません**（続けて消す・動かすため）。一覧の組み直しは呼び出し側が `set_items()` で行います |

渡さなかった処理のキーは握り潰さずに素通しします（押しても何も起きないだけです）。プレビューやキー操作の追加分は `_fit_to_items()` で**固定値の高さ**として足しています。`QT_QPA_PLATFORM=offscreen` ではフォントメトリクスが当てにならず、測った値だけを根拠にすると環境によって高さが潰れるためです。

## 既知の制限事項

- **マルチモニタでDPI(拡大率)が異なる場合、1回の選択が2画面をまたぐとズレが残ります。** キャプチャは選択範囲の中心にある画面のdevicePixelRatioを基準に行うため、単一モニタ内の選択であれば各モニタごとの拡大率差には対応していますが、範囲が複数モニタにまたがりそれぞれ拡大率が異なる場合は原理的に補正しきれません。
- 付箋ウインドウのタイトルバーの高さ・見た目はOSのテーマに依存します。
- グローバルホットキーは他アプリと競合すると登録に失敗します。失敗しても他の機能・アプリ全体は動作を続けますが、標準エラー出力にメッセージが出ます（通常運用ではコンソールが無いため気付きにくい点に注意してください）。
- **スリープ抑止が防げるのは「無操作によるスリープ・画面オフ」だけです。** スタートメニューから明示的にスリープした場合、ノートPCの蓋を閉じた場合、組織のポリシーで強制されるロック画面は防げません（**入力の有無で決まるアイドル切断・ロックには「🖱 マウスジグラー」を使ってください**）。
- **マウスジグラーは、管理者権限で動いているウィンドウが前面にある間は入力を送れません**（Windows の UIPI が弾きます）。その場合は自動的に停止して通知します。また、会社によっては入力の自動生成そのものが規程で禁じられていることがあります（EDR が検知する可能性もあります）。使う前に自分の環境の決まりを確認してください。
- 通知領域のアイコンは Windows 11 では既定で「隠れているインジケーター」に入ります。見えない場合はオーバーフローから引っ張り出してください。
- **付箋の待機プロセスが常に1つ動きます（専有 27MB 前後）。** 付箋が出るまでの待ちを消すためのもので、タスクマネージャーには本体とは別の `pythonw.exe` として並びます。ウインドウは持たないのでタスクバーには出ません。要らなければ `settings.json` の `capture.prewarm` を `false` にしてください。
- **セカンダリのタスクバーウィジェットは「重ねて隠している」だけで、本物の時計を消しているわけではありません。** セカンダリの時計は XAML（`Windows.UI.Composition.DesktopWindowContentBridge`）で描かれており、子ウィンドウとして掴めないため、位置も大きさも画面のピクセルから実測して合わせるしかありません。Windows の更新でタスクバーの見た目が変わったら、`width` / `height` と Ctrl+左ドラッグで合わせ直してください。
- **セカンダリのタスクバーが複数ある（モニタが3枚以上ある）場合、どれに出るかは選べません。** 最初に見つかったものを基準に置きます。狙いと違う画面に出たら Ctrl+左ドラッグで動かしてください（位置が保存され、以後はそちらが使われます）。
