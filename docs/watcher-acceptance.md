# 見張りの常駐化 第1段階 受け入れテスト計画

- 対象: `docs/watcher-resident-design.md` の第1段階（タスクスケジューラ
  MuseBridgeMonitor による自動起動・落下復旧、合図ファイル化、
  ミューテックスによる二重起動防止）を実機に入れたあとの確認項目。
- 進め方: 上から順に。1項目 = 手順・合格の基準・だめなときに見るもの。
- 見るものの略記: 「状態ファイル」=
  `%LOCALAPPDATA%\traytools\muse_bridge_status.json`、
  「合図ファイル」= 同じ場所の `muse_bridge_wake.json`、
  「ログ」= `R:\claude\claude-bridge\muse_monitor.log`。

## 1. PC再起動後に自動で起動する

- 手順: PC を再起動し、ログオンしてから何もせず5分待つ。
- 合格: ブリッジに「見張りが止まっています」と出ておらず、状態が
  新しくなり続ける。タスク MuseBridgeMonitor が「実行中」。
- だめなとき: タスクの「前回の実行結果」と履歴、ログの有無。

## 2. プロセスを強制終了すると約1分で戻る

- 手順: タスクマネージャで見張りの python を「タスクの終了」する。
  ブリッジが「見張りが止まっています」になるのを確認してから、
  復帰までの時間を測る。
- 合格: 約1分（再起動間隔）＋数十秒で状態ファイルが再び新しくなり、
  ブリッジの表示が戻る。
- だめなとき: タスクの「前回の実行結果」（再起動が試みられたか）、
  ログ末尾の例外。

## 3. 2本目が起動しない

- 手順: 見張りが動いている状態で、`muse_monitor.py` をもう1本、
  手で起動する。
- 合格: 2本目がすぐに終了する（または「すでに動いている」旨を
  記録して終わる）。ブリッジの状態が乱れない。動いている見張りの
  状態ファイルの更新が止まらない。
- だめなとき: ログ（両方のプロセスの記録）、状態ファイルの
  更新が交互に跳ねるような形跡。

## 4. 起こす用件でも見張りが終了しない

- 手順: Muse へ起床の用件を作る（郵便受けで依頼を送る等）。
- 合格: 合図ファイルが書かれ、Claude 側の待ち受けがそれを拾って
  起きる。見張りのプロセス自体はその前後で終了していない
  （状態ファイルの更新が途切れない）。
- だめなとき: 合図ファイルが作られているか／更新時刻、ログの
  起床まわりの記録、待ち受け側の記録。

## 5. 範囲外の承認カードは1回だけ合図される

- 手順: 委任の条件の範囲外の操作（対象外のリポジトリやファイル範囲
  など）で承認カードを出し、そのまま放置する。
- 合格: 自動では押されず、合図（起床）が1回だけ行われる。同じカード
  に対して合図が繰り返し連打されない。
- だめなとき: ログの承認まわりの記録、合図ファイルの更新回数。

## 6. 承認の自動押下が続けて効く

- 手順: 委任の条件の範囲内の操作（tray-tools の main／muse/* への
  push 等）を、間を置いて複数回行う。
- 合格: 毎回、カードが自動で承認され、ログに承認した記録が残る。
  つつき（カードが出ないときの入力）も従来どおり効く。
- だめなとき: ログの承認記録、ブリッジの「受信 ○秒前」の動き。

## 7. 休止ボタンが効く

- 手順: ブリッジの休止ボタンを押して「休止」にし、その状態で
  範囲内の承認カードを出す。次に休止を解除して、もう一度出す。
- 合格: 休止中は自動承認もつつきも起床も止まり、カードは手動待ちに
  なる。解除後は自動承認が再開する。見張りのプロセス自体は
  休止中も動いていて、状態ファイルの更新は続く。
- だめなとき: `%LOCALAPPDATA%\traytools\muse_bridge_pause.json`
  が書かれているか、ログの休止まわりの記録。

## 8. Claude が居なくても動く

- 手順: Claude のセッションを閉じた状態で、郵便受けの受信・
  状態表示・範囲内の承認カードの自動押下までの一通りを行う。
- 合格: 見張りが終了せず、状態ファイルの更新が続く。承認の自動押下
  （Claude を必要としない分）が効く。起床の用件は合図ファイルに
  書き置かれ、次に Claude が起きたときに拾われる。
- だめなとき: ログ、合図ファイルの滞留の有無。

## 9. スリープ復帰で壊れない

- 手順: PC をスリープし、30分ほど置いてから復帰する。
- 合格: 復帰後数分でブリッジの状態表示が正常に戻る。見張りが
  落ちていれば自動再起動で戻る。誤った合図や承認が復帰の瞬間に
  まとめて飛ばない。
- だめなとき: ログの復帰前後の記録、状態ファイルの updated の跳ね。

## 10. 画面ロック中は勝手に押さない

- 手順: 画面をロックした状態で、範囲内の承認カードが出る操作を
  用意しておく（またはロック前に出しておく）。しばらく置いてから
  ロックを解除する。
- 合格: ロック中は自動承認されない（画面が判定できない間は押さない
  仕様どおり）。解除後に、通常の扱い（自動承認または合図）になる。
- だめなとき: ログのロック中の判定の記録（「不明」として扱われて
  いるか）。
