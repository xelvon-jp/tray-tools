# 見張りの運用手順書

- 対象: 常駐化（第1段階）したあとの見張り（`muse_monitor.py`）を、
  陽太さんが日常で運用するための手順。設計の前提は
  `docs/watcher-resident-design.md` の第1段階。
- 関係するもの:
  - 見張り本体: `R:\claude\claude-bridge\muse_monitor.py`
  - 起動するタスク: タスクスケジューラの **MuseBridgeMonitor**
    （ログオンで自動起動、落ちたら約1分間隔で自動再起動）
  - 状態ファイル: `%LOCALAPPDATA%\traytools\muse_bridge_status.json`
    （見張りが定期的に書き、ブリッジが読んで表示する）
  - 起床の合図ファイル: `%LOCALAPPDATA%\traytools\muse_bridge_wake.json`
    （見張りが「Claude を起こしてほしい」ときに書く）
  - 休止の合図ファイル: `%LOCALAPPDATA%\traytools\muse_bridge_pause.json`
    （ブリッジの休止ボタンが書く）
  - ログ: `R:\claude\claude-bridge\muse_monitor.log`
    （自動承認したカードの記録もここ）

## 動いているかの確認（PC起動後など）

ふだんはブリッジ（右下のパネル）を見るのが一番確実。

1. ブリッジのカードで、状態の更新が新しいこと（「受信 ○秒前」が
   増え続けていない／「見張りが止まっています」と出ていない）。
2. もっと直接見たいときは、エクスプローラで
   `%LOCALAPPDATA%\traytools` を開き、`muse_bridge_status.json` の
   更新日時が新しい（数十秒以内）こと。
3. タスク側は、タスクスケジューラで **MuseBridgeMonitor** が
   「実行中」になっていること。

注意: **プロセスの数では判断しない**。見張りは venv の都合で
タスクマネージャに2つ並んで見えるのが正常（本体と起動用のスタブ）。
二重起動していても、ミューテックスで2本目は動かない作り。

## 止まったときの見分け方と直し方

### 見分け方

- ブリッジに「見張りが止まっています」と出る、または状態ファイルの
  更新日時が数分以上古いまま。
- スリープから復帰した直後は、一時的に古く見えることがある。まず
  2〜3分待って、更新が再開するかを見る。

### 直し方（上から順に）

1. **約1分待つ**。落ちた場合はタスクが自動で起こし直す。再起動が
   間に合えば表示は勝手に戻る。
2. 戻らなければタスクスケジューラで **MuseBridgeMonitor** を開き、
   「前回の実行結果」を確認する。エラーが出ている場合はその文面を
   控える（報告に使う）。
3. タスクを右クリックして「実行」する。数十秒後にブリッジの状態が
   新しくなれば復旧。
4. それでも直らなければ、ログ `muse_monitor.log` の末尾を見る。
   直近の例外やエラーの行が原因の手がかり。そのまま Claude／Muse へ
   報告する。

## 見張りを更新したいとき

見張りのプログラム（`muse_monitor.py`）を新しい版に差し替えるとき:

1. ブリッジの休止ボタンを押して「休止」にする（差し替え中に
   つつき・自動承認が走らないように）。
2. ファイルを差し替える。
3. タスクスケジューラで **MuseBridgeMonitor** を「終了」→「実行」
   して、見張りを読み直させる。
   （自動再起動を待つだけでもよいが、確実なのは手動の終了→実行）
4. ブリッジで状態が新しくなるのを確認し、休止ボタンをもう一度押して
   解除する。

注意: venv を作り直した場合は、タスクが指す python の場所が変わる
ことがある。そのときはタスクの再登録が必要（登録スクリプトを
実行し直す）。

## 一時的に止める／再開する（3つの方法の違い）

| 方法 | 止まるもの | プロセス | 再開のしかた | 向いている場面 |
|---|---|---|---|---|
| ブリッジの休止ボタン | つつき・自動承認・起床の合図だけ | 動いたまま | もう一度押す（即座に再開） | しばらく手動で承認したい、様子を見たい |
| タスクの「終了」 | 見張りの全部 | 止まる | タスクの「実行」、または次回ログオン | 見張りの差し替え、短時間の完全停止 |
| タスクの「無効化」 | 自動起動そのもの | 止まる＋次回も起きない | タスクを「有効化」してから「実行」 | 長く使わない、切り分けで完全に外したい |

- 休止中は、ブリッジのバナーとカードに「休止」と出る。見張り自体は
  生きていて状態の記録は続くので、解除すれば間が空かずに再開する。
- タスクを終了・無効化すると状態ファイルが更新されなくなり、
  ブリッジには「見張りが止まっています」と出る（異常ではなく、
  止めた結果として正しい表示）。

## アンインストール

1. タスクスケジューラで **MuseBridgeMonitor** を無効化し、次に削除。
2. 見張りのファイル一式（`R:\claude\claude-bridge\`）は、残しておいても
   害はない。消す場合はフォルダごと。
3. `%LOCALAPPDATA%\traytools\` の状態・合図ファイルは tray-tools 側の
   ものなので、見張りだけを外す場合は消さなくてよい（ブリッジは
   「見張りが止まっています」と出すようになる。ブリッジ自体を
   出したくなければ、大きさをステルスにするか、環境に合わせて
   非表示になる）。
4. アンインストール後は、承認はすべて手動に戻る。郵便受けによる
   起床も止まる（チャット自体は通常どおり使える）。

## よくある失敗と対処

| 症状 | 見当 | 対処 |
|---|---|---|
| ブリッジに「見張りが止まっています」が居座る | 見張りが落ちて自動再起動も届いていない／タスクが無効化されている | 本書「直し方」の順に。前回の実行結果とログ末尾を控えて報告 |
| 承認カードが自動で押されない | 休止中／画面ロック中（判定できない間は押さない仕様）／委任の条件の範囲外のカード | 休止を解除する。ロック中は解除後に扱われる。範囲外は合図ファイルで知らされるので手動で押す |
| カードが出ているのに合図が来ない | 合図ファイルが書かれていない（見張りが止まっている）可能性 | 状態ファイルの更新日時を見る。古ければ「直し方」へ |
| 見張りのプロセスが2つ見える | 正常（venv のスタブ＋本体） | 何もしない。3つ以上でも、ミューテックスで実際に動くのは1本 |
| スリープ復帰直後、経過時間の表示が跳ねる | スリープ中は時計が進むため | 数分で正常に戻る。戻らなければ状態ファイルの更新日時を確認 |
| PC再起動後、見張りが起きてこない | タスクの登録が壊れた／venv を作り直してパスが変わった | タスクの「前回の実行結果」を確認。登録スクリプトを実行し直す |
| ログ（muse_monitor.log）が肥大化する | 長期運用の蓄積 | Claude／Muse に相談（ローテーションの追加を検討） |
