## 結果

職場のPCで「明日から便利！」になる新機能の案5つ。base 時点の README.md・AGENTS.md・CLAUDE.md を読み、既存機能（画面アイコンのメニュー構成、Rapture 付箋、定型文、クリップボードの書式落とし、Teams の一人会議、画面ミラー、プレゼン支援、タスクバーウィジェット、Copilot 状態監視、スリープ抑止／マウスジグラー、フォルダ監視移動、診断の QR など）と重ならないことを確かめてある。全案共通で、トレイアイコンは増やさない／新しい IPC ポートは作らない／データを PC の外へ送らない、を守る前提。

新規（既存機能の延長ではない）のは 1・3・4 の3案。2 は音声機能の、5 はクリップボード書式落としの延長。

### 1. 窓レスキュー「画面の外の窓を戻す」（新規）

- **どんな困りごとを解くか**：拡張ディスプレイを外した／繋ぎ直したあと、会議アプリやメールなどの窓が画面の外に残って「起動しているのにどこにも見えない」ことが起きる。タスクバーで選んでも戻せず、アプリの再起動や Shift+右クリックの取り回しに頼るしかない。ドッキングの抜き差しがある日は毎日起こりうる。
- **使い方**：画面アイコンのメニューから「画面の外の窓を戻す」を1回押すだけ。どのモニタとも重なっていない窓（タイトルバーが掴めない窓を含む）だけを、プライマリの作業領域の中へ大きさを保ったまま寄せる（画面より大きい窓だけ縮める）。最小化中の窓・全画面の窓・tray-tools 自身の付箋やミラー窓は触らない。直前の位置はメモリに1手だけ覚えて「戻した窓を元に戻す」も出す。
- **既存機能との関係**：新規。最前面固定（`Ctrl+Alt+T`）は「今手前にある窓の固定」で、窓の列挙や救出はしていない。タスクバーウィジェットはトレイの代わりで、他のアプリの窓は扱わない。
- **実装の見込み**：**小〜中**。Win32 の `EnumWindows` / `GetWindowRect` / モニタ矩形の列挙 / `SetWindowPos`（`SWP_NOACTIVATE` でフォーカスは奪わない）を ctypes で叩き、アイコンを持たない通常モジュールとして画面アイコンのメニューから呼ぶ形（リポジトリの規約どおり）。入力の自動生成も UIA も使わないので EDR 面は穏やか。詰まりそうな点：管理者権限で動く窓は UIPI で動かせない（「動かせなかった窓が何件」と通知して済ませる）、DPI 混在環境での座標の扱い、スナップ済み窓の復元矩形の扱い。
- **「明日から使える」度**：**高**。設定・登録・準備は一切なし。困った瞬間に押すだけ。

### 2. 会議前チェック「音、聞こえる？」（音声機能の延長）

- **どんな困りごとを解くか**：Teams 会議に入ってから「声が聞こえない」「マイクがミュート／別デバイスだった」に気づく事故。出力先の切替は既にあるが、「いまの組み合わせで本当に聞こえて喋れるか」を確かめる手段が無く、会議の冒頭で手間取る。
- **使い方**：画面アイコンのメニュー（音声側でも可）から「会議前チェック」を開くと小さなパネルが出る：いまの出力先名＋「テスト音を鳴らす」ボタン（押したときだけ鳴る）、いまのマイク名＋ミュート状態＋喋ると反応するレベルメーター、「ヘッドセット／マイク ON・音あり」のような1行の結論。録音はしない（レベルだけ見て捨てる）。問題があればその場で既存のデバイス切替に進める。
- **既存機能との関係**：音声 Feature の延長。既存は「切替」と「状態のアイコン表示」までで、入出力の実地確認（特にマイクのレベル）は無い。一人会議の立ち上げとも別（あちらは会議を作る、こちらは入る前の確認）。
- **実装の見込み**：**中**。既存の `mic_control` / pycaw（Core Audio COM）でデバイスとミュートは取得済み。マイクのレベルは `IAudioMeterInformation` のピーク値ポーリングで足りる（録音 API は使わない）。詰まりそうな点：COM オブジェクトの保持の仕方（リポジトリの落ちる書き方の規約に従い、関数内に閉じる）、ヘッドセット側の物理ミュートは検出できない（「レベルが出ない＝ミュートか物理スイッチか」までを文面で案内する）。
- **「明日から使える」度**：**高**。登録済みデバイスを使うので追加設定なし。未登録でも Windows の既定デバイスでチェックが動く形にする。

### 3. さっきのファイル（新規）

- **どんな困りごとを解くか**：「さっき受け取った／落としたあのファイル、どこだっけ」。ダウンロード、デスクトップ、ドキュメントなど置き場が散らばり、名前もうろ覚えで、探し直しが日に何度も起きる。ブラウザのダウンロード一覧やエクスプローラの行き来では、フォルダを横断して新しい順には見られない。
- **使い方**：画面アイコンのメニューから開くと、ダウンロード／デスクトップ／ドキュメントの直近ファイルを更新時刻の新しい順に一覧表示（今日・昨日の見出し付き）。文字入力で絞り込み（既存の `picker.py` を再利用）、プレビューに「3分前・サイズ・置き場のフォルダ」が出る。`Enter` で関連付けで開き、別キーでフルパスをクリップボードへ。開くたびにその場で走査し直すので、さっき来たファイルもすぐ出る。
- **既存機能との関係**：新規。フォルダブックマークは「登録したフォルダへの移動」、フォルダ監視移動は「ルールで自動で移す」、あっふの Everything 検索は「ファイラの中で名前で全体検索」。こちらは「フォルダ横断・新しい順・ファイラの外」という別の仕事で、入口も対象も重ならない。
- **実装の見込み**：**小**。`os.scandir` で対象フォルダの直下＋1階層だけを見て時刻順に並べる（上限件数で打ち切る）＋ `PickerWindow`。索引も常駐スキャンも要らない。詰まりそうな点：オンライン専用ファイルは属性を見て印を出す（メタ情報の取得ではダウンロードを始めない。開いたときだけ落ちてくる、その旨をプレビューに出す）、巨大なフォルダでの走査時間（階層と件数の上限で抑える）。
- **「明日から使える」度**：**高**。対象フォルダは固定の既定で、設定なしで初日から効く。

### 4. きょうの足跡（日報メモ）（新規）

- **どんな困りごとを解くか**：在宅勤務の終業時、日報や工数の記録を書く段になって「今日なにをどれだけやったか」を思い出すのに時間がかかる。会議と作業の切り替わりが多い日ほど曖昧になる。
- **使い方**：朝、画面アイコンのメニューで「今日の足跡を開始」を押した日だけ、常駐が前面の窓（アプリ名＋タイトル）を約30秒ごとにそっと記録し、区間の集まりとして貯める。夕方「きょうの足跡」を開くと時系列の一覧とアプリ別の合計時間が出て、「日報用にコピー」で `09:00-10:30 会議アプリ「◯◯会議」` のような下書きテキストをクリップボードへ（貼る先と直すのは自分）。「今日を消す」「一時停止」も同じ窓に置く。
- **既存機能との関係**：新規。操作の記録（`action.log`）は tray-tools 自身の動作ログで、仕事の振り返りには使わない。診断は障害時の情報集めで目的も中身も別。
- **実装の見込み**：**中**。Win32 の `GetForegroundWindow` / `GetWindowText` / プロセス名の取得を既存のポーリングに相乗りさせ、区間の集計は純関数にできる。保存先はリポジトリの外（`%LOCALAPPDATA%\traytools\`）で、外へは一切送らない。詰まりそうな点：窓タイトルには会議名や件名が入りうるので、**既定はオフ・開始は明示の1クリック・保存はローカルのみ・消去ボタン**を初版の必須要件にする。会社の決まりで記録自体が憚られる環境では使わない、という線引きも文面で要る。ロック画面中は記録を止める。
- **「明日から使える」度**：**中**。設定は不要だが、朝に開始を押すひと手間がある。その代わり押した当日の夕方から効く。

### 5. 改行をほぐす（プレーンテキスト整形）（クリップボード機能の延長）

- **どんな困りごとを解くか**：PDF やメール、チャットからコピーしたプレーンテキストは、数十文字ごとの強制改行、行の途中で切れた URL、空行だらけ、といった崩れが多く、資料やメールに貼る前に手で繋ぎ直す作業が毎回起きる。既存の書式落としは HTML 形式が載っているとき専用で、テキストだけのコピーには出てこない。
- **使い方**：入口は今と同じ `Ctrl+Alt+V` の一覧。クリップボードがテキストだけのときにも「改行をほぐす」項目を先頭に出し、選ぶと既存のプレビュー窓と同じ作りの前後見比べが出る。整え方は控えめに固定：段落（空行区切り）は保ち、文末記号で終わらない行は次の行と繋ぐ／箇条書き・番号・インデント行は繋がない／行末空白の除去と3行以上の空行の圧縮／切れた URL 行の連結。`Enter` でクリップボードに載せるまでで、貼り付けは自分で押す（既存方針どおりキー送信はしない）。
- **既存機能との関係**：書式落とし（`clipboard_format.py`）の延長だが、対象が違う（あちらは `HTML Format` の段階落とし、こちらはテキストのみが載っている場合）。退避して元に戻す仕組み（メモリに1つだけ）もそのまま再利用するので、試して違えば戻せる。
- **実装の見込み**：**小**。整形は純関数でテストが書きやすく、窓と退避は既存の流用。一覧に項目を出す条件を「テキストのみのときにも出す」へ広げるのが主な変更。詰まりそうな点：コード片・住所・表など改行が意味を持つテキストの誤連結（インデント行を繋がない、プレビュー必須、自動では決して適用しない、で抑える）。判定の暴走より「繋ぎ足りない」側に倒すのが安全。
- **「明日から使える」度**：**高**。入口も操作も既存と同じで、設定なし。

### イチオシ

**1 の窓レスキュー**。理由は3つ：(1) 前提の環境（ノート画面がプライマリ＋正面の拡張ディスプレイ）で構造的に起きる困りごとで、起きると作業が完全に止まる。(2) 設定なし・データなし・入力の自動生成なしで、5案の中でいちばん職場の制約に触れず、失敗しても「元に戻す」で巻き戻せる。(3) 実装が小〜中で、既存のどの機能とも競合しない。次点は 5（実装がいちばん小さく毎日効く）。
