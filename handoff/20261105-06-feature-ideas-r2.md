## Claude の5案（第1回の結果を見る前に作成）

### C1. 会議前カウントダウン
Outlook の予定を COM でローカルに読む（送信なし）。次の会議の開始5分前に、正面（セカンダリ）画面の端へ小さな帯
「10:30 定例まであと5分（Teams）」を出す。帯を押すと予定本文の Teams 参加リンクを開く。
Windows の通知や Outlook のリマインダはノート側の画面に出て見落としやすい・集中していると流れる、を解く。
中規模。詰まりそう：Outlook COM の起動待ち・新しい Outlook（COM が無い）だと使えない。

### C2. 画面共有前のおそうじ
ワンクリックで「共有の準備」：Rapture の付箋・画面ミラー・タスクバーウィジェットなど tray-tools 自身の浮いている窓を一時的に隠す、
デスクトップのアイコンを隠す、Windows の通知を止める（集中モード）。もう一度押すと元に戻す。
画面共有で見せたくない付箋や通知が映る事故を防ぐ。小〜中。詰まりそう：集中モードの切替に公開 API が無い。

### C3. 今日の時間の使い方（作業ログ）
前面の窓（アプリ名だけ）を1分ごとに記録し、夕方に円グラフと時系列で出す。日報の材料。データは PC 内のみ。
中規模。※Muse の M4「きょうの足跡」とほぼ同じ発想。

### C4. パス変換コピー
エクスプローラーで選んだファイルのパスを「UNC（`\\server\share\...`）」「親フォルダだけ」「`"` 付き」「Teams/メールに貼る file: リンク」
の形を選んでコピーする。社内でファイルの場所を人に伝える場面で、ドライブ文字のパスを送ってしまい相手が開けない、を解く。小。
詰まりそう：エクスプローラーの選択の取り方（Shell COM）、OneDrive 配下は SharePoint の URL にしたいが取れるか不明。

### C5. Copilot 定型プロンプト差し込み
選んだ文章を「要約して」「敬語に直して」「英訳して」などの型に包んで、M365 Copilot の入力欄へ UIA で流し込む（送信は人が押す）。
既存の copilot_loop の口と定型文機能を流用。小〜中。詰まりそう：選択中の文章の取り方（コピーを人にしてもらうのが安全）。

## Claude から Muse 案への批評

- **M1 窓レスキュー**：仕組みは堅く安全。ただ前提の「在宅勤務中心」では、ドッキングの抜き差しは毎日は起きにくく、Windows 11 はモニタを外すと多くの窓を自動で寄せる。
  頻度が肝。逆に効く場面（RDP の後・プロジェクタ接続の後・古いアプリの子窓）を挙げられると強くなる。`Win+Shift+矢印` で足りる人も多い点にどう答えるか。
- **M2 会議前チェック**：毎日の会議に効く。ただ Teams 自体に「デバイスの設定」とテスト通話があり、重なりの説明が要る。
  Teams より速い（1クリック・会議に入る前に終わる）なら勝てる。M2 と C1 は「会議の5分前」という同じ瞬間を狙っているので、**C1 の帯から M2 のチェックへ進める一体化**も考えられる。
- **M3 さっきのファイル**：Claude の評価ではいちばん「明日から便利」に近い。気になる点：職場の PC は OneDrive の既知フォルダー移動でデスクトップ/ドキュメントが OneDrive 配下にあることが多い（オンライン専用ファイルの扱いは書いてあって良い）。
  Outlook で開いた添付は一時フォルダ（`INetCache\Content.Outlook`）に落ちるので、そこも対象に入れると「さっきメールで来たやつ」が拾える。保存場所を選ばずに開いたファイル問題に効く。
- **M4 きょうの足跡**：C3 と同じ発想で、Muse 案のほうが丁寧（既定オフ・明示開始・消去ボタン）。統合して M4 側を残すのがよい。
  ただし「職場で自分の作業を記録するツール」は規程上グレーになりうるので、3案に残すなら最後に陽太さんの判断を要する点として明記したい。
- **M5 改行をほぐす**：小さく毎日効く。日本語の行を繋ぐときは空白を入れず、英語の行は空白を入れる、の区別が要る（混在文もある）。
  「繋ぎ足りない側に倒す」方針に賛成。
