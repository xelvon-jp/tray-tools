### 仕様1. 改行をほぐす（M5）

- **一言**：テキストのコピペの強制改行を繋いで読みやすくする
- **使う場面**：
  1. PDF の資料から文章をコピーしてメールや資料に貼ると、数十文字ごとに改行が入ってガタガタになる。貼る前にほぐして段落の形にする。
  2. チャットの投稿やメールの本文をコピーしたら URL が途中で切れていた。繋ぎ直して開ける形で貼り直す。
- **画面イメージ**：

```
Ctrl+Alt+V の一覧（クリップボードがテキストのみのとき）
┌ 定型文 ──────────────────────────────┐
│ ▸ ✂ 改行をほぐす（いまのクリップボード） │ ← 先頭に出る
│   （以下、定型文の一覧）               │
└──────────────────────────────────────┘
        ↓ 選ぶとプレビュー窓（既存の左右見比べの作り）
┌ 改行をほぐす ────────────────────────────────┐
│ 元のまま                │ ほぐした結果          │
│ 会議の日程については、   │ 会議の日程については、 │
│ 別途ご連絡します。担当の │ 別途ご連絡します。     │
│ 田中さん…               │ 担当の田中さん…       │
│                         │                       │
│ [Enter] この形にする   [Ctrl+Z] 元に戻す  [Esc] やめる │
└──────────────────────────────────────────────┘
```

- **操作の流れ**：何かテキストをコピーした状態で `Ctrl+Alt+V` → 先頭の「改行をほぐす」を選ぶ → 前後の見比べで確かめる → `Enter` でほぐした形をクリップボードに載せて閉じる（貼り付けは自分で押す。既存方針どおりキー送信はしない）。違えば窓の中でも閉じた後でも「元に戻す」で戻せる。ほぐす所が無い文章では「整える所はありませんでした」と出して載せない。
- **決まり**：
  - 入口はクリップボードが**テキストのみ**のときだけ（HTML 形式があるときは既存の書式落としが担当し、こちらは出ない）。整え方は**1種類だけ**（段階制なし）。
  - 空行が2つ以上続いたら1つに詰める。段落（空行区切り）は保つ。行末の空白（半角・全角）は取る。
  - 次のどれかに当たる行は**繋がない**：前の行が文末記号（`。．.!?！？` と閉じ括弧・閉じ引用符）で終わる／次の行が箇条書き・番号・見出しの頭（`・-*•●■□◆【`、`①`、`1.`、`1)`、`(1)`、`第1`）で始まる／次の行が字下げ（行頭の空白）で始まる／タブを含む行（表のコピー）の前後／**前の行が半角ハイフンで終わる**（単語の分割か複合語か判別できないため）。
  - URL の連結：前の行の最後の空白以降に `://` を含む（＝URL の途中）ときだけ、次の行が空白なしに URL の文字で始まれば空白を入れずに繋ぐ。
  - 日英の空白：前の行の最後の文字と次の行の最初の文字が**両方とも半角英数字**のときだけ空白1つを入れる。それ以外は空白なしで繋ぐ。
  - コードかどうかの自動判定はしない。プレビューが警告の代わりで、自動では決して適用しない。「元に戻す」は既存の退避（メモリに1つだけ）をそのまま使う。
- **実装の規模**：**小**。変えるのは書式落としのモジュールにほぐし整形の純関数群を足す（約150行）＋入口の一覧に項目を出す条件の追加＋プレビュー窓の流用（段階切替の代わりに前後表示だけ使う形に小変更）。テストは整形の純関数に約100行（判定表のケースを並べる）で、VM でも全部回せる。
- **実機で確かめること**：実際の PDF・メール・チャットのコピーで繋ぎの当たり具合（特に混在文と箇条書きの誤判定）、プレビュー窓が HTML 用のものと見分けられるか、大きなテキストでの退避（上限 16MB）の扱い。

### 仕様2. さっきのファイル（M3）

- **一言**：直近のファイルを置き場の横断で新しい順に探す
- **使う場面**：
  1. メールで開いた添付を、保存し直そうとして「どこに居るのか分からない」。一時フォルダも対象なので「さっき開いた添付」が出てくる。
  2. ブラウザで落とした資料とデスクトップに置いた資料のどちらが新しい版か分からない。横断で時刻順に並ぶので見分けられる。
- **画面イメージ**：

```
画面アイコンのメニュー → 📄 さっきのファイル
┌ さっきのファイル ──────────────────────────┐
│ 提案書_v2.pdf            ・ 3分前          │
│ 会議メモ.docx            ・ 26分前         │
│ 見積書.xlsx              ・ 1時間前  ☁     │
│ （絞り込み入力）                            │
│ ─ プレビュー ──────────────────────────   │
│ 見積書.xlsx／1.2 MB／デスクトップ／         │
│ C:\Users\…\Desktop\見積書.xlsx             │
│ ☁ オンライン専用（開くとダウンロードされます）│
│ [Enter] 開く  [Ctrl+C] パス  [Ctrl+Enter] 置き場 │
└────────────────────────────────────────────┘
```

- **操作の流れ**：メニューから開く（窓を先に出し、フォルダごとに非同期で埋まる）→ 文字入力で絞り込む → `Enter` で関連付けで開く／`Ctrl+C` でフルパスをコピー／`Ctrl+Enter` で置き場のフォルダをそのファイルを選んだ状態で開く。開くたびに走査し直す（キャッシュしない）。
- **決まり**：
  - 対象は Known Folder（`SHGetKnownFolderPath`）で実体を解決した**ダウンロード／デスクトップ／ドキュメント**と、レジストリ `HKCU\Software\Microsoft\Office\<版>\Outlook\Security\OutlookSecureTempFolder` から取る **Outlook 添付の一時フォルダ**（読むだけ。取れなければ黙って外す）。横断が看板なので、この対象の広さは必須要件。
  - 深さ：ダウンロードとデスクトップは直下＋1階層、ドキュメントと Outlook 一時フォルダは直下のみ。範囲は**直近7日・全体で200件**まで（新しい順）。
  - フォルダ自体、ダウンロード中・一時ファイル（`.crdownload`／`.part`／`.tmp`）は出さない。一覧の行は「ファイル名＋経過時間」、プレビューにサイズ・置き場・フルパスを出す（同名ファイルの区別のため）。
  - オンライン専用ファイルはファイル属性で判定して ☁ の印を付け、プレビューに「開くとダウンロードされます」と出す。メタ情報の取得では中身を落としてこない。
  - 性能の予算：フォルダあたり 0.5 秒・全体 1.5 秒。超えたフォルダは途中までで打ち切り「（時間切れで一部）」と出す。走査はワーカースレッドで行い、窓の操作を止めない。
- **実装の規模**：**小〜中**。新規モジュール（走査・対象解決・並べ替え）約300行＋ピッカーに `Ctrl+C`／`Ctrl+Enter` のキーコールバックを足す小変更＋画面アイコンのメニューに項目追加。テストは合成フォルダでの走査・並べ替え・対象外の判定が中心（約100行、VM でも回せる）。
- **実機で確かめること**：Known Folder が OneDrive の実体を正しく指すか、Outlook のレジストリ値が読めて添付が実際にそこに居るか、☁ の属性が実ファイルで立つか、ウイルス対策の走査がある環境で時間予算に収まるか、`explorer /select` が効くか。

### 仕様3. 窓レスキュー（M1）

- **一言**：画面の外に取り残された窓を全部まとめて戻す
- **使う場面**：
  1. 会議室のディスプレイやドッキングを外したあと、アプリは起動しているのに窓がどこにも見えない。タスクバーから選んでも出てこない窓を戻す。
  2. 解像度の違うリモート接続を切ったあと、ダイアログが画面の外に残って作業が止まった。対象を特定しなくてもまとめて救出する。
- **画面イメージ**（窓は出さず、メニューと通知だけ）：

```
画面アイコンのメニュー
  🪟 画面の外の窓を戻す
  ↩ 戻した窓を元に戻す   （救出した直後だけ出る）

通知（自前の小さなパネル）
  「3件の窓を画面内に戻しました」
  「1件は動かせませんでした（◯◯）」   （あるときだけ）
  「画面の外の窓はありませんでした」     （0件のとき）
```

- **操作の流れ**：メニューで「画面の外の窓を戻す」を押すだけ。対象の窓がまとめて寄り、結果が通知に出る。寄せた直後なら「戻した窓を元に戻す」で一括で元の位置に戻せる（記録はメモリのみ・再起動で消える）。
- **決まり**：
  - 対象は、見えていて最小化されておらず、最大化でも全画面でもなく、**タイトルバーを持つ普通の窓**のうち、**タイトルバーの帯（上端からタイトルバーの高さ分）がどのモニタの作業領域にも入っていない**もの。一部はみ出しでもタイトルバーが掴めなければ対象、掴めれば対象外。
  - **別の仮想デスクトップにある窓は対象外**（画面外と誤認して引っ張らない）。タイトルバーを持たない窓（付箋・オーバーレイなど tray-tools 自身の浮き窓を含む）とツール窓も対象外。
  - 寄せ先はその窓にいちばん近いモニタ（`MonitorFromWindow` の NEAREST）の作業領域。大きさは保ち、作業領域より大きい窓だけ縮める。複数を同時に救出したら、左上を少しずつずらして置く（同じ位置に重なって互いを隠さないため）。フォーカスは奪わない（`SWP_NOACTIVATE`）。
  - 動かせなかった窓（管理者権限の窓など）は件数とアプリ名を通知する。対象が0件のときも通知する（押した手応えを残す）。
- **実装の規模**：**小〜中**。新規モジュール約250行（窓の列挙と移動は Win32 を ctypes で。タイトルバーの内外判定は矩形だけの純関数に分ける）＋画面アイコンのメニューに2項目。アイコンは増やさない。テストは判定の純関数が中心（合成した矩形で約80行、VM でも回せる）。実窓の列挙・移動は実機のみ。
- **実機で確かめること**：仮想デスクトップの窓を誤って引っ張らないか、管理者権限の窓で失敗通知になるか、DPI の違うモニタ混在でタイトルバーの判定がずれないか、最大化・スナップした窓を誤判定しないか、付箋など自前の窓が対象外のままか。

### 作る順番の提案

1. **M5 改行をほぐす**：いちばん小さく、純関数＋既存の窓で完結する。毎日の動作に効くので「作って使う」の手応えが最も早く得られ、判定表の当たり具合も日常のコピーで自然に検証できる。
2. **M1 窓レスキュー**：新規モジュール1つで自己完結し、職場環境への依存（レジストリ、Known Folder、ウイルス対策）が無い。起きる頻度は低い分、M5 の様子見の期間と並行しても負担にならない。
3. **M3 さっきのファイル**：価値は高いが、実機でしか分からない前提（Known Folder の実体、Outlook のレジストリ、☁ 属性、走査の詰まり）が最も多い。先に1回だけ実機で「対象フォルダが想定どおり取れるか」を確かめてから作ると手戻りが無い。
