# 見張りの休止 — 見張り側(Claude)への仕様

陽太さんの指示: 「ブリッジに対する操作で、Claude による見張りを休止させたい」。
パネル(ブリッジ)側は Muse が実装済み(このブランチ)。見張り側はこの仕様で
従ってもらう分だけが残っている。十数行の想定。

## 合図ファイル(契約)

- パス: `%LOCALAPPDATA%\traytools\muse_bridge_pause.json`
  (状態ファイル muse_bridge_status.json と同じフォルダ)
- 形式: `{"paused": true, "at": <epoch秒>, "by": "bridge"}`
- 書くのはブリッジだけ(bridge_control.set_paused)。ボタンはバナーの右、
  たたむボタンの左隣(縦棒2本の絵。休止中は橙)。
- 読めない・壊れている・paused が true でない → 「休止していない」として扱う
  (fail-open: 合図の破損で見張りが止まり続けないため)。

## 見張り側に頼みたいこと

1. ポーリングのたびに合図ファイルを読む(状態ファイルの書き出しと同じ周期でよい)。
2. `paused: true` の間は、能動的な動作を止める:
   - つつき(入力欄への空白投入などのカード表示トリガ)
   - 承認カードの自動押下
   - Claude の起床(郵便受けの request 送信を含む)
   画面の読み取り自体を続けるかどうかは見張り側の都合でよいが、次の 3 を守ること。
3. 休止中も状態ファイル(muse_bridge_status.json)は通常周期で書き続け、
   `"paused": true` を含める。last_poll が止まると、ブリッジが「見張りが
   止まっています」という異常表示を出してしまうため(休止は異常ではない)。
   kind は直前のまま保持でよい。
4. 再開(paused でなくなった)ら通常動作に戻る。合図ファイルは消さなくてよい
   (ブリッジが paused: false に書き換える)。
5. 任意: 休止・再開を bridge_journal に "monitor" イベント
   (phase="pause" / "resume")で残すと、後から時間を数えられる。

## ブリッジ側の表示(実装済み)

- 合図が paused の間、バナーは「見張り休止中 / ブリッジのボタンで再開できます」、
  カードの「見張り」は「休止」。last_poll が止まっても異常表示にはしない
  (coop_view の paused 判定が停止判定より優先)。
- したがって見張り側が未対応の間は、見た目は休止中でも見張りは動き続ける。
  対応が入って初めて実態と一致する。この文書がその対応の仕様。
