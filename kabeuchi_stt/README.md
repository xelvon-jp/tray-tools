# コダマ（KODaMA）— 声に出せば、返ってくる

**K**eyboard-free **O**ral **D**ictation **a**nd **M**essage **A**ssembly の頭文字（小文字の a は、前置詞ではなく接続詞の and）。
「木霊（こだま）」と「言霊（ことだま）」のダブルミーニング: 声に出した言葉が、そのまま AI へ届き、返ってくる。
旧名「壁打ち文字起こし」。フォルダ名・ファイル名・設定のキー名は、つながりが壊れないよう `kabeuchi_stt` のまま。

しゃべった内容を、**下書き**に溜めてから、確定したときだけ AI アプリ等の入力欄へ届ける、ローカル完結のツール（音声は外に出さない）。録音は残り、終わったあとに録音全体を清書して履歴に保存する。
版は `version.py`（例 `20261123-12`、画面タイトルにも表示）。仕様は `SPEC.md`、AI 対話（宛先・配達・確定）の詳細は `SPEC_dialogue_mode.md`、設計メモは `DESIGN_stageA.md`・`DESIGN_unified_gui.md`。

**守っていること**
- 下書きの内容を、利用者が何も操作していないのに宛先へ入力・送信しない。自動確定・自動送信はしない。
- このツールが文字をクリップボードへ入れてよいのは、利用者が明示的にコピー（Ctrl+C／右クリック）したときだけ。配達の貼り付けのための一時使用（退避→貼り付け→復元）だけは例外。

## セットアップ

```powershell
$env:PYTHONUTF8=1
python -m venv $env:USERPROFILE\.venvs\kabeuchi-stt
& $env:USERPROFILE\.venvs\kabeuchi-stt\Scripts\python.exe -m pip install -r requirements.txt
```
venv はプロジェクト外に置く。依存は faster-whisper / sounddevice / numpy / PySide6（録音の圧縮は faster-whisper の依存の PyAV を使う）。
宛先への書き込み（UI Automation）は、別プロセスのワーカー（`dialogue_worker.py`）が、comtypes の入った別の python で行う（本体は COM を使わない）。ワーカーの python は設定 `dialogue.worker_python`（空＝既定の場所）。

## 起動

```powershell
$env:PYTHONUTF8=1
$py = "$env:USERPROFILE\.venvs\kabeuchi-stt\Scripts\python.exe"
& $py main.py                       # GUI（トレイ常駐。2つ目を起動すると既存の窓が出る）
& $py main.py --hidden              # 窓を出さずトレイ常駐だけで起動
& $py main.py --no-tray             # トレイを使わない（閉じると終了）
& $py main.py --wav out\xxx.wav     # 既存の録音（WAV／Opus）の清書だけやり直す（GUIなし。置換辞書は適用、履歴には載せない）
& $py main.py --wav out\xxx.wav --model medium
& $py main.py --list-devices        # 入力デバイス一覧（マイクは開かない）
```

2. 起動したらタスクバーのアイコンを右クリック →「タスクバーにピン留めする」。
3. うまくいかないとき（アイコンが python のままだったり、ピン留めしたものを開くと何も起きないとき）は、`コダマ.lnk` を右クリック →（Windows 11 は「その他のオプションを確認」）→「タスクバーにピン留めする」。

## 使い方

使い方は1つだけ（モードの切替はない）。**録音ボタン＝セッションの開始／停止**。

1. **宛先を選ぶ**: 宛先の行のコンボで、プリセット（Claude・Muse・Copilot など、自分で付けた名前）か「なし（記録だけ）」を選ぶ。新しい宛先は、コンボ末尾の「入力欄を選んで追加…」→ 宛先の入力欄をクリック（30 秒以内、Esc でやめる）→ 名前を付けて保存。
2. **［録音］**: セッション開始。マイクを開きっぱなしにし、録音（WAV）も続く。しゃべって **1.2 秒（`dialogue.utterance_gap_sec`）の無音**で区切れると、その発話を small（既定。`dialogue.model`）で認識し、下書き欄に**白い文字**で出る。
3. **下書き欄**（主役。1つの編集可能な欄）: 確定前の内容。キーボードで自由に直せる。認識結果は末尾へ追記されるが、編集中の内容・カーソル・選択・スクロールは壊さない（カーソルが末尾にあるときだけ追記分のあとへ進む）。直した内容が確定の正本で、以後の追記は直した内容の末尾へ付く。欄の末尾には進み具合が出る（下記）。
4. **確定**: 利用者の操作だけ。**［確定して届ける］／Ctrl+Enter（下書き欄にフォーカス）／ヘッドセットの多機能ボタン／マウスの戻る・進むボタン／舌打ち2回（実験・既定OFF）／ホットキー**はすべて同じ操作で、下書き全体を宛先へ届ける。清書待ち（認識中）の発話があるときは、揃うまで待つ。
5. **［停止］**: セッション終了。録音全体を清書して履歴に保存する（下記）。

### 下書き欄の末尾の表示

| 状況 | 表示 |
|---|---|
| 喋っている | 喋った長さに比例して伸びるバー（10 秒で折り返す）と「喋っています 0:12」 |
| 黙った | 「無音 0.5秒（あと0.7秒で認識開始）」（バーは止まる） |
| 区切れた（認識待ち） | 「認識中（small・あと約N秒）」 |

認識が済むと、その場で白い文字に置き換わる。声のない発話（無音・環境ノイズ・最短長 `min_utterance_sec` 未満の物音・「ご視聴ありがとうございました」等の定番の幻覚だけのもの）は、バーも文字も出さない。同じ語・文の繰り返しの暴走（3回以上）は1回にまとめる。

### 状態バッジと警告（録音の行）

| バッジ | 意味 |
|---|---|
| 録音中 | 話している |
| 無音待機中 | セッション中で、黙っている |
| 認識中（N件） | 認識待ちの発話が N 件 |
| 送信中 | 配達中 |
| ✓ 完了 | 配達が成功した直後（約 1.5 秒） |
| 保留中 | 一時停止（保留）中 |
| 停止中 | セッションをしていない |
| 清書中 N%（あと約…）／清書待ち | 停止中に、録音全体の清書が進行中／待機中 |

バッジの上へマウスを置くと、使用中のモデル（認識・清書）が出る。録音していないのに喋り続けると、下書き欄が**赤**で点滅して知らせる（喋り終えるまで）。一時停止中に喋り続けると**アンバー**で点滅する。

### 宛先と配達

- 宛先は、窓（プロセス名・クラス・タイトル）＋その中の入力欄・送信ボタン（UI Automation の要素）。セッション中は毎回その宛先へ届け、途中で別のアプリをアクティブにしても、そちらへは送らない。窓が見つからない・複数あるときは、別の窓へは送らず止めて、ヘッダーに短い警告を出す。
- **届ける流れ**: ① UIA で入力欄へ書き込み → 読み戻しで一致を確認 → ② 不一致なら前面化（UIA SetFocus 等）・フォーカス確認 → 貼り付け（Ctrl+V）→ 読み戻し（クリップボードは一時使用して元に戻す。前面になったと確認できるまでキー送信はしない）→ ③ それも不可なら、点の下が宛先であることを確かめたうえでクリック → ④ どれも不可なら中止。
- **［送信までする］**（`dialogue.send_after_deliver`、既定 OFF）: ON のとき、入力欄に届いたと読み戻しで確認できたあと、送信ボタン（UIA。無ければ Enter）を押し、入力欄が空に戻ったかで送れたかを確認する。1回しか試さない。相手が回答中（停止ボタンが見える）なら、最大 `busy_wait_sec`（120 秒）待つ。
- **未配達**: 届けられなかった文は消さず「未配達」で保持する（件数と理由、［再試行］［コピー］［破棄］の行が出る）。セッションを終えるときに残っていれば、［コピー］［破棄］［あとで］を選ぶ。入力は成功したが送信できなかったときは「配達済み・未送信」（入力欄に残る）として記録し、二重入力しない。
- 空の入力欄がプレースホルダー（Muse の「メッセージ」、Copilot の見えない文字 U+FFFC など）を値として返すアプリに対応する（宛先プロファイルの `empty_values`・`input_name`）。
- 宛先が「なし（記録だけ）」のときは、確定しても何も届けず、クリップボードにも入れない（確定済みとして記録に残すだけ）。
- **送信中の表示**: 確定すると、下書き欄の上に「送信中…」のブロックが出て、送った文章を見せる。成功すると緑の「✓ 送信しました」を 1.5 秒出して消える。送信を確認できなかったときは、赤字で残す（クリックか次の確定で消える）。失敗した文は未配達の行に出る。送信中にしゃべった内容は、下の下書きに入る。

### 前置き

宛先の行の［前置き ▾］から保存済みの前置きを選ぶと、いまの下書きの先頭に**灰色のブロックとして1回だけ**入る（×で外せる。入れ直せば置き換わる）。送るときは「前置き＋改行＋下書き」。配達が済むとブロックも消える。**自動では付かない**。前置きの作成・編集・削除は、引き出しの「前置き」タブ。

### 一時停止（保留）

［保留］（録音の行。トレイ・ホットキー `hotkey_pause` からも）は、**新しい発話の取り込みだけを止める**。録音 WAV は続く。すでに話した分は、認識して下書きに入る。もう一度押すと再開。

### 認識開始ライン

音量メーターの上の青い縦線（ドラッグで動かす。`dialogue.voice_min_dbfs`、既定 -50dBFS。ダブルクリックで既定に戻る）。メーターと同じ基準（0.1 秒の平均 RMS）で、これに届く音が一瞬もない塊は、認識へ回さない。周囲の雑音が多いときは右へ、小声が拾われないときは左へ。

### マイクの状態

録音の行のチップ（入力OK／音が小さい／音割れ／ノイズ大（要相談）／音が入っていない／マイク使用中／未録音（話しています）／一時停止中（話しています）／マイク確認中）。サイズは固定で、文言と色だけ変わる。押すと詳細と対処が出る。待機中もマイクを開いてメーターと診断を動かす（設定 `idle_monitor`。窓が見えている間だけ。保存も認識もしない）。

### 画面の部品

- **録音の行**: ［録音／停止］・［保留］・経過時間・状態バッジ・マイクチップ・最前面（画びょう）・⚙・引き出しの開閉。
- **⚙ メニュー**: 設定／WAV を選んで清書／出力フォルダを開く／確定履歴を開く／接続の状態（診断）。「接続の状態（診断）」は、ヘッドセット（HID・ホットキー）・マウス・舌打ちの状態を、選択してコピーできる窓で見せる。
- **引き出し**（右。開くと窓が広がり、下書きも自動で広がる）: **履歴**（検索・行クリックで再生・本文の修正・辞書へ登録・WAV から清書をやり直す・削除）／**用語・置換**（専門用語のチップ・自動置換辞書）／**前置き**／**清書の状況**（直近の清書の一覧・実行中の中断）。
- **確定履歴**: AI 対話で確定したメッセージの履歴（確定時刻・送信済み／未送信／未確認・手修正あり）。⚙ メニューの「確定履歴を開く…」から。
- 窓の大きさ・位置は、引き出しを閉じているとき（`win_geometry_unified`）と開いているとき（`win_geometry_unified_drawer`）で別に記憶する。

### 清書（セッション終了時）

- 設定「録音全体の清書」（`finalize_on_end`、既定 ON）: **する**＝停止したあと、録音全体を「録音全体の清書モデル」（`final_model`。設定画面で選ぶ。大きいほど正確で遅い）で認識し直して履歴に保存する。**しない**＝再認識せず、セッション中の発話ごとの結果（時刻つき）をそのまま履歴の1件にする（待ち時間なし）。
- **清書はセッション中は始めない**（録音が終わってから。ゲート）。次のセッションを始めると、待機中の清書は待つ。実行中のものは、スレッドの優先度を下げて、しゃべっている間の認識を遅くしない（**優先度が実際に効くかは未確認**）。進み具合と残り時間は、停止中の状態バッジ（「清書中 35%（あと約3分）」）に出る。
- 結果が空だったときは、専門用語（hotwords）なしでやり直す。kotoba-whisper は hotwords を渡すと何も出なくなるので、渡さない。
- 履歴・用語辞書・「WAV を選んで清書」「履歴の WAV から清書をやり直す」は、そのまま使える。

### 録音の圧縮（Opus）

保存した WAV は「あとで聞き直せればよい保険」なので、**清書が終わったあと**に Opus（ogg・モノラル・既定 24kbps、拡張子 `.opus`）へ変換して小さくする（1 時間でおよそ 100MB → 6MB 前後）。追加インストール不要（PyAV の libopus。ffmpeg は使わない）。

- 設定（⚙ → 設定 →「共通」）: `audio_compress` = `off`（しない）／`keep`（Opus を作り WAV も残す）／`trash`（WAV はごみ箱へ）／**`delete`（既定。WAV を完全に削除。元に戻せない）**。`audio_compress_kbps`（既定 24）。
- 変換できたときだけ WAV を後始末する。失敗した・長さが大きくずれた・ごみ箱へ移せなかったときは WAV を残し、`error.log` に書く（録音・清書は止めない）。
- **無音カット**（`audio_silence_cut`、既定 ON）: Opus にするとき、4 秒以上の明らかな無音を 0.5 秒に縮める（発話の前後は守る）。縮めた場所は履歴に `cuts_json` として保存し、再生位置・時刻を補正する（**実画面での再生位置の合い方は未確認**）。
- 履歴は圧縮後、録音ファイルの場所（DB の `wav_path` 列）を Opus に差し替える。再生・「WAV から清書をやり直す」・削除は Opus のままで動く。`main.py --wav out\xxx.opus` も可。
- 対象はセッションを終えた直後の清書ジョブだけ。［WAV を選んで清書］や履歴からのやり直しは、圧縮も後始末もしない。

### 認識モデル

設定の「認識モデル」（共通）と、AI 対話・録音全体の清書それぞれのコンボから選べる（tiny／base／small／medium／large-v3-turbo／large-v3／kotoba-whisper〔日本語特化〕）。一覧に取得済み／未取得と、用途別の **【非推奨：理由】** の印が出る（AI 対話の認識は **small 推奨**。medium 以上は、1 発話ごとに 9 秒以上かかる実測）。**モデルの取得は、［モデルの取得・管理…］で利用者が押したときだけ**（通信するのはそのときだけ）。

### ヘッドセット・マウス・舌打ちで確定する

| 方法 | 設定 | 備考 |
|---|---|---|
| ヘッドセットの多機能ボタン | `dialogue.headset_button` | セッション中だけ有効。下記 |
| マウスの戻る／進むボタン | `dialogue.mouse_button`（`""`／`back`／`forward`） | セッション中だけ低レベルフック（`WH_MOUSE_LL`）で拾い、そのボタンは他のアプリへ渡さない（ブラウザの戻る／進むも効かない）。効くのは次のセッションから。**セキュリティソフトに警告されうる。会社 PC での動作は未確認** |
| 舌打ちを2回続けて | `dialogue.click_commit`（実験・既定 OFF） | マイクの音だけで判定（追加ソフト・権限なし）。静かな場所向け。1回だけ・3回以上・会話の中の音では動かない。誤動作・取りこぼしがありうる。効くのは次のセッションから |
| ホットキー | `hotkey_dialogue_commit`（既定は未割り当て） | `RegisterHotKey` |

**ヘッドセット**: 検出経路は2つを併用する（`dialogue.headset_mode`、既定 `auto`）。①HID 直接読み（`dialogue_hid.py`。USB ドングル `dialogue.headset_vid_pid` の入力インターフェースを、共有・読み取り専用で開く。ヘッドセットへ何も書かない）②`RegisterHotKey`（再生/一時停止キーの独占。動画・音楽が同時に反応するのを抑える役目＋予備）。**マイクを使っている間は、多機能ボタンの信号が、再生/一時停止ではなく、電話用インターフェース（HID Page 0x0B）に出る**（実測）ので、HID 直接読みは両方を読む。両方が同じ押下を拾ったときは 0.5 秒以内の重複を 1 回に間引く。診断ツールを用意してある（下記）。**電話用インターフェースの読み取りを入れた版で、本体のセッション中に確定まで届くかは未確認。**

- `headset_probe.bat`（ヘッドセット診断）: 単独で動く窓。［開始］（Enter でも開始）→ 多機能ボタンを1回ずつ押すと、どの経路（HID・再生/一時停止キー・メディアキー）で届くかを見られる（メディアキーの経路は、参考のため観測だけする低レベルのキーボードフックで、本体では使わない）。ヘッドセットへ何も書かず、キーもマウスも送らない。コダマ本体でセッション中は、本体の検出と取り合いになる。
- `hid_watch_all.bat`（全インターフェース監視）: コダマでセッションを始めたあとに起動し、多機能ボタンを数回押して、ボタンがどの HID インターフェースに出るかを、90 秒間（Ctrl+C でも終了）全部読んで記録する（読み取り専用）。

## 設定

⚙ → 設定 → 3つのタブ。

| タブ | 主な項目 |
|---|---|
| 共通 | 表示サイズ（小／標準／大）・マイク・待機中のマイク確認・録音の圧縮（方式・音質）・［モデルの取得・管理…］ |
| 録音と清書 | 録音全体の清書（する／しない）・清書モデル・無音で自動終了（`idle_stop_sec`、0=無効）・改行（すき間の秒数）・ホットキー（録音／保留／窓の表示） |
| AI対話 | AI 対話の認識モデル・ヘッドセットで確定・マウスで確定・舌打ち2回で確定・確定ホットキー・句点で改行・発話の区切り（秒）・入力欄に書きかけがあるとき（追記／上書き／中止） |

［送信までする］は、設定画面ではなく宛先の行のチェック。ホットキーは、Claude アプリ等の常用ショートカットと衝突しない組み合わせにする（Ctrl/Alt/Shift/Win のどれかが必須。`RegisterHotKey` を使い、低レベルキーフックは使わない。**マウスのフックだけは例外**で、上の表のとおり）。

### 句点と改行

- **文中**: 「。」「？」「！」「．」の直後に改行を1つ入れる（`dialogue.newline_after_sentence`、既定 ON。設定画面の「句点で改行する」で、下の空行規則と一緒に切り替える）。数字の小数点「３．５」・英語の「.」・ASCII の「?」「!」は対象外。
- **話を区切った所**（無音で区切った所）: 前の発話が句点系で終わっていれば**空行**（`dialogue.break_blank_line`、既定 ON）。句点が無いまま区切れたときは連結（話の途中かもしれない）。間が `paragraph_force_gap_sec`（3.0 秒）以上なら、句点を補って（末尾の「、」は「。」に置き換え）空行。最長（`max_utterance_sec`）での強制の区切りは区切りではないので連結。
- 手で直した部分には再適用しない。**確定時**、末尾が句読点で終わっていなければ「。」を補う（`dialogue.punctuate_on_commit`、既定 ON。絵文字・記号で終わるものは補わない）。
- 履歴の txt / md の全文は、清書の出力に同じ整形（すき間の長さによる改行。`paragraph_enabled`、`paragraph_gap_sec`、`paragraph_force_gap_sec`）をかける。履歴の元の区間（時刻つき）は無加工。

## 自動置換の適用ルール

1パスのみ（置換結果は再置換しない＝無限ループなし）／同じ位置は長い誤認識を優先（「一時解析」が「解析」に勝つ）／同じ誤認識の重複は後勝ち／空の誤認識は無視。認識（発話ごと）と清書の両方に適用する。

## モデルのオフライン手置き（SSL検査環境向け）

読み込み順: ①`model_dir\<モデル名>\model.bin`（ネットに出ない）→ ②`model_dir` 内の取得済みキャッシュ → ③ダウンロード（［モデルの取得・管理…］を押したときだけ）。失敗すると手順が日本語で出る。別PCで `python -c "from faster_whisper import download_model; print(download_model('small'))"` を実行し、表示されたフォルダの中身を `models\small\` へコピー（直下に `model.bin`）。目安: base 約140MB / small 約460MB / medium 約1.5GB。`models\` が OneDrive 配下だと同期されるので、気になる場合は `model_dir` をフォルダ外の絶対パスに。

## 録音が落ちても

WAV は録音中ずっとディスクへ追記され、1秒ごとにヘッダが確定する。落ちても最後の約1秒手前までは開ける。ヘッダ未確定でもファイルサイズから読めるので `--wav` で清書できる。録音スレッドは認識側の遅れや例外から独立している。

## tray-tools へ組み込む際の注意

- コアは GUI・Qt・COM に依存しない。**別プロセスの Feature として `main.py` を起動する形**を想定（Whisper の推論は CPU を使い切るので、tray-tools 本体と同居させない）。
- tray-tools 側もトレイアイコンを持つので、`--hidden` で起動すると窓なしの常駐になるが、**このアプリ自身のトレイアイコンも1つ出る**。「トレイアイコンは2つ固定」の方針と合わせるなら、組込時に `--no-tray` ＋ tray-tools 側のメニューから窓を出す形にする（`single_instance.notify_existing()` で既存の窓を出せる）。
- ホットキーは tray-tools 側の割り当てと重複しないこと。
- 本人のデータは `%LOCALAPPDATA%\kabeuchi_stt\`。tray-tools の repo に入れない。venv は別（`kabeuchi-stt`。faster-whisper が重いので混ぜない）。
- `on_event` / `on_utterance` / キューのイベントは**別スレッドから呼ばれる**。Qt では Signal 経由で UI スレッドへ。

## 既知の罠

- **時刻なしの認識は長い発話で打ち切る**: 時刻を出さない方式は速いが、30 秒の発話で 15 字しか出ず残りが消えた。時刻を出す方式（約5割遅い）にしてある。
- **前の結果を前置き（プロンプト）にすると句読点が消える**: 句読点なしの結果を次の前置きにすると、次も句読点なしになる悪循環。前置きは句読点を含むときだけ使い、句読点入りの見本文を常に末尾に付ける。見本文がそのまま出てしまう場合に備えて、その文は幻覚として除外する。
- **無音確率だけで捨てると小声が消える**: Whisper 本来の規則（無音確率が高く、**かつ**自信も低いときだけ）にする。
- **認識に 9 秒かかる medium・kotoba の固定コスト**: 短い発話でも 1 回 9 秒ほどかかる（このPCでの実測）。AI 対話の認識には small。medium 以上は清書向け。
- **hotwords で kotoba が空になる**: kotoba-whisper は hotwords を渡すと何も出さない。渡さない。それ以外のモデルでも、声のある録音なのに空だったときは、用語なしでやり直す。
- **前置きが長いと出力の上限（448 トークン）**: 前置き（プロンプト・hotwords）と出力の合計が 448 トークンまで。トークナイザで実際の長さを数えて、残りを出力の上限にしている。見積もりが大きすぎると長い発話が途中で切れ、小さすぎると「長すぎる」エラーになる。
- **空の入力欄がプレースホルダーを値として返す**: Muse は「メッセージ」、Copilot は見えない文字 U+FFFC。そのまま読み戻しや追記に使うと、本文の前に入ってしまう。宛先プロファイルの `empty_values` で「空」として扱う。
- **UIA で空にしたあとの読み戻し**: 目視では空でも「残っている」と出るアプリがある。クリア後の判定に読み戻しを使わない。Copilot は UIA の書き込みが成功と返っても入力欄に入らない。**読み戻しの一致だけを成功とする。**
- **Opus・無音カットと履歴の時刻**: 無音を縮めると、録音上の時刻と元の時刻がずれる。縮めた場所を `cuts_json` に保存して、再生位置・行の時刻を補正している。履歴の既存の行（`cuts_json` が空）は補正しない。
- **区間の境目の無音**: Whisper の区間は無音を含めて連続して返すことがあるので、区間の時刻だけでは改行の判定ができない。WAV から無音を測っている（`gaps.py`）。履歴から後でテキストだけ整形し直すことはできない。
- **単発の舌打ち**: 区切り器に「発話」と判定され、認識に回ることがある（検出時に合図の音は取り除くが、単発の場合は未対応）。意味のない文字が出る可能性。
- **マイクのミュート**: ヘッドセット本体のミュートボタンで無音になる件は、アプリでは防げない（チップの「音が入っていない」で気づける）。
- **PyAV（av）19 と faster-whisper 1.2.1 の不整合**: mp3 等を直接渡すと `decode_audio` が落ちうる（`pip install "av<17"`）。16kHz mono の WAV・PCM16 WAV・Opus は自前で読むので影響しない。
- **スロット内の例外**: PySide6 はスロット内で例外が投げ切られるとプロセスごと落ちるため、全スロットを `safe()` で包み `error.log` へ記録している。
- QMediaPlayer（Qt の FFmpeg バックエンド）は音声を開くとき stderr にログを出す。無害。まれに `stop()` で固まる（環境依存）ので、`run_all.py` はタイムアウトしたモジュールを 1 回だけ再実行する。
