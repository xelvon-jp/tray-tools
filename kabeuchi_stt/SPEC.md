# コダマ（KODaMA）仕様 — 版 20261123-12 時点

旧名「壁打ち文字起こし」（フォルダ名・設定キーは `kabeuchi_stt` のまま）。しゃべった内容を下書きに溜め、確定したときだけ AI アプリ等の入力欄へ届け、録音は残して、終了時に録音全体を清書して履歴に保存する。完全ローカル。
使い方・設定値・既知の罠は `README.md`、宛先・配達・確定・ヘッドセットの詳細は `SPEC_dialogue_mode.md`、設計は `DESIGN_stageA.md`（AI 対話の分担）・`DESIGN_unified_gui.md`（画面の構成。一部は古い記述を含む）。

## 1. 方針

- GUI は PySide6（tray-tools と同じ基盤）。コア（録音・認識・辞書・履歴・配達の判断）は Qt・COM に依存させない。UI Automation は別プロセスのワーカーが行う。
- **使い方は1つ**。モードの切替（旧「壁打ち」と「AI対話」）はない。録音＝セッションの開始／停止。
- 完全ローカル。音声は外に出さない。モデルの取得（通信）は、利用者が［モデルの取得・管理…］を押したときだけ。
- **自動確定・自動送信はしない**。下書きは、利用者の操作（［確定して届ける］・Ctrl+Enter・ヘッドセット・マウスのボタン・舌打ち2回・ホットキー）なしに宛先へ入れない。
- **クリップボード**: このツールが入れてよいのは、利用者が明示的にコピー（Ctrl+C／右クリック）したときだけ。配達の貼り付けのための一時使用（退避→貼り付け→復元）は例外。自動コピーの設定はない。
- 録音スレッドは絶対に途切れさせない。認識・清書は別スレッド（低優先度）。モデルは git に入れない（保存先は設定可。SSL 検査環境向けの手置きの読み込み順あり）。
- ファイルは UTF-8・LF。公開リポジトリに入るファイルに、個人の実パス・個人データ・秘密情報を書かない。版表示は `version.py`（`YYYYMMDD-NN`）。

## 2. 機能

### A. セッション（録音→認識→下書き）
1. ［録音］でセッション開始。マイクを開きっぱなしにし、WAV に逐次保存する（1秒ごとにヘッダを確定。落ちても開ける）。［停止］で終了。無音が `dialogue.idle_stop_sec`（既定 180 秒、0=しない）続くと自動終了。
2. 無音 `dialogue.utterance_gap_sec`（既定 1.2 秒）で発話を区切り、`dialogue.model`（既定 small）で認識して、下書き欄に白い文字で追記する。直前の発話（句読点を含むときだけ）と専門用語（hotwords）を手がかりに渡し、置換辞書を適用する。句読点入りの見本文を常に末尾に付ける。
3. **認識開始ライン**（`dialogue.voice_min_dbfs`、既定 -50dBFS）: 音量メーターと同じ基準（0.1 秒の平均 RMS）で、これに届く音が一瞬もない塊、最短長（`min_utterance_sec` 0.3 秒）未満の物音は、認識へ回さない。メーター上の線をドラッグで調整する。
4. **幻覚・暴走の除外**: 「ご視聴ありがとうございました」等の定番だけの結果、記号だけ、認識に渡した見本文がそのまま出たもの、同じ語・文の3回以上の繰り返し（1回にまとめる）を除く。無音確率が高く、かつ自信も低い区間だけを捨てる（無音確率だけでは捨てない）。
5. 認識は時刻を出す方式（長い発話の打ち切りを避ける）。温度の切り替えによる再試行はせず、出力の長さに上限を付ける（前置きと出力の合計が 448 トークンまでなので、トークナイザで実長を数えて残りを上限にする）。失敗したら制限なしで1回やり直す。
6. **一時停止（保留）**: 新しい発話の取り込みだけ止める（録音 WAV は続く）。すでに話した分は認識して下書きに入る。

### B. 下書き欄
- 1つの編集可能な欄。前から順に、確定済み（白。利用者が自由に直せる）→ 認識待ちの発話（バー）→ いま喋っている発話（バー）。**仮認識（黄色い暫定の文字）は廃止**。
- バーは、喋った長さに比例して伸び（10 秒で折り返す）、右に「喋っています 0:12」。黙ると「無音 0.5秒（あと0.7秒で認識開始）」（バーは止まる）。区切れると「認識中（small・あと約N秒）」。認識が済むと、その場で白い文字に置き換わる。声のない発話にはバーを出さない。
- 守り: 認識の更新で、利用者の編集・カーソル・選択・スクロールを動かさない。バーには入力できない。確定済みとバーにまたがる削除・結合は受け付けない。Ctrl+Z は使えない（認識結果の差し込みと混ざるため）。直した内容が確定の正本（以後の追記は直した内容の末尾へ）。
- **句点と改行**: 文中の「。？！．」の直後に改行（`newline_after_sentence`）。話を区切った所は、前が句点系なら空行（`break_blank_line`）。間が `paragraph_force_gap_sec`（3.0 秒）以上なら句点を補って空行。手で直した部分には再適用しない。確定時、末尾が句読点でなければ「。」を補う（`punctuate_on_commit`）。
- **前置き**: 宛先の行の［前置き ▾］から選ぶと、下書きの先頭に灰色ブロックとして1回だけ入る（×で外す。自動では付かない。配達が済むと消える）。編集は引き出しの「前置き」タブ。
- **送信中ブロック**: 確定すると、下書き欄の上に「送信中…」（送った文章つき）。成功は緑「✓ 送信しました」を 1.5 秒。送信を確認できないときは赤字で残す。続けてしゃべった内容は下の下書きへ。

### C. 宛先・確定・配達
詳細は `SPEC_dialogue_mode.md`。要点:
- 宛先 = プリセット（窓＋入力欄・送信ボタン。クリックで取って保存）／「なし（記録だけ）」（何も届けず、クリップボードにも入れず、確定済みとして記録に残すだけ）。セッション中は毎回その宛先へ。別の窓へは送らない。
- 届ける流れ: UIA 書き込み → 読み戻し一致 → 不一致なら前面化・貼り付け（クリップボードは一時使用）→ 読み戻し → 前面化不可ならクリック → 不可なら未配達。前面になったと確認できるまでキー送信しない。
- ［送信までする］（`send_after_deliver`、既定 OFF）: 読み戻しで確認できたあと、送信ボタン（UIA。無ければ Enter）→ 入力欄が空に戻ったかで確認。1回だけ試す。回答中なら最大 `busy_wait_sec` 待つ。
- 未配達は消さず保持（再試行・コピー・破棄）。入力成功・送信失敗は「配達済み・未送信」。
- 空の入力欄がプレースホルダーを値として返すアプリ（Muse の「メッセージ」、Copilot の U+FFFC）に対応（宛先プロファイルの `empty_values`・`input_name`）。
- 確定の入口: ［確定して届ける］／Ctrl+Enter／ヘッドセットの多機能ボタン／マウスの戻る・進む／舌打ち2回（実験・既定 OFF）／ホットキー。すべて同じ操作。

### D. 録音全体の清書と履歴
- **セッション終了時**に、録音全体を設定のモデル（`final_model`）で清書して履歴に保存する（`finalize_on_end`、既定 ON）。OFF のときは、再認識せず、セッション中の発話ごとの結果（時刻つき）から履歴の1件を作る（待ち 0）。
- 清書は**セッション中は始めない**（ゲート。録音が終わってから）。実行中の清書は低い優先度で動かす（**効きは未確認**）。進み具合は、停止中の状態バッジ「清書中 35%（あと約3分）」。清書キューは別スレッド・1件ずつ。
- 結果が空なら専門用語なしでやり直す。kotoba-whisper は hotwords を渡すと何も出ないので渡さない（`models_catalog.supports_hotwords`）。
- 履歴（SQLite）: 録音ごとに 日時・長さ・先頭の一文・モデル。全文検索（空白区切りで AND、修正後の文も対象）。行クリックでその位置から再生（出力先を選べる。「システム既定」は再生のたびに取り直して追従）。本文の直接編集と保存（元の清書は DB に残る）。直した語を置換辞書へ登録。履歴の WAV から清書をやり直す。削除（ごみ箱へ）。
- ［WAV を選んで清書］（⚙メニュー）・`main.py --wav` も使える（圧縮・後始末はしない）。
- 清書の出力（txt / md の全文）は、すき間の長さで改行する（`paragraph.py`。2 秒以上＋句点系で改行、3 秒以上で必ず改行・句点を補う、2 秒未満はつなげる）。実際の無音は WAV から測る（`gaps.py`。Whisper は区間に無音を含めて返すため）。履歴の元の区間（時刻つき）は無加工。

### E. 録音の圧縮
- 清書のあとに Opus（ogg・モノラル・既定 24kbps）へ変換（PyAV の libopus。ffmpeg 不要）。`audio_compress` = `off`／`keep`／`trash`／`delete`（**既定**。WAV を完全に削除）。変換できたときだけ WAV を後始末し、失敗・長さのずれ・ごみ箱への失敗では WAV を残す（例外は出さず `error.log` へ）。
- **無音カット**（`audio_silence_cut`、既定 ON）: 4 秒以上の明らかな無音を 0.5 秒に縮める（発話の前後は守る）。縮めた場所は履歴の `cuts_json` に保存し、再生位置・行の時刻を補正する。
- 履歴は圧縮後、録音の場所（`wav_path`）を Opus に差し替える。再生は PyAV で一時 WAV へ展開。対象はセッション終了直後の清書ジョブだけ。

### F. マイクの診断と警告
- **チップ**（固定サイズ）: 入力OK／音が小さい／音割れ／ノイズ大（要相談）／音が入っていない／マイク使用中／未録音（話しています）／一時停止中（話しています）／マイク確認中。判定は `mic_check`（純関数。ピーク・クリップ率・ノイズの床）と `meter_state`・`session.monitor_error` の結果をまとめるだけ。しきい値は設定（`mic_*`）。
- **待機中のマイク確認**（`idle_monitor`、既定 ON）: 窓が見えている間だけ入力を開き、メーターと診断を動かす（保存も認識もしない）。開けなければ「マイク使用中」。録音開始時は同じストリームを引き継ぐ。
- **停止中・一時停止中の発話警告**: 録音（取り込み）されていないのに喋り続けると、下書き欄が赤（停止中）／アンバー（一時停止中）で点滅し、喋り終えるまで続く。メーターも赤になる。
- **状態バッジ**: 録音中／無音待機中／認識中（N件）／送信中／✓ 完了／保留中／停止中／清書中 N%（あと約…）／清書待ち。使用中のモデルはバッジのツールチップ。

### G. 認識モデル
tiny／base／small／medium／large-v3-turbo／large-v3／kotoba-whisper。設定のコンボに、取得済み／未取得と用途別【非推奨：理由】を出す（AI 対話の認識は small 推奨。medium 以上は 1 発話 9 秒以上）。取得は利用者が押したときだけ。モデルは常駐してメモリに保持し、最後の使用から `model_idle_release_sec`（既定 600 秒）で解放する。

### H. 専門用語・置換辞書・前置き
- 専門用語（hotwords）: 引き出しの「用語・置換」でチップとして追加・削除。`settings.json` に保存し、認識・清書の全窓に渡す。
- 自動置換辞書（誤認識 → 正解）: 1パスのみ・同じ位置は長い誤認識を優先・重複は後勝ち。辞書は `%LOCALAPPDATA%\kabeuchi_stt\replacements.json`（公開リポジトリに入れない）。
- 前置き: 名前＋本文を複数保存（`presets.json`）。メイン画面の［前置き ▾］からだけ使う（クリップボードへ入れる機能はない）。

### I. 常駐・ホットキー
- トレイ常駐（左クリックで窓の表示/非表示。メニュー: 画面を表示/隠す・録音を開始・保留・辞書・専門用語を開く・履歴・検索を開く・設定・終了）。単一起動（2つ目は既存の窓を出す）。
- ホットキー（`RegisterHotKey`。既定は未割り当て。低レベルキーフックは EDR に検知されうるので使わない）: `hotkey_record`・`hotkey_pause`（保留/再開）・`hotkey_show`・`hotkey_dialogue_commit`（確定）。常用アプリのショートカットと衝突しない組み合わせにすること。
- **マウスの戻る/進むボタンで確定**（`dialogue.mouse_button`）は例外的に低レベルフック（`WH_MOUSE_LL`）を使う。セッション中だけ入れ、終了・例外・アプリ終了で必ず外す。会社 PC では警告されうる（未確認）。

## 3. 画面

1列の小さな窓（既定は引き出しを閉じて幅約 400px）。上から: 録音の行（［録音/停止］・［保留］・経過時間・状態バッジ・マイクチップ・最前面・⚙・引き出しの開閉）／音量メーター（認識開始ラインつき）／宛先の行（宛先・［送信までする］・［前置き ▾］）／下書き欄／未配達の行（あるときだけ）／［確定して届ける］／通知の1行。
- ⚙ メニュー: 設定／WAV を選んで清書／出力フォルダを開く／確定履歴を開く／接続の状態（診断。選択・コピーできる窓）。
- 引き出し（右 約 460px。開くと窓が広がり下書きも広がる）: 履歴／用語・置換／前置き／清書の状況。
- 設定は ⚙ → 設定 の3タブ（共通／録音と清書／AI対話）。引き出しに設定タブはない。
- 窓の位置・サイズは、引き出しを閉じている／開いているで別に記憶（`win_geometry_unified` / `win_geometry_unified_drawer`）。表示サイズは小（既定）／標準／大。ダーク基調、DPI 100〜200%。
- 従来の左右2ペイン画面、コンパクト表示、タブ式の画面、［清書してコピー］、Copilot プロンプトのタブ、マイクテスト（3秒）、逐次認識の切替は廃止した。

## 5. テスト

`tests\run_all.py --fast`（画面のテストと実モデルの e2e を除く。普段はこれ）、`--gui` で画面のテストも含める。マイクは開かない・窓は画面に出さない（`WA_DontShowOnScreen`）・音は鳴らさない・クリップボードは偽物に差し替え・本人のデータは触らない。合成波形で、区切り・マイク判定・舌打ち検出などを単体テストする。実マイク・実ワーカー・実ヘッドセット・実マウスフックの動作は、実機でしか確かめられない。
