# AI 対話（しゃべった内容を AI の入力欄へ届ける）仕様 — 版 20261123-12 時点

コダマの中心の使い方。かつては「AI対話モード」という別モードだったが、モードの切替はなくなり、これが使い方そのもの（録音ボタン＝セッション開始／停止）。画面と全体の仕様は `SPEC.md`、使い方は `README.md`、実装の分担は `DESIGN_stageA.md`。
最初の要望（2026-11-22）: 喋った内容を Claude・Muse・Copilot 等のアプリの入力欄へ直接入れたい。認識は、録音中の仮の文字と録音後の清書の中間の品質で。送り方は色々試して使いやすいものを探したい。

## 1. 守ること（不変条件）

1. **利用者の操作なしに、下書きを宛先へ入力・送信しない。** 確定は［確定して届ける］・Ctrl+Enter・ヘッドセットの多機能ボタン・マウスの戻る/進むボタン・舌打ち2回（実験）・ホットキーのときだけ。無音による自動確定・自動送信は**採用しない**（考え中の沈黙で早まる・周囲の声が AI へ行く誤爆を避けるため）。無音が続いたときの**セッションの自動終了**（`idle_stop_sec`）だけが自動。
2. **確定したテキストは、どの経路でも捨てない。** 確定の瞬間にメッセージとして履歴に登録し、配達の結果（成功・失敗・中断・保存と分離）にかかわらず残す。配達できなかったものは「未配達」として保持する。
3. **前面になったと確認できるまで、キー送信（貼り付け・Enter）をしない。** 別の窓へ誤入力しない。
4. 宛先は固定。セッション中は毎回その宛先へ送り、別のアプリをアクティブにしても、そちらへは送らない。窓が見つからない・複数あるときは止めて知らせる。
5. 本体は COM を使わない（UIA は別プロセスのワーカー）。
6. クリップボードは、利用者が明示的にコピーしたときだけ入れる。配達の貼り付けのための一時使用（退避→貼り付け→復元）は例外。

## 2. 認識と下書き

- 録りっぱなし（セッション制）。マイクをセッション終了まで開き、WAV も残す。
- 無音（`utterance_gap_sec`、既定 1.2 秒）で発話を区切り、`dialogue.model`（既定 small）で認識して下書きへ。直前の発話（句読点を含むとき）と専門用語を手がかりに渡し、置換辞書を適用する。medium 以上は 1 発話ごとに 9 秒以上かかるので対話には向かない（設定のコンボに【非推奨】の印）。
- 認識結果は、確定するまで下書きに溜め、宛先へは書かない。確定時に、下書き全体を1回で届ける。**仮認識（逐次認識の暫定の文字・黄色）は廃止**。確定のとき清書待ち（認識中）の発話があれば、揃うまで待つ（確定ボタンに「認識待ち N件…」）。
- 下書き欄は、手で直せる1つの欄（確定済みの白＋認識中のバー）。詳細は `SPEC.md` の B。句点・改行・空行の規則、確定時の「。」補いも同じ。
- 保留（一時停止）: 新しい発話の取り込みだけ止める。録音 WAV は続く。すでに話した分は認識して入る。
- セッション終了時に、録音全体を清書して履歴へ（`SPEC.md` の D）。未配達や確定前の下書きが残っていれば、［コピー］［破棄］［あとで（残す）］を選ばせる。

## 3. 宛先

- 宛先 = 窓（プロセス名・クラス・タイトル）＋その中の入力欄／送信ボタン（UIA の要素）。**PHAL のプロファイルと同じ形**（`process_name` `window_class` `window_title_contains`、入力欄・送信ボタンの候補、`click_rel` `window_size`）で保存する。プリセットは `%LOCALAPPDATA%\kabeuchi_stt\dialogue_targets\*.json`。
- **宛先の取り方**: コンボ末尾の「入力欄を選んで追加…」→ 入力欄をクリック（30 秒以内、Esc でやめる）→ 名前を付けて保存。クリックの検出は、グローバルなマウスフックを使わず、カーソル位置とボタン状態の監視（`GetAsyncKeyState`）で行う。クリック点の要素が粗いとき（Muse は入力欄を包む Button、Copilot は Document 全体）は、窓を起こしてから、矩形内の Edit／ComboBox／Document（値パターンあり）のうち最小のものへ降りる。手がかりは、自動化 ID → 名前＋種類 → クラス名 → 保存したクリック位置の順に、毎回探し直す。
- セッション開始時にプリセットを実際の窓へ結びつけ（ハンドルを握る）、以後はそのハンドルの中の要素を毎回探し直して書き込む。送信直前に、窓のタイトルが合うかも確かめる。
- **「なし（記録だけ）」**: 何も届けず、クリップボードにも入れず、確定済みとして記録に残すだけ。
- 宛先プロファイルの `empty_values`・`input_name`: 空の入力欄が、プレースホルダー（Muse の「メッセージ」）や見えない文字（Copilot の U+FFFC）を値として返すとき、それを「空」として扱う（書きかけの判定・追記・読み戻しの比較に効く）。

## 4. 配達（確定→入力欄）

順序（`dialogue_deliver.py`。ワーカーの `deliver` op）:

1. 宛先の窓を探す（握ったハンドルを優先。見つからない・複数なら止める）。入力欄を探し（初回のあとは使い回す）、書きかけは `existing_text`（追記／上書き／中止。既定は追記）に従う。
2. **UIA で値を設定 → 読み戻し**。一致すれば delivered（stage=`uia`）。
3. 不一致なら**前面化**（UIA SetFocus → 前面確認 → 最小化なら復元 → だめなら SetForegroundWindow）。**前面確認が取れるまでキー送信はしない**。フォーカスを確認 → **貼り付け（Ctrl+V）** → 読み戻し（stage=`paste`。クリップボードは退避して元に戻す）。
4. 前面化できないとき、クリック点の下が宛先であることを確認したうえで、本物のクリック → 前面確認 → 貼り付け → 読み戻し。
5. どれも不可なら中止して未配達（理由つき）。読み戻しが一致しなければ**送信もしない**。

- **［送信までする］**（`send_after_deliver`、既定 OFF）: 配達の読み戻しが一致したときだけ、①送信ボタン（プロファイルの `send_button`）を UIA で Invoke（前面化不要）→ ②ボタンが無い／無効なら、前面確認とフォーカス確認ののち Enter。**1回しか試さない**（自動再試行しない）。送れたかは、入力欄が空（または元の書きかけだけ）に戻ったかの読み戻しで判定し、判定できなければ「未確認」。入力は成功したが送信できなかったときは「配達済み・未送信」（入力欄に残る。再試行で二重入力しない）。
- 相手が回答中（`busy_button` が見える）の間は送信を待つ（`wait_while_busy` 既定 ON、`busy_wait_sec` 既定 120 秒。超えたら送らず「回答中のため未送信」）。
- **前面化ロック対策**: ヘッドセット等の入力を受けるのは本体。配達を頼む直前に本体が `AllowSetForegroundWindow` を呼んで、ワーカーへ前面化の権利を渡す。窓のボタンや無入力のタイマーからの前面化は別条件で、失敗しうる（失敗は未配達へ倒す）。
- 「入力中の他作業を奪わない」（`keep_idle_foreground`、既定 OFF）・「配達のあと元の窓へ戻す」（`return_focus`、既定 OFF）は設定にある。

### 実測の結果（2026-11-22、段階0。利用者の立ち会い。ほぼ各1回の試行・目安）

| 項目 | Claude | Muse | Copilot |
|---|---|---|---|
| 背面の窓へ UIA の値設定だけで書き込み | 成功 | 成功 | 成功と返るが入力欄に入らない（読み戻し不一致） |
| UIA SetFocus での前面化 | 成功 | 成功 | 成功 |
| SetForegroundWindow 単独 | 成功と失敗が混在 | — | 失敗 |

→ UIA で書けたと判断せず、**毎回読み戻して一致を確認**し、不一致なら貼り付けへ倒す。前面化の既定は UIA SetFocus。ヘッドセットのボタン（HID／ホットキー）で受けた直後は、前面化ロックが効かなかった（直近の入力として数えられる）。UIA で空にしたあとの読み戻しは、目視では空でも「残っている」と出ることがある（Muse・Copilot）ので、クリア後の判定に読み戻しを使わない。送信ボタン名・Enter の挙動・回答中の検出が各アプリで動くかは、実機での確認が済んでいない部分がある（下記）。

## 5. 未配達

- 対象: 前面化できなかった／窓が見つからない／入力欄へ書き込めなかった／読み戻しが一致しなかった。
- 保持と表示: 画面に件数と理由、内容を出す。録音は続き、新しい発話は次の下書きへ。
- 再試行: 確定の操作（次の1回は「再試行」になり、送信にはならない）／［再試行］／ホットキー。宛先が見つからないときは、宛先を選び直す。
- 手で使う: ［コピー］で、未配達のテキストを手で貼れる。自動でクリップボードへ入れる設定（`copy_undelivered_to_clipboard`）もあるが、既定 OFF。
- 複数溜まったら、古いものから順に配達（`merge_undelivered` でまとめて1通にもできる）。期限で捨てない（セッション終了まで保持。終了時に選ばせる）。
- 確定履歴（確定したメッセージ・時刻・送信済み／未送信／未確認・手修正あり）は、⚙メニューの「確定履歴を開く…」。

どれも同じ操作（下書きがあれば確定して届ける。未配達があれば再試行。下書きが空なら何も届けず「下書きが空です」）。押した瞬間に、通知の1行へ「…のボタンを受け取りました → 確定します／再試行します／下書きが空です」を必ず出す。間引き（同じ押下を拾った別経路の重複）は 0.5 秒以内を1回にする。

### ヘッドセット
- 多機能ボタンの**短押し**だけが使える。長押し・ミュートは PC に届かない。素早い2〜3連続も、ヘッドセットが内部処理して届かない（ダブル／トリプルクリックは使えない）。トグル（1回押すごとの合図）としてのみ使い、押している間だけ録音するプッシュ・トゥ・トークはこのボタンでは不可。音量ボタンは使わない。
- 検出経路は2つを併用（`headset_mode`: `auto`／`hid`／`hotkey`）。①**HID 直接読み**（`dialogue_hid.py`。ヘッドセットの USB ドングル `headset_vid_pid` の入力インターフェースを共有・読み取り専用で開く。フックなし・書き込みなし）②`RegisterHotKey(VK_MEDIA_PLAY_PAUSE)` の独占（動画・音楽が同時に反応するのを抑える役目＋予備。セッション中だけ登録し、終了・異常終了で必ず解除）。どちらか一方でも成功すれば受付中。警告「ヘッドセット受付できません」は両方失敗のときだけ。
- 経緯: `RegisterHotKey` は登録に成功しても押下を1回も受け取れない状況が実機で起きたので、HID 直接読みを足した。さらに実測で、**マイクを使っている間（セッション中）は、多機能ボタンの信号が、再生/一時停止ではなく電話用インターフェース（HID Page 0x0B）に出る**ことが分かり、HID 直接読みは両方を読む。HID だけだと同じ押下が Windows にも届き、再生中のメディアが反応しうる（独占が効いていれば抑えられる）。
- 診断: ⚙「接続の状態（診断）…」、`dialogue.log`（独占の登録結果・エラーコード、押下の受信と経路 `via=hid|hotkey`・間引き、確定の呼び出しと結果。発話の内容は書かない）、単独の診断ツール `headset_probe.bat`・`hid_watch_all.bat`。
- **未確認**: 電話用インターフェースの読み取りを入れた版で、本体のセッション中に確定まで届くか。

### マウスのサイドボタン
`WH_MOUSE_LL`（低レベルフック。`dialogue_mouse.py`）で拾う。追加ソフトが入れられない会社 PC を想定。**フックを入れるのはセッション中だけ**（終了・例外・アプリ終了で必ず外す）。対象ボタンの down で確定し、down と up の両方を握りつぶす（他のアプリへ戻る/進むを渡さない）。対象外のボタン・動き・ホイール・他ソフトが注入した擬似入力は素通し。コールバックは軽く（押下をキューへ入れるだけ）。ヘッドセットとは独立。失敗しても本体・ヘッドセットは止まらず、`dialogue.log` に `via=mouse` で理由が残る。効くのは次のセッションから。**セキュリティソフトの警告対象になりうる。会社 PC での動作は未確認。**

### 舌打ち2回（実験）
マイクの音だけで判定（`dialogue_click.py`。純 NumPy。セッション中だけ）。条件（実測で決定）: 5ms ごとのピークが -30dBFS を超える塊が、継続 25〜110ms・最大ピーク -14dBFS 以上・高域（2kHz 以上）の比率 0.5 以上なら「舌打ち1回」。開始から開始まで 0.2〜0.7 秒で2つ並び、さらに1つ目の前 0.3 秒と2つ目の後 0.3 秒がどちらも -48dBFS より静かなときだけ「2回続け」（発話の語尾の破裂音などの誤検出を除く）。通知後 2 秒は再検出しない。検出した瞬間、合図の音を区切り器の途中の発話から取り除き、文字起こしへ混ぜない。実録音では、2回続けが 10 組中 10 組検出、1回ずつ・普通の発話・過去の約 4.5 時間の録音では検出 0。静かな場所向け。**単発の舌打ちが発話と判定され、認識に回ることがある**（未対応）。

## 8. 未決・未確認

- 区切りの無音（1.2 秒）の最適値。入力欄に書きかけがあるときの既定（追記でよいか）。
- 送信ボタン名・Enter の挙動・回答中の検出が、Claude／Muse／Copilot で期待どおり動くか（回答中に待つ動きを含め、実機は未確認）。
- ヘッドセットの電話用インターフェース経由の確定、マウスの低レベルフックの会社 PC での動作（上記）。
- 空行入りの文章を AI アプリの入力欄へ届けたときの見た目。
- 発話ごとの認識の CPU 負荷（職場 PC で実測していない）。
- 単発の舌打ちが発話になる件。
